# Task 16 binding global constraints

Source: `Docs/superpowers/specs/2026-07-15-standalone-html-presentations-design.md`, especially the extension consumer matrix, no-execution contract, frontend/security tests, plus `PRODUCT.md`, `DESIGN.md`, and the approved Task16 plan.

1. The extension remains source-free. It may receive only normalized bounded presentation metadata. It never requests, retains, logs, caches, stores, messages, displays, parses, downloads, exports, renders, executes, or forwards `html_document`, a version payload, a draft body, or any source-derived value.

2. V1 gains no execution or preview surface. No iframe, `srcdoc`, DOM/HTML parser, `innerHTML`, `dangerouslySetInnerHTML`, popup containing source, source-derived URL/Blob/data URL, generated worker/module/function/import, renderer, thumbnail, export, or hidden runtime flag may consume standalone source. CSP is unchanged.

3. Extension routes are transport-aware. `/presentation-studio` remains the metadata index and `/presentation-studio/start` remains structured quick-start. `/presentation-studio/new` is WebUI-only and is never registered to the WebUI form/editor in the extension. Literal `new` is explicitly reserved ahead of the parameter route and redirects source-free to `/start`; `/start` retains precedence.

4. The extension parameter route performs exact-ID source-free metadata resolution before any structured detail work. Only a validated `structured_slides` result may mount the existing structured detail wrapper. `standalone_html`, unknown future kinds, blank/mismatched IDs, malformed metadata, and failures never mount the generic detail wrapper or any HTML workspace.

5. Structured projects preserve existing extension behavior after the metadata decision. Do not replace or fork their store/autosave/editor logic. Route changes between structured, HTML, and unknown kinds must retire prior results so one kind can never mount the other surface.

6. Metadata and click-time work are identity fenced across route changes, unmount, config updates, auth-principal changes, and `tldw:slides-scope-mismatch`. Boundary handlers synchronously clear trusted-ready authority before React rerenders, and handlers verify the exact route, metadata epoch, and ready record both at entry and immediately before opening. Stale results remain unpublished. A create or metadata response that resolves after retirement may not navigate or reveal prior metadata.

7. HTML and unknown states show only a closed, bounded projection of normalized title, kind, optional description, counts, and provenance plus a single `Open in WebUI` action. Validate before state/DOM: exact nonblank route ID <=256 Unicode scalars; nonblank title <=512; kind, unknown-kind, and each nonblank provenance field <=256; optional description <=2,048; finite nonnegative integer counts; and no C0/C1, bidi-format control, NUL, or lone surrogate in any accepted string. Fail closed rather than truncate, and promptly release the raw response. Unknown kinds are explicitly read-only. UI uses React text nodes, one clear `h1`, semantic status/error regions, keyboard and visible-focus behavior, shared tokens/primitives, and concise copy without em dashes, gradients, glass, card-grid layouts, or decorative motion.

8. Handoff destinations are application-owned. At click time read the runtime config, pass only source-free `serverUrl`, `webUiUrl`, and `webuiUrl` to the existing `resolveSidepanelChatWebUiBaseUrl`, and append the relative trusted route `presentation-studio/${encodeURIComponent(projectId)}`. Require at least one configured candidate that independently parses as HTTP(S), so all-missing/all-invalid configuration fails closed rather than accepting the helper's default. Preserve explicit alias/subpath priority and the helper's documented API `:8000` to WebUI `:8080` inference. Strip credentials, query, and fragment through the canonical helper. Never construct directly from raw `new URL(serverUrl).origin`, and never use metadata, title, provenance, project payload, or source/model output to influence the target.

9. Open the handoff only from an explicit user action using `_blank` and `noopener,noreferrer`. Missing or wholly malformed canonical WebUI configuration is a bounded fail-closed UI error; a valid configured server URL may use the canonical helper's WebUI-origin inference. Navigation is revalidated against the current route and authority epoch immediately before `window.open`.

10. Use the authoritative Task13 `getPresentationMetadata` normalization and existing client authentication. Do not hand-roll fetch/auth, broaden normalization, add request-core/background-proxy behavior, introduce a source-bearing cache, or infer kind from generic detail. Static client types may omit runtime WebUI URL aliases; narrow unknown runtime config only to those two optional string fields.

11. Route metadata explicitly declares the availability of `/presentation-studio`, `/new`, `/start`, and `/:projectId`. Preserve exact metadata lookup semantics and existing unrelated route governance. Extension build registration and metadata availability must agree.

12. The extension index remains source-free and must fence stale list metadata across configuration/principal/scope changes. The canonical RED proved this requirement was missing, and the controller approved `PresentationStudioIndex.tsx` as a narrow additional production path. Its fix is limited to local request-identity invalidation/reload; no new cache, storage, client, or source-bearing behavior is allowed.

13. Tests are RED first. The complete unit/E2E behavioral patch lands before production edits, then the exact single-file route command and extension compile capture the canonical RED. Use real route definitions/metadata/panel behavior, mock only transport/runtime, and retain the real built-extension Playwright quick-start while adding source-route network tripwires.

14. E2E instrumentation may observe/reject source-bearing extension storage and runtime messages, but must not ban unrelated extension infrastructure. Unit and E2E tests must prove no source-bearing detail/version/save/download/export/render calls and fixed-origin handoff attributes.

15. Scope is the five original Task16 plan files, the separately approved `apps/packages/ui/src/components/Option/PresentationStudio/PresentationStudioIndex.tsx`, the approved compatibility test `apps/packages/ui/src/routes/__tests__/option-presentation-studio-start.test.tsx`, plus the Task16 brief, global constraints, and report. Request approval before any other tracked path. Preserve the protected `apps/packages/ui/node_modules/antd` artifact and two Watchlist templates; make no Backlog calls or edits; do not install; stage explicitly; commit working code only; and do not push.
