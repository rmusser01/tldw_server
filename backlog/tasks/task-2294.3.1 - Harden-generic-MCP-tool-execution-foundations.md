## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Harden the extracted MCP execution foundation required before model-running tools are introduced. Add a host-neutral expected tool-failure outcome, correct closed/half-open breaker accounting, fail-closed policy-bound rate admission, HMAC-bound immutable prepared execution policy and live-binding revalidation, and an extracted idempotency state machine with bounded contention, sticky ownership, strict replay encoding, and cancellation-safe success finalization. Keep protocol-level authorization errors unchanged and add no Skills-specific logic to protocol.py.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A generic bounded known-failure type/outcome is defined outside Skills and provider packages with server-defined breaker action.
- [ ] #2 Known failures produce MCP tools/call isError results with sanitized reason_code and constant public message content, preserve safe outer bookkeeping, and do not become JSON-RPC request errors.
- [ ] #3 Domain/policy failures record failure metrics, audit, hooks, and tool-use reporting without incrementing or resetting the module circuit breaker; known shared dependency failures count toward it.
- [ ] #4 Known failures are not cached by local or Redis idempotency result paths; unexpected exceptions preserve existing generic handling and breaker behavior.
- [ ] #5 Injected and fallback module breakers have identical neutral/counting behavior: ignored closed-state outcomes preserve prior counters, ignored half-open outcomes release the probe lease without closing/reopening or advancing thresholds, and counted half-open failures reopen with normal backoff.
- [ ] #6 IdempotencyManager and its Redis/local state machine live in the extracted tool-execution package behind a narrow typed runtime interface; protocol.py retains only a compatibility re-export.
- [ ] #7 Server-authored rate_limit_fail_closed metadata maps admission-service failure to sanitized rate_limit_unavailable before module dispatch without breaker/idempotency mutation; no tool-name-specific branch is added.
- [ ] #8 An optional bounded local/Redis idempotency contention wait returns stable idempotency_in_progress without dispatch, bounds only pre-owner waiting, and does not time out owner execution after lock acquisition.
- [ ] #9 The idempotency owner callback runs at most once per request: ambiguous Redis lock acquisition fails closed as idempotency_unavailable, while cache/serialization/release failure after owner execution never falls back to re-execution.
- [ ] #10 Successful payloads use one strict bounded canonical JSON representation with no default=str or NaN; local and Redis replay equivalent copies and caller mutation cannot alter cached state.
- [ ] #11 A valid success whose persistence/serialization/size check fails is returned unchanged, retained in bounded local cache when possible, and emits degraded-persistence observability without a durable replay claim.
- [ ] #12 For idempotent calls, response construction/cache persistence occurs before cancellation-sensitive post-execution observers; observer failures preserve the committed outcome and cannot redispatch.
- [ ] #13 Focused extraction-contract, runtime, breaker closed/half-open/injected/fallback, protocol-envelope, rate-limit admission, reporting, post-hook, Redis/local idempotency fault-injection, canonical-serialization, mutation-isolation, lint, compile, and Bandit checks pass.
- [ ] #14 Touched module/breaker/runtime logs use only safe reason, exception-family, module, and bounded structural fields; they never interpolate exception message or repr.
- [ ] #15 Prepared calls carry an HMAC-bound versioned immutable execution policy, normalized idempotency-key/cache-key relationship, complete identity-context fingerprint, and detached bounded canonical tool-definition and scope-reporting snapshots; execution performs a second complete integrity and live registry/module/definition check after all waits, uses private observer decodes, and rejects stale state or tampering before dispatch.
- [ ] #16 After a valid owner callback result, strict serialization and a fresh bounded local replay copy commit before remote awaits; Redis persistence/release runs in a bounded cancellation-shielded manager-owned task, and cancellation, timeout, remote failure, or late completion cannot re-enter the callback, replace the result, publish different bytes, or leave orphan work.
- [ ] #17 Idempotency owner/cache/argument-binding keys include a fixed-format digest of explicit authenticated active team/organization scope, never raw scope IDs or generic metadata; personal/no-scope keys preserve legacy shape, and the same user/key/arguments cannot replay across active scopes.
<!-- AC:END -->
