## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement P1 Chatbooks UX clarity findings from the remediation PRD: rename visible Playground copy to Backup & Import, make Settings an entry point to full Backup & Import or clearly secondary conversation shortcut, and let OpenWebUI hydration reuse a visible last/selected import job scope with persisted source-to-destination conversation mappings.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Visible Chatbooks backup/import heading and copy no longer says Chatbooks Playground.
- [x] #2 Settings points users to the full Backup & Import page by default.
- [x] #3 Any remaining Settings conversation export shortcut is secondary and clearly labeled conversation-only.
- [x] #4 OpenWebUI hydration can reuse a last or selected import job scope.
- [x] #5 OpenWebUI import results persist source conversation ID to imported tldw conversation ID mappings.
- [x] #6 Normal hydration uses the persisted mapping and does not require users to know imported tldw conversation IDs.
- [x] #7 Reused hydration scope is visible before preview or job creation, including source format, source user, conversation count, and attachment-reference summary.
- [x] #8 Manual conversation ID paste is no longer required for the normal OpenWebUI hydration path.
- [x] #9 Backup all can start without invented metadata while generated values remain editable
- [x] #10 Restore preview summarizes full account impact and Include all never reports Selected: 0
- [x] #11 Dark-theme upload, progress, and empty-state text meets WCAG AA and all controls have accessible names
- [x] #12 Jobs is full-width, human-readable, recoverable, and confirms destructive cleanup
- [x] #13 Completed jobs report truthful progress, counts, verification, and timezone-aware timestamps while incomplete terminal jobs never appear complete
