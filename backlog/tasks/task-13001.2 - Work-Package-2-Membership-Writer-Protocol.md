## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement Work Package 2 from the approved UserProfiles Stage 2 plan: define immutable membership-write context and deterministic lock planning, route every direct organization/team membership API through one transaction-aware writer, and migrate ownership transfer, registration/provisioning, default-team, and scope-deletion paths without changing public return or exception contracts. This package remains independently reviewable and does not introduce the typed Stage 2 command pipeline.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Membership write context, mutations, anchor ownership, results, and lock sets are immutable, validated, and deterministic; actor and trusted-system authority are mutually exclusive and closed.
- [x] #2 Lock planning derives complete unique user, organization, team, membership-row, and owner sets in the approved total order while preserving mutation execution order.
- [x] #3 Direct organization/team add, remove, and role APIs use one supplied transaction connection, revalidate authorization and volatile invariants after locking, preserve legacy contracts, and advance each affected profile anchor exactly once in writer-owned mode.
- [x] #4 Ownership transfer, registration/invite/bootstrap provisioning, default-team helpers, and organization/team deletion all delegate to the shared writer with no runtime membership-DML exemptions.
- [x] #5 Scope deletion detects any preflight lock-set change, including new memberships or empty child teams, and restarts from a fresh bounded transaction without taking lower-order locks in place.
- [x] #6 Focused SQLite tests pass locally; PostgreSQL locking/concurrency checks pass or are recorded as CI-required; structural inventory, Ruff/compile, diff, Bandit, and independent review gates report no unresolved findings.
