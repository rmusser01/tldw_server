## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H13b, severity High (data loss), roadmap phase 0. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

apps/packages/ui/src/hooks/document-workspace/useAnnotationSync.ts:31-71 sends pending annotations on beforeunload via navigator.sendBeacon or fetch keepalive with only a Content-Type header. Normal requests add X-API-KEY or Authorization (services/tldw/request-core.ts:603-639) and cookie-session mode needs X-CSRF-Token (csrf_protection.py:168-203), so the server rejects the unload request in every auth mode. Because the helper returns true once the request is queued, the beforeunload handler (:321-334) skips its forceSync fallback, and pending annotations are lost on page close.

Review and dry run (2026-10-25): Review findings: the sync endpoint (endpoints/media/document_annotations.py) generates a new id per annotation and does not dedupe, so replay without idempotency duplicates annotations; the Fetch spec caps in-flight keepalive bodies at 64 KiB, so the existing over-60KB keepalive branch cannot work in browsers (jsdom would not show it); custom auth headers trigger a CORS preflight for cross-origin server URLs, so local persistence is the real delivery guarantee.
