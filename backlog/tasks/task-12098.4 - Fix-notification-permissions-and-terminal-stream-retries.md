## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Resolve notification authorization failures and retry loops observed during Chatbooks UAT across WebUI and extension runtimes. Seed effective permissions in SQLite and PostgreSQL with correct fresh-install ordering, preserve structured 401/403 semantics, scope unread state by principal/server, and provide accessible auth-required, degraded, and unavailable recovery states.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The next available SQLite migration and PostgreSQL fresh-seed plus post-role backfill seed notifications.read/control idempotently after rebasing.
- [ ] #2 Built-in interactive roles receive effective personal notification access while custom roles and explicit per-user denies remain unchanged.
- [ ] #3 Production registration and the browser UAT fixture create users with verified effective default-role membership.
- [ ] #4 Extension and direct-WebUI transports preserve structured HTTP status and distinguish 401 auth-required from 403 unavailable.
- [ ] #5 Header and inbox states are accessible for active counts, connecting, degraded, auth-required, and unavailable, including keyboard popover behavior and explicit Try again.
- [ ] #6 Focused backend, frontend, and browser tests cover standard users, restricted roles, reauthentication, role grants, badge suppression, terminal failures, and transient recovery.
- [ ] #7 Idempotent bootstrap, read, poll, and SSE operations stop on terminal errors and retry transient errors with bounded Retry-After-aware backoff; mutations never replay automatically and require explicit user retry unless an idempotency-key contract exists.
- [ ] #8 Unread count and lifecycle state are scoped by server and principal and reset synchronously on login, logout, token refresh, account switch, and server switch; a later grant is discovered only by successful explicit permission refresh or Try again, never passive polling.
<!-- AC:END -->
