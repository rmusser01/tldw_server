## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Resolve the notification 403s and repeated SSE retries observed during Chatbooks host UAT. Add notification permissions to the AuthNZ catalogs and standard-user grants for both SQLite and PostgreSQL, ensure the UAT-created standard user receives the intended role, and make the notification client stop reconnecting on terminal authorization failures while presenting a compact unavailable state for intentionally restricted roles.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 SQLite and PostgreSQL migrations seed notifications.read and notifications.control without duplicating existing rows.
- [ ] #2 The default standard-user role receives the notification permissions required by the header notification experience.
- [ ] #3 The browser UAT fixture creates a user whose effective roles and notification permissions match the intended standard-user product contract.
- [ ] #4 Notification list, unread count, mutation, and SSE requests succeed for a standard user in WebUI and extension runtimes.
- [ ] #5 Terminal 401/403 stream failures do not trigger an automatic reconnect loop.
- [ ] #6 Intentionally restricted roles receive a compact, accessible unavailable state without repeated requests or misleading unread indicators.
- [ ] #7 Focused backend, frontend, and browser tests cover permission grants, terminal errors, and reconnectable transient failures.
<!-- AC:END -->
