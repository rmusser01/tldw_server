## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cold-start real-backend UAT captured GET /api/v1/rag/health, /api/v1/setup/readiness/status, and /api/v1/setup/readiness/profiles returning 401 before the seeded single-user API key becomes available. The page later connects and the workflow passes, but the premature probes create avoidable warning/error UI during startup.
<!-- SECTION:DESCRIPTION:END -->

- [x] #3 A cold-start retained live workflow produces no startup 401 responses.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Trace RAG/readiness query enable conditions and runtime-auth hydration; add failing cold-start tests; centralize or apply an auth-ready gate without masking real failures; rerun focused and live diagnostics.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Root cause was isolated to the retained WebUI harness: its context init script rewrote tldwConfig to an incomplete legacy shape on every new page, momentarily removing the credential metadata required by direct authenticated probes. Added a shared complete manual-credential seed used by both WebUI and extension wrappers. The product bootstrap itself was confirmed to migrate the same legacy record correctly when it was not repeatedly overwritten. Regression guard: 22/22 passed. Cold-start headless diagnostic showed RAG/readiness probes authenticate and return 200. Focused live Chat-to-Notes rerun passed in 1.1m with no startup 401; RAG and readiness requests still executed successfully. Frontend/test-only change, so Bandit is not applicable.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Fixed the cold-start UAT authentication race by making both retained live-browser wrappers seed the canonical complete manual credential record. Verified the probes still run with authentication and the live retained workflow has no startup 401 responses.
<!-- SECTION:FINAL_SUMMARY:END -->
