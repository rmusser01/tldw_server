## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Follow-up found during the TASK-13950.7 slice 5 work; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

Audio WebSockets check a scoped JWT's allowed_endpoints, allowed_paths and quota, but not its `scope` claim or `allowed_methods`. HTTP audio routes check the `scope` claim through TokenScopeGuard("any", require_if_present=True), e.g. audio_history.py:109. So a virtual-key JWT scoped to another feature opens an audio WebSocket that HTTP would refuse. This predates TASK-13950.7, and streaming_service.py cites this id.
