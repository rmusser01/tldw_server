## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H1b, severity High (security), roadmap phase 3. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

_selected_owner_filter (ChaChaNotes_DB.py:35037) and _selected_keyword_link_filter (:35046) return an empty predicate when owner_client_id is None or the backend is not Postgres (77 call sites in ChaChaNotes_DB, keyword_store and note_store); _require_selected_owner_row has the same guard (22 more). On per-user SQLite files this is correct by design, so SQLite CI can never detect a missing owner, which is how the cross-user leak class recurs. RLS backstops most ChaCha tables (installed at schema init ChaChaNotes_DB.py:27454; startup refuses SUPERUSER/BYPASSRLS roles, factory.py:92-129), but stale comments still call a superuser the documented setup (ChaChaNotes_DB.py:19400-19403, tests/_plugins/postgres.py:335). Helper_Scripts/ci/scope_predicate_ratchet.py ignores is-None guards by design (:58-62) and SCOPE_NAMES lacks owner_client_id. Owner-isolation Postgres tests run in the db-management-a-c shard (ci.yml:928-935).
