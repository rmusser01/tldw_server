## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Follow-up found during execution of TASK-13950.11 group D (PR #3347 reviews); roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

require_local_setup_access treats a request as local when request.client is loopback, the Host header is local, and any proxy client-IP headers resolve to loopback (TLDW_SETUP_TRUST_PROXY defaults to true). Behind a same-host reverse proxy with a bare proxy_pass (default Host 127.0.0.1:8000, no X-Forwarded-For), every remote request looks local, and a client-sent X-Forwarded-For: 127.0.0.1 passes through unchanged. During the pre-setup window (needs_setup true), POST /first-run/providers/validate then lets a remote caller make the server probe an arbitrary URL with the private-network egress opt-in (SSRF). Pre-existing; not introduced by the migrations.
