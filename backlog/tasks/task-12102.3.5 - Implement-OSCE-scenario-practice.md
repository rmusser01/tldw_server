## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Versioned osce.station.v1 contracts and the next dual-backend database migration persist first-class OSCE quizzes, stations, provenance, immutable attempt snapshots, lifecycle state, candidate notes, checklist selections, rubric selections, timestamps, and optimistic versions.
- [ ] #2 Strict validation enforces the approved collection and text bounds, server-owned nested UUIDs, ordered non-numeric rubric levels, source-specific citations, activity-type boundaries, and rejection of unknown, scoring, pass/fail, feedback, and chain-of-thought fields.
- [ ] #3 Authorized station and practice APIs support paginated authoring, retry-safe attempt creation, candidate-phase marking-guide omission, idempotent lifecycle transitions, conflict handling, resume, soft deletion, and deterministic separate checklist and rubric summaries.
- [ ] #4 Source-backed OSCE generation validates and verifies every station before atomic persistence; evidence-bearing edits invalidate verification; candidate notes never enter LLM calls, logs, analytics, or exports; advisory LLM feedback remains deferred.
- [ ] #5 The WebUI supports OSCE generation, inline station editing, advisory timing, serialized autosave with bounded local fallback, self-assessment reveal, accessible checklist and rubric controls, resume, and separately paginated OSCE results without normal quiz-only actions.
- [ ] #6 SQLite, PostgreSQL, API, WebUI, import/export v2, privacy, lifecycle, compatibility, and end-to-end tests satisfy the approved design and preserve legacy question quizzes and tldw.quiz.export.v1 behavior.
