## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Write the Stage 2B design for moving Claims review-metrics aggregation onto the shared Jobs control plane while preserving interval-based rolling lookback behavior, owner isolation, and a one-release compatibility-local path.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 The design preserves the existing interval and rolling-lookback contract while making every Jobs execution use explicit canonical UTC date bounds.
- [x] #2 APScheduler only makes recurring enqueue decisions and creates one owner-scoped Job per eligible owner and stable run slot; Jobs exclusively owns execution lifecycle and administration.
- [x] #3 The design defines strict payload, idempotency, retry, cancellation, result, owner-routing, and SQLite/PostgreSQL parity behavior.
- [x] #4 Claims remains the owner of aggregation rules and persisted daily metrics, including atomic concurrent-safe upserts and explicit UTC grouping.
- [x] #5 The rollout matrix, compatibility-local fallback, transition barriers, configuration bounds, observability, tests, and non-goals are explicit.
- [x] #6 The specification is self-reviewed for placeholders, contradictions, scope drift, implementation ambiguity, and consistency with current dev.
<!-- AC:END -->
