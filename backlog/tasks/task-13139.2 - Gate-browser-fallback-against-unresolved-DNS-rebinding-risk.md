## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Preserve the current Playwright request and WebSocket interception controls, but close the remaining policy gap honestly: URL-level checks do not pin browser DNS or verify the connected peer. Add a fail-closed capability gate for untrusted and strict multi-user retrieval unless an approved pinned transport or governed proxy can attest the destination.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Existing pre-page HTTP and WebSocket interception, redirect/subresource checks, popup handling, and blocked service-worker behavior remain covered and are not reimplemented.
- [x] #2 Documentation and capability metadata state that URL-policy validation alone does not prevent browser DNS rebinding.
- [x] #3 Strict multi-user and untrusted retrieval profiles fail closed by disabling browser escalation unless a governed proxy or equivalent transport provides an approved destination-attestation contract.
- [x] #4 A structured denial reason distinguishes unavailable safe browser transport from ordinary outbound-policy denial and extraction failure.
- [x] #5 Regression tests cover strict-mode denial, permitted attested configuration, redirects/subresources, and preservation of credentialless HTTP extraction.
- [x] #6 This task does not add authenticated browser sessions; any future credentialed browser capability also depends on TASK-13100.
<!-- AC:END -->
