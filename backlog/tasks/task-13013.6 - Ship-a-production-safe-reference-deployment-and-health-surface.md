## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace unsafe production guidance with a reference profile that keeps stateful services private, requires non-default secrets, terminates TLS, and exposes only minimal public liveness while keeping detailed readiness and metrics operator-only.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The production profile does not publish PostgreSQL or Redis and contains no deployable default credential.
- [ ] #2 TLS, reverse-proxy trust, secrets, backup, and rollback requirements are validated by fail-closed preflight checks.
- [ ] #3 Public health returns minimal status while detailed readiness, provider state, database state, and metrics require trusted operator access.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-08-30: Design approved. Use a dedicated production reference profile; expose only minimal public /health; keep /ready, /health/ready, and /metrics private-network-only; require admin authentication for detailed API-v1 health and metrics; enforce TLS, secrets, backup, rollback, and topology requirements with fail-closed preflight.

Baseline verification: 15 targeted deployment/health/metrics tests passed on origin/dev 52774a0453. Sandbox-only cache/log PermissionError warnings did not affect results. No dependencies were installed.
