## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Replace unsafe production guidance with a reference profile that keeps stateful services private, requires non-default secrets, terminates TLS, and exposes only minimal public liveness while keeping detailed readiness and metrics operator-only.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The production profile does not publish PostgreSQL or Redis and contains no deployable default credential.
- [ ] #2 TLS, reverse-proxy trust, secrets, backup, and rollback requirements are validated by fail-closed preflight checks.
- [ ] #3 Public health returns minimal status while detailed readiness, provider state, database state, and metrics require trusted operator access.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
2026-08-30: User approved the reviewed architecture. The formal design now specifies a standalone production profile; exact minimal public /health; loopback-only detail-free /internal/ready; always-authenticated detailed health and metrics through RequirePermission(SYSTEM_LOGS), with administrators retaining the existing bypass; proxy denial of internal, legacy, and completed-setup routes; aligned bounded proxy trust; and fail-closed static plus operational deployment gates covering immutable current/rollback images and verified PostgreSQL, Redis, and app-data backup artifacts. Implementation planning remains intentionally paused pending review of the committed specification.
