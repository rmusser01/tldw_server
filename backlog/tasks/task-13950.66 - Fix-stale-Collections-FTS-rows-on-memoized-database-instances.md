## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Follow-up found during execution of TASK-13950.5 slice 3 (PR #3342 merge review); roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

On memoized CollectionsDatabase constructions (the third and later per process), _fts_supports_direct_delete stays True because it is set in __init__ and refreshed only in ensure_schema. Item updates then run DELETE FROM content_items_fts on the contentless table, which fails silently and skips the re-insert, so the item stays indexed under its old text. Present on dev since 763611cf5f.
