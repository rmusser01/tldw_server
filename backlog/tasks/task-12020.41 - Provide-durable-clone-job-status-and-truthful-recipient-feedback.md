## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Shared-workspace clone returns a pending job ID but exposes no completion status; the WebUI immediately announces success. Add a durable status contract using existing Jobs primitives and make UI feedback track pending, completed, and failed outcomes.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Clone enqueue returns a stable idempotent job reference owned by the requesting user.
- [ ] #2 An authenticated status endpoint exposes bounded pending/progress/completed/failed state without leaking other users' jobs.
- [ ] #3 The UI reports cloning in progress, reports success only after completion, and surfaces a recoverable failure.
- [ ] #4 Repeated clone requests with the same idempotency key do not create duplicate workspaces.
- [ ] #5 Focused tests and live recipient UAT verify completion, failure, authorization, and reload continuity.
- [ ] #6 The clone worker is registered in the supported application worker lifecycle with an explicit enable flag, stable default, inventory visibility, and bounded shutdown; standalone execution reuses the same implementation.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Use the existing Jobs database and WorkerSDK. The API enqueues an owner-scoped idempotent sharing/workspace_clone job; a shared service function executes the clone; both application-managed and standalone workers call that function. Do not require an undocumented manual worker in normal deployments. The status endpoint returns only a bounded, typed clone projection after owner authorization.
<!-- SECTION:IMPLEMENTATION_NOTES:END -->
