## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Shared-workspace clone returns a pending job ID but exposes no completion status; the WebUI immediately announces success. Add a durable status contract using existing Jobs primitives and make UI feedback track pending, completed, and failed outcomes.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Clone admission returns a stable owner-scoped Workspace operation backed by an atomic Jobs idempotency receipt.
- [ ] #2 Authenticated status reads expose one bounded canonical operation envelope from active or archived Jobs without leaking another user's operation.
- [ ] #3 The UI reports queued/running state inline, reports success only after terminal completion, surfaces partial retrieval readiness and recoverable failure, and opens the deterministic target Workspace.
- [ ] #4 Same-key active, concurrent, response-loss, and archived replays cannot create duplicate workspaces; request mismatches return 409 and corrupt correlation fails closed.
- [ ] #5 Clone results distinguish copy outcome from text, citation, and vector readiness; absent vector indexing is explicit and tracked by TASK-12020.45.
- [ ] #6 The clone worker is registered once in the supported declarative application lifecycle, uses the allowed sharing queue, honors route/flag/sidecar policy, and reuses the same standalone handler.
- [ ] #7 Current share permission is revalidated before content copy, clone_workspace capability metadata is authoritative, and status remains owner-readable after later revocation.
- [ ] #8 Focused SQLite/PostgreSQL, backend, frontend, lifecycle, security, and live backend plus WebUI CDP verification covers completion, partial readiness, failure, authorization, replay, archive, and reload recovery.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Implement the revised approved-direction design in Docs/superpowers/specs/2026-08-25-shared-workspace-clone-jobs-design.md. Jobs remains the sole execution/status authority. Add a generic atomic idempotency receipt with a 30-day replay window, active/archive lookup, forced archive-on-prune for receipt-backed Jobs, and owner/share admission locking that converges matching concurrent requests. Expose canonical Workspace operation fields and truthful retrieval readiness. Revalidate share permission before and during a repeatable source snapshot. Offload blocking work without crossing DB handles between threads. Reserve and publish deterministic staged targets through explicit CharactersRAGDB methods; reconcile failed staged targets. Use an operation-owned Media snapshot insert that never aliases or mutates unrelated recipient media. Use the strict shared-workspaces client, pre-submit scoped recovery records, canonical Shared With Me component ownership, and no page-level banner, trust bar, alias, or redirect. TASK-12020.45 owns durable clone vector reindex orchestration.
Delivery decomposition after pre-implementation review: TASK-12020.46 and TASK-12020.47 are parallel backend foundations; TASK-12020.48 integrates API/worker/lifecycle after both; TASK-12020.49 is a contract-first frontend track that can proceed in parallel and then integrate; TASK-12020.50 is the live CDP acceptance gate.
