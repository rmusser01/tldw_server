## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Follow-up found during execution of TASK-13950.3 (PR #3329 merge review); roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

ChaChaNotes_DB.py creates a global unique index on flashcard_templates(name). Under the FORCE RLS policies #3329 adds, a user who picks a name another user already holds gets a ConflictError on a row they cannot see, which is also an existence probe across tenants. Before #3329 templates had no Postgres owner filter at all, so RLS closes the read/write leak but leaves the uniqueness leak.
<!-- SECTION:DESCRIPTION:END -->

- [ ] #3 A Postgres name conflict maps to ConflictError (today the mapping matches only the SQLite 'UNIQUE constraint failed' message), proven in the Postgres shard along with no cross-user existence leak
