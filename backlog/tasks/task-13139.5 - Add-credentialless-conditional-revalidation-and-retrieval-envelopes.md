## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Extend the existing opt-in in-memory web.fetch TTL/LRU cache with conditional HTTP revalidation for public credentialless retrieval and return a serializable versioned retrieval envelope. The envelope is provenance data, not a new durable store; Media remains the only durable snapshot owner.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Fresh cache entries retain current behavior; stale eligible entries issue If-None-Match or If-Modified-Since and handle 304 without re-extracting unchanged content.
- [ ] #2 The first release caches only public credentialless requests using the existing bounded key dimensions; authorization, cookies, custom credential-bearing headers, arbitrary Vary handling, owner-scoped durable caches, and cross-process persistence are out of scope.
- [ ] #3 Any future credential-bearing request shape bypasses this cache fail closed until a separately approved owner-isolation contract exists.
- [ ] #4 A serializable versioned retrieval envelope carries safe final URL, retrieval time, content fingerprint, selected validators, extraction/quality versions, bounded tier trace, and change classification without raw secrets.
- [ ] #5 The in-memory cache remains opt-in, bounded, TTL/LRU governed, process-local, and safe to discard; the envelope can be handed to Media but is not persisted by MCP.
- [ ] #6 Tests cover 200-to-304 reuse, changed 200 replacement, validator absence, cache expiry/eviction, credential bypass, content-limit changes, and redaction.
<!-- AC:END -->

## Implementation Plan
