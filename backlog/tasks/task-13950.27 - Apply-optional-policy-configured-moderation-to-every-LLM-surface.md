## Description

Owner decision 2026-10-25: moderation applies to every LLM-calling surface but stays optional and policy-configured. Today moderation runs only in the /chat/completions path (chat_service.moderate_input_messages :3651, streaming output in execute_streaming_call, non-stream via moderation_pipeline.apply_output_safety_to_choices :86) and surfaces that call that route (persona live, writing playground). perform_chat_api_call(_async) (chat_service.py:2643-2742) applies none, and 53 files call or reference them. Unmoderated: the chat auto-router sends the latest user turn to an LLM (chat.py:3666) before the input check (:4517); /api/v1/messages (messages.py:2116,2143); character complete-v2 (:7439), roleplay resume and router; workflow LLM steps; RAG generation (generation.py:532); voice assistant (VoiceAssistant/router.py:1153); voice chat WS (speech_chat_service.py:815, docstring says it avoids moderation); study assistant and StudyPacks; Prompt Studio and media summarization (direct adapter calls); watchlists briefs; deep research; MCP quizzes; VN Play has its own unwired hook. Policy today: config.txt [Moderation] enabled = False, MODERATION_* env (config_sections/moderation.py), per-user overrides (/moderation/users/{id}); no per-surface or per-org scope.

Review and dry run (2026-10-25): Review: per-user overrides coalesce enabled (Moderation/policy_compiler.py:138) and Guardian forces enabled=True for supervised accounts (Moderation/supervised_policy.py:325), so a literal 'enabled=False disables everywhere' would switch off parental controls; AC3 keeps them.

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Moderation now applies to every LLM surface the server owns, optionally and by policy. The gateway hooks (core/LLM_Calls/gateway.py, registered by the Moderation package at app startup and in every LLM worker) moderate input messages before and model output after each provider call, stream and non-stream, for the 44 moderated surfaces in core/Moderation/surfaces.py; a call that names no surface is moderated as unclassified. Chat (chat.completions) keeps its own pipeline and audit rows; the hooks skip it. Configuration: the existing [Moderation] policy and per-user overrides, plus per-surface keys (surface.<id> = true|false) that can only narrow the default and a stream_buffer_chars holdback (default 1024); Guardian supervised overlays still force moderation on. Exempt, with reasons: internal.byok_probe (fixed prompt), internal.eval_judge (owner decision: measurement), moderation.classifier (it is the moderation) and the OCR LLM backends (owner decision: transcription). Enforcement: a shrink-only guard baseline of unsurfaced gateway calls, a direct-adapter ratchet, and an R10 lint that keeps exempt ids in their designated modules; both baselines end with only Summarization_General_Lib.py and byok_testing.py, each with a reason. Known limitations (follow-ups TASK-13950.189 to .207): hook surfaces write no audit rows and run no self- or topic monitoring; system-message text, list content parts, tool-call arguments and reasoning_content are not moderated; the /llamacpp passthrough and Local_LLM handlers are outside the gateway; hook surfaces moderate only the provider request, so a surface may persist unredacted user text; stream holdback adds latency up to stream_buffer_chars.
