## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H11, severity High, roadmap phase 4. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

Adding a provider touches about 22 files (moonshot: 16 backend, 3 config, 3 frontend). 17 provider-keyed tables drift from the 27-key registry (adapter_registry.py:51-79): e.g. byok_runtime.py:184 lacks anthropic, bedrock, groq and others; capability_registry.py:106 lacks bedrock so policy stamping skips bedrock_api; Setup/provider_catalog.py:11 uses different spellings; llm_providers.py:1587 and Workspaces/service_capabilities.py:34 list minimax, which has no adapter; chat_validators.py:459 ALLOWED_PROVIDERS and validate_provider_name are dead. Six alias tables point in opposite directions (provider_identity.py:11, provider_readiness.py:17, Summarization_General_Lib.py:67, extra_body_compat_catalog.py:79, wordbench_runner.py:26, tokenizer_resolver.py:33), which already cost three separate llama-alias fixes (TASK-12120, TASK-12867, TASK-13260.178). adapter.capabilities() disagrees with provider_metadata.PROVIDER_CAPABILITIES for 16 of 26 providers (e.g. kobold streaming, tabbyapi tools, bedrock timeout), and /llm/providers serves the static map as fallback (llm_providers.py:2150). Open PRs #3191, #3180, #3187 touch these tables.
