## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the disabled-by-default skills_runner module and skills.run tool after the generic failure and bounded model ports exist. Load one strict single-file user-scoped Skill snapshot, close the Skills database, and perform one capability-gated model-only completion under effectful MCP authorization and bounded lifecycle controls.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A separate disabled-by-default skills_runner module exposes only skills.run and has the model_execution risk tier.
- [ ] #2 The strict snapshot loader accepts only the explicit documented frontmatter key/type allow-list with context fork, user-invocable true, model invocation enabled, no tools, and no model selector; it rejects coercion, aliases used together, duplicate/unknown keys, YAML anchors/aliases/merges/tags, excessive parser budgets, and every directory entry beyond one regular SKILL.md.
- [ ] #3 Under the existing per-user mutation lock, snapshot loading performs a targeted optimistic registry reconciliation for only the selected Skill from the same captured bytes; it never calls catalog-wide synchronization, reads/mutates unrelated Skills, trusts a stored directory path, or indexes an invalid/integrity-blocked file.
- [ ] #4 The loader uses fail-closed no-follow stable-identity access, bounds SKILL.md before allocation/decoding, detects concurrent mutation, never reads supporting-file bytes, validates the raw text hash against registry file_hash, and independently validates the canonical single-file Skill digest with Context Integrity purpose skill_execution.
- [ ] #5 The runner preserves textual arguments without SQL-oriented mutation, requires strict UTF-8 encodability, rejects prohibited controls, and closes all Skills database resources before model dispatch.
- [ ] #6 Tool catalog and call classification agree through write_capable, uses_network, rate_limit_fail_closed, readOnlyHint false, and explicit call classification; rate-limit denial or admission-service failure prevents model dispatch.
- [ ] #7 The runner uses the bounded model port exactly once, returns the approved stable success/error contracts, and preserves authorization, idempotency disclosure, hooks, audit, metrics, and reporting.
- [ ] #8 Focused runner, targeted-reconciliation, Skills regression, public tools/call integration, lifecycle, rate-limit, configuration, documentation, lint, compile, and Bandit checks pass.
- [ ] #9 Public failure precedence is deterministic and oracle-safe: inability to establish current visibility maps to skill_not_found; specific fork/tools/files/model/prompt reasons appear only after visibility is proven, and extra entries are never opened.
- [ ] #10 The runner constructs ModelInvocationIdentity only from positive numeric explicit server-authenticated user and optional active team/organization RequestContext fields plus a server-generated execution ID; spoofed metadata, request arguments, headers, client/request IDs, and arbitrary memberships cannot influence credential or billing scope.
- [ ] #11 Focused integration proves the same user/key/arguments under different authenticated active team/organization scopes cannot replay another scope's result, while personal/no-active-scope replay remains compatible and performs no second model dispatch.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
2026-07-25 final design consistency review: distinguished the registry raw SKILL.md content hash from the canonical Context Integrity filesystem digest. Execution must recompute the canonical user Skill asset digest and require it with exact purpose skill_execution.
2026-07-25 final design consistency review also made the strict frontmatter allow-list and exact user-invocable requirement explicit so execution eligibility cannot depend on permissive parser defaults or coercion.
2026-07-25 parser/lifecycle review added fixed frontmatter byte/node/depth budgets, rejection of YAML graph/tag features, a limit-plus-one SKILL.md read, and fail-closed platform requirements for no-follow stable-identity filesystem access.
2026-07-25 repository contract review found that catalog-wide Skills synchronization is not a safe execution snapshot primitive. The runner must reconcile only the requested row under the mutation lock from the same bounded captured bytes, with optimistic and post-mutation checks.
2026-07-25 error-precedence review made overlapping invalid states deterministic and oracle-safe. A malformed current file cannot reveal existence; specific eligibility reasons require proven current visibility.
2026-07-25 credential-scope review assigned the runner side of the boundary here: capture only explicit authenticated user/active-scope fields into the immutable model identity. TASK-2294.3.2 remains responsible for authoritative membership revalidation and credential precedence.
