## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cloning currently copies source text and chunks but deliberately does not copy or regenerate vector embeddings. Add a durable, deployment-compatible reindex path so a cloned shared workspace can transition from text/citation ready to vector-search ready without hidden fire-and-forget work.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Choose and document a durable indexing primitive that works without an undocumented Redis-only deployment dependency.
- [ ] #2 Reindex admission and retries are idempotent and surface progress through canonical Workspace source/readiness status.
- [ ] #3 A cloned workspace transitions from vector_search=needs_indexing to ready only after target vectors are verified.
- [ ] #4 Failures remain recoverable and never convert clone copy completion into false full-readiness success.
- [ ] #5 Focused backend/frontend tests and live backend CDP UAT verify vector-grounded retrieval after clone.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Created from the TASK-12020.41 pre-implementation design review. Keep clone copy execution truthful and bounded; do not add a hidden embeddings side effect to the clone worker.
