## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add a small versioned deterministic fusion utility beside the general Web_Scraping SearchResult and SearchResultsPayload contracts. MCP web.search may compose it directly; scholarly Research discovery may reuse scoring primitives but must preserve its domain-specific identity and open-access metadata.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The reusable fusion API lives with general Web_Scraping search contracts and does not require or return scholarly Research DiscoveryResult models.
- [ ] #2 Canonical URL deduplication, reciprocal-rank fusion, independent-provider consensus, domain diversity, deterministic tie-breaking, and provider degraded/failed status are specified and versioned.
- [ ] #3 MCP web.search can opt into concurrent provider fan-out and the general fused payload without changing single-provider default behavior.
- [ ] #4 Research discovery can reuse narrowly scoped normalization or scoring primitives without losing DOI, PMID, PMCID, arXiv, open-access candidate, or provider metadata.
- [ ] #5 Offline fixtures prove determinism, duplicate handling, weak/degraded outcomes, provider-order independence, and compatibility with existing SearchResult payloads.
<!-- AC:END -->
