## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Follow-up found during execution of TASK-13950.2 (PR #3324); roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

The merge review of #3324 found these deferrable follow-ups, none reachable as data loss or cross-account delivery today. (1) apps/packages/ui/src/hooks/document-workspace/useAnnotationSync.ts keeps a module-level unloadContextRef that is never cleared, so a new mount uses the previous mount's scope and headers until its own preparation finishes; the URL is also resolved apart from the header plan (plan.url discarded, request-core.ts:660-673). (2) Header recompute keys on lastConfigUpdatedAt and misses token refresh, login and logout; CSRF can be re-read at send time. (3) A batch the server permanently rejects (404 for deleted media, a future 422) is kept forever and merged into every later unload and replay for that media. (4) Persisted pending annotations stay in localStorage after logout and until that media is reopened. (5) In-app navigation (unmount) still relies on forceSync without local persistence. (6) Tests do not assert Content-Type: application/json on the unload request, header recompute, or failed-replay retention. (7) api/v1/schemas/document_annotations.py client_ids are now idempotency keys but undocumented and without max_length on an indexed column.
<!-- SECTION:DESCRIPTION:END -->
