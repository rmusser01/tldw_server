## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 API export treats omitted content_selections as full user-account export.
- [ ] #2 API export treats content_selections: {} as full user-account export.
- [ ] #3 Backend schema, OpenAPI examples, and TypeScript client types allow omitted content_selections.
- [ ] #4 Non-empty content_selections remains explicit allowlist mode, with empty arrays meaning no items for that type.
- [ ] #5 Zero-item allowlists are rejected with a 4xx validation error instead of creating empty backups, and normal UI flows block them with clear validation.
- [ ] #6 Account-data inventory covers every account-owned database, file, vector, settings, relationship, and sensitive-data category in scope.
- [ ] #7 Full user-account export includes media records and associated stored/derived media data.
- [ ] #8 Full user-account export includes other account-owned records needed to restore account state, not only named content-selection types.
- [ ] #9 Export manifests and completed jobs report inventory counts, archive size, pointer-only counts, warning counts, and post-write verification status.
- [ ] #10 Main UI and extension Backup all use the API all-export contract and show a readable scope summary with categories, counts, pointer-only counts, sensitive-category counts, warnings, and estimated archive size.
- [ ] #11 Default archive import restores all account data present in the archive, including media records and associated stored/derived media data.
- [ ] #12 Backend media/embedding import reject paths are removed or replaced with working restore handlers.
- [ ] #13 Full import does not silently skip inventory categories.
- [ ] #14 Sensitive values are included, excluded, redacted, warned, logged, and audited according to the PRD sensitive-data policy.
- [ ] #15 Unsupported raw-source-file import toggles are disabled, hidden, or clearly marked unavailable rather than normal enabled options.
- [ ] #16 User guide, API docs, examples, and release/migration notes match runtime behavior.
