## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement child task 3 from the Paperless-inspired document lifecycle PRD: surface duplicate file and source identities as actionable recovery choices while preserving permission boundaries.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Duplicate local files show recoverable actions when the current user has access.
- [ ] #2 Duplicate URL or source-hash matches show recoverable actions when the current user has access.
- [ ] #3 Trash duplicates show restore when permitted.
- [ ] #4 Inaccessible duplicates do not leak titles, paths, owners, workspace names, other sensitive metadata, or the existence of a match.
- [ ] #5 Tests cover duplicate identity normalization, permission-safe responses, and UI action routing.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
- Confirmed duplicate responses may only include records the current user can open, attach, or restore.
- When lookup finds only inaccessible matches, return non-confirming copy such as `No recoverable duplicate found` and preserve normal ingest when policy allows.
- If a hard duplicate constraint blocks ingest because of an inaccessible match, return generic non-confirming user-facing copy.
- Do not expose a separate "permission-blocked duplicate exists" result.
