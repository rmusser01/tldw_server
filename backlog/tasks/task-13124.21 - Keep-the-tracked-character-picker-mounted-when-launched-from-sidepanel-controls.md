## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Three live attempts/paths failed: (1) the old chat-character-select path does not exist in the current sidepanel; (2) using Character controls then Start tracked character chat closed without showing AssistantSelect; (3) dispatching the picker event before the close callback still produced no panel. Reassessment: AssistantSelect is hosted inside CharacterControlsSheet, so closing or hiding the launcher is structurally coupled to the picker listener/portal. Alternatives reviewed: keep the controls modal open while the picker is active; mount a permanent picker host at form scope; drive an unrelated overlay picker. Preferred minimal path: keep controls open for tracked selection and close only through the user's normal modal action, then validate live before considering a lifted host.

Live reassessment result: even keeping CharacterControlsSheet mounted did not make its global AssistantSelect event listener produce a panel. The event/portal approach is not a dependable runtime seam. Next alternative is an inline tracked AssistantSelect rendered and owned directly by the controls sheet, eliminating the global event dependency.
<!-- SECTION:NOTES:END -->
