## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950; found during TASK-13950.19 Task 7 (ledger, 2026-11-05). Three symptoms of one lifecycle in the get_db_transaction dependency and _transaction_context in auth_deps.py. (1) get_db_transaction is a FastAPI request-scoped yield dependency, so it commits after the response is sent: a commit that fails after a 200 silently loses the change. (2) The audio transcriptions and translations endpoints hold Depends(get_db_transaction), keeping a SQLite BEGIN IMMEDIATE open across the whole STT run. (3) _transaction_context raises TransactionError from None, which drops the cause of endpoint errors, so endpoint bugs log as 'SQLite transaction failed'.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A commit failure is returned to the client as an error (no 200 followed by a lost write), with a test that forces the commit to fail
- [ ] #2 The audio transcriptions and translations endpoints hold no write transaction while the STT run executes, with a test that a concurrent writer is not blocked during it
- [ ] #3 _transaction_context keeps the original exception as the cause (raise ... from exc), with a test that an endpoint error logs its own type and message
