## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Live multi-user PostgreSQL UAT for TASK-12020.39 reproduced a 500 from notes search when concurrent workspace initialization requests each authenticated through AuthnzUsersRepo. AuthnzUsersRepo constructs a fresh UsersDB and runs users-table DDL on every lookup, allowing ordinary request concurrency to deadlock on PostgreSQL table locks. Move schema assurance back to startup/explicit initialization while preserving standalone UsersDB setup behavior.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 AuthnzUsersRepo operations backed by an initialized DatabasePool do not run users-table schema DDL during ordinary reads or writes.
- [ ] #2 Explicit standalone UsersDB initialization continues to ensure the users schema for SQLite and PostgreSQL callers.
- [ ] #3 A focused regression test fails if repository user lookup invokes UsersDB schema creation.
- [ ] #4 PostgreSQL concurrent authenticated lookup verification completes without deadlock-derived 500 responses.
- [ ] #5 The TASK-12020.39 live Chrome CDP flow no longer records the notes-search 500.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Preserve explicit UsersDB schema assurance by default, add an explicit opt-out for repository adapters that receive the initialized shared DatabasePool, prove request-time lookups do not open DDL transactions, then verify concurrent PostgreSQL requests and the live Chrome CDP flow.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Root cause confirmed from the live PostgreSQL backend: AuthnzUsersRepo._users_db() creates a new UsersDB and runs _create_tables() during each authenticated repository operation. Concurrent workspace initialization requests can deadlock on users-table DDL and surface as unrelated endpoint 500s. Design recorded at Docs/Design/2026-07-15-authnz-request-time-usersdb-schema-ddl-design.md. Independent spec review result: APPROVED.
