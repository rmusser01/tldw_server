## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Cut standalone Research Discovery over to the certified shared executor and expose explicit legacy, source, preset, category, and automatic selection contracts with a usable large-catalog interface. Preserve absent-mode legacy behavior, show the effective external plan and truthful readiness, and prove end-to-end operation across more than eight source targets.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The API exposes a dry-run/effective plan with selected targets, actual backends receiving query text, coalesced physical requests, readiness, policy and budget skips, selection reasons, and catalog/preset/policy versions.
- [ ] #2 The source controls remain usable across the complete 235-row frozen inventory through search, grouping, filtering, presets, keyboard navigation, accessible state labels, and ready-only defaults that distinguish the 191 currently mapped credentialless targets from unavailable entries.
- [ ] #3 Users can distinguish selected, attempted, no-results, successful, failed, unavailable, policy-blocked, and budget-skipped targets and can retain partial results when one source fails.
- [ ] #4 A controlled end-to-end test selects at least twelve routable targets, proves shared-backend coalescing and physical-budget accounting, and preserves requested-source, backend-route, gateway-observed transport-origin, and untrusted reported-document-origin provenance.
- [ ] #5 Golden API/OpenAPI behavior, frontend loading/empty/error/partial/responsive/accessibility states, redaction, focused tests, lint/format checks, Bandit, and diff hygiene pass before the new mode becomes the UI default.
- [ ] #6 If the canonical selection object is absent, the characterized legacy default and legacy source/category union remain unchanged; canonical modes are mutually exclusive, versioned, and reject null, unknown, or conflicting fields according to the approved truth table.
<!-- AC:END -->
