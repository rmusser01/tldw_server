## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Add the narrow host-composed model completion port required by the MCP Skills runner. Bind one operator-configured provider/model pair, explicit server-authenticated user and active team/organization scope identity, authoritative membership and credential-precedence resolution, quota reservation/reconciliation, native async cancellation, provider-native output token bounds, pre-decode response-byte bounds, and one outbound request attempt with all server-controlled retries and fallbacks disabled.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The host-neutral port exposes immutable positive numeric user and optional active team/organization identity plus a fixed-format server-generated opaque execution ID, capability, bounded request, and normalized result contracts without credentials, client/request identifiers, request metadata, or mutable MCP RequestContext.
- [ ] #2 The production adapter revalidates active-scope membership and relationships from authoritative AuthNZ state, follows user then active-team then active-organization then server credential precedence without guessing memberships, advances only on authoritative absence, uses the frozen server endpoint with base-URL override trust disabled, and fails closed on invalid/revoked/unavailable scope.
- [ ] #3 User/team/organization/server credential-scope failures and request-content-dependent provider outcomes do not mutate the global module breaker; only shared adapter, identity/accounting-store, and fixed provider-transport failures with trusted shared provenance may select record-failure behavior.
- [ ] #4 Only a certified native-async provider path with hard response-byte, output-token, tool-suppression, cancellation, and no-server-retry capabilities is healthy.
- [ ] #5 Provider output normalization deterministically requires one non-empty textual choice, rejects tool calls, malformed Unicode and prohibited controls, normalizes only line endings, and enforces character/UTF-8 byte limits without truncation.
- [ ] #6 A durable worst-case quota/cost reservation occurs before dispatch; pre-dispatch cancellation releases it, post-dispatch ambiguous outcomes retain it, and post-completion reconciliation failure returns the valid result with the conservative reservation intact rather than inducing a duplicate call.
- [ ] #7 A provider child that misses the cancellation cleanup deadline remains lifecycle-owned with its late result discarded, retains ambiguous accounting, and makes adapter health fail closed until termination; no task is left unreferenced.
- [ ] #8 At most one outbound provider request attempt occurs with no server-controlled retry, fallback, streaming, tools, or multiple choices.
- [ ] #9 Focused provider, credential-precedence, active-scope authorization, quota, egress, cancellation, retained-child lifecycle, bounds, output-normalization, identity-minimization, breaker-scope isolation, lint, compile, and Bandit checks pass.
- [ ] #10 Provider response limits are enforced over decompressed limit-plus-one bytes before JSON parsing; compressed expansion cannot bypass the cap.
- [ ] #11 MCP authentication populates optional active team/organization fields outside generic request metadata; both fields are included in prepared-context integrity and second pre-dispatch verification, and single-user/no-active-scope calls preserve existing behavior.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Coordinate with TASK-12963 because it actively owns the shared provider credential/runtime, Chat accounting, and OpenAI adapter contracts. Revalidate its landed interfaces before planning or editing provider code; do not duplicate the consolidation.
2026-07-25 final design consistency review: because the MCP module breaker is shared across users, provider outcomes influenced by one Skill, prompt, credential scope, or response content are neutral. record_failure requires trusted shared-infrastructure provenance; status or exception class alone is insufficient.
2026-07-25 output-contract review made normalization deterministic: bounded envelope first, one textual choice, strict UTF-8, line-ending normalization only, no empty/control-bearing output, and atomic character/byte enforcement.
2026-07-25 identity minimization removed client-influenced request_id/client_id and mutable RequestContext from the provider port. The adapter receives only explicit server-authenticated positive numeric user and optional active team/organization IDs plus a server-generated opaque execution_id.
2026-07-25 cancellation review defined containment for a transport that violates its native-cancellation contract: retain task ownership, discard late output, retain ambiguous accounting, and fail adapter health closed.
2026-07-25 transport review clarified that response-byte accounting must cap decompressed bytes, not only Content-Length or wire bytes.
2026-07-25 credential-scope review found that user_id alone cannot reproduce TASK-12963's active-team/active-organization precedence when a user has multiple memberships. The identity contract carries only explicit server-authenticated positive numeric active scope IDs, revalidates membership and team/organization relationship, skips absent scopes without guessing, and fails closed on invalid/revoked/unavailable scope.
