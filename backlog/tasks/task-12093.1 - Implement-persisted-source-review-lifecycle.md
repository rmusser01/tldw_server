## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Implement child task 1 from the Paperless-inspired document lifecycle PRD: add a persisted source review lifecycle that is distinct from transient Quick Ingest row status and usable by Research Workspace source filters.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Persisted review state survives page reloads and workspace reloads.
- [ ] #2 Review state is visible in Research Workspace source rows and details.
- [ ] #3 Users can mark one source or selected sources as reviewed and can return reviewed sources to needs-review.
- [ ] #4 Needs-review state is available to source filters and built-in source views.
- [ ] #5 Existing workspace sources migrate or default to `unset` and are not treated as reviewed.
- [ ] #6 Review state is exposed through dedicated fields on workspace source/status responses, separate from processing status.
- [ ] #7 Each review-state transition records `review_state_updated_at`.
- [ ] #8 Review actor and timestamp are recorded when a source becomes reviewed, when auth context is available, and reviewed-only fields are cleared when a source leaves reviewed.
- [ ] #9 Quick Ingest and extension workspace attachments can opt into defaulting new workspace sources to needs-review.
- [ ] #10 Tests cover backend/state normalization, persistence, permissions, and UI state transitions.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
- V1 review state belongs on workspace source associations, not global media items.
- Use the enum `unset`, `needs_review`, and `reviewed`.
- Do not overload queued/indexing/queryable/failed processing status with review state.
- Bulk review updates require the same workspace-source write permission as single-source updates.
