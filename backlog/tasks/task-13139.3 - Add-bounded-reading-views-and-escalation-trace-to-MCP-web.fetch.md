## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 web.fetch can request whole, table-of-contents, section, or focused views plus optional must-contain validation while preserving the existing default response contract.
- [ ] #2 Character and UTF-8 byte limits are authoritative; any token field is an explicitly approximate convenience value with no tokenizer dependency.
- [ ] #3 Continuation is stateless and carries a content fingerprint plus block index or character offset; continuation is rejected with a structured reason when the fetched content changed.
- [ ] #4 Responses expose versioned extraction-quality metadata and the existing article orchestrator's attempted tiers, selected tier, trust classification, and bounded failure reasons.
- [ ] #5 HTTP-to-browser escalation continues to be decided by the current article orchestration and preflight contracts; this task only exposes trace data and addresses measured classifier gaps found by fixtures.
- [ ] #6 Focused MCP and Web_Scraping tests cover compatibility, view selection, budgets, changed-content rejection, and strict-browser-gate behavior.
<!-- AC:END -->
