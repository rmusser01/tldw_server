## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Live extension UAT proved the media review route can issue overlapping GET /api/v1/media/{id} requests while resolving a permalink. A display-results change cancels only the consumer of the first request; a later conditional 304 can then become the accepted response and replace usable media content with an empty value, leaving Generate Analysis disabled.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A permalink media selection performs at most one accepted detail hydration for the same pending media id while result lists change.
- [x] #2 A stale, cancelled, empty, or conditional response cannot overwrite already resolved media content.
- [x] #3 Regression coverage reproduces the display-results rerender race and passes.
- [x] #4 The retained live extension analysis workflow completes generation, persistence, review, and re-analysis.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Add focused failing hook coverage for permalink hydration across display-result changes; stabilize the effect identity/acceptance logic; run focused unit tests and retained live workflow.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Three live attempts failed: (1) replacing the duplicated parser with the canonical extractor did not stop empty content; (2) reusing the pending request across result-list rerenders still allowed the matching-result branch to abandon it; (3) publishing lastFetchedId before selection still produced an initial 200 followed by a 304. Reassessment: the matching search result uses a different ID representation and replaces the in-flight permalink hydration; strict identity/early matching-result logic then launches a second detail request. Alternatives reviewed: normalize ID equality only; keep the in-flight request authoritative when a matching result appears; move content recovery into AnalysisModal. Preferred: preserve the in-flight detail request and merge its body with matching-result metadata.

Live reassessment result: preserving the in-flight request when a matching string-ID result arrived still left Generate disabled. The route-level state is not a reliable single source under the extension cache path. Next alternative is deliberately independent: AnalysisModal will recover missing content from a cache-busted detail request and use the canonical extractor, so the action is not coupled to navigation hydration timing.
<!-- SECTION:NOTES:END -->
