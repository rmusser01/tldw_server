## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H3 (sub-finding), severity Medium (bug), roadmap phase 0. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

core/AuthNZ/session_manager.py:2079-2085 initializes the global session manager without a lock and publishes the singleton (:2083) before await initialize() completes (:2084), so concurrent first callers can receive a half-initialized one. core/MCP_unified/server.py:2317 get_mcp_server is likewise unlocked. The structural fix (an app-scoped container) is TASK-13950.18; this task fixes the race now.

Review and dry run (2026-10-25): Correction from review: on one event loop only one manager is built; the harm is that callers receive a half-initialized manager whose methods' own lazy `if not self._initialized: await self.initialize()` checks then run initialize() concurrently (duplicate DB pool, Redis client and scheduler.start). A module-level asyncio.Lock left bound to a previous test's event loop raises RuntimeError in the next test.
