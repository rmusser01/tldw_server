## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding owner item 5 (mlx), severity High (bug), roadmap phase 0. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

MLXChatAdapter is registered (core/LLM_Calls/adapter_registry.py:67) and chat_service special-cases provider == "mlx" (core/Chat/chat_service.py:2433); the WebUI resolves MLX models to api_provider "mlx" (apps/packages/ui/src/utils/resolve-api-provider.ts:60). But ALL_SUPPORTED_PROVIDER_NAMES_LIST (api/v1/schemas/chat_request_schemas.py:203-233) has never contained mlx (git log -S), so ChatCompletionRequest(api_provider="mlx") raises "Unsupported api_provider: mlx" (reproduced with the repo venv). tests/LLM_Calls/test_mlx_provider_integration.py:95 calls perform_chat_api_call_async directly and never exercises the schema. The long-term fix (derive allowlists from the registry) is TASK-13950.31; this task is the immediate fix.

Review and dry run (2026-10-25): Dry run: with only mlx added, the schema and parity tests pass and no other /chat/completions gate rejects mlx. Patching only perform_chat_api_call_async lets the real adapter return 400, which would satisfy a not-422 assertion for the wrong reason. Setup readiness tables also lack mlx; that belongs to TASK-13950.31.
