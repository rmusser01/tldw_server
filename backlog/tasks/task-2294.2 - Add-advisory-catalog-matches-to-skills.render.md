## Implementation Notes

Goal revalidated against TASK-2294, completed TASK-2294.1, SkillsModule, SkillExecutor, MCPProtocol tool listing, and the standalone gateway boundary. Review removed the renderer-local invalid state because the shared parser already coerces some raw values, removed duplicated resolved/unresolved declaration arrays and their speculative bounds, renamed the field to catalog_matches to avoid conflicting with SkillExecutor resolved_tools semantics, documented the reused handler's partial-result behavior, and retained explicit cancellation propagation. The implementation is now one render-path change plus focused tests and operator documentation. No implementation begins until this written design is approved.

Approved design translated into a four-stage TDD plan: direct non-executing render, exact catalog matching, bounded failure/cleanup/cancellation handling, and final regression/security gates. Plan scope is one production module, its existing contract suite, and one operator document; no adjacent production subsystem is modified.
