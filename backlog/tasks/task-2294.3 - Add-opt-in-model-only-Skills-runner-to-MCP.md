## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Design and implement the first executable MCP Skills slice as a separate, disabled-by-default `skills_runner` module exposing one bounded, model-only `skills.run` tool. The slice supports verified fork-mode Skills that declare no tools and no supporting files. It establishes authorization, provider-runtime, lifecycle, cancellation, observability, and result contracts without changing the existing read-only `skills` module or adding nested tool execution, workflow scripts, subagents, durable Jobs, or approval continuation.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A separate `skills_runner` module exposes only `skills.run`, is disabled by default, and has an explicit model-execution risk tier; the existing read-only `skills.list`, `skills.get`, and `skills.render` module contracts remain unchanged.
- [ ] #2 Only user-scoped, model-visible, integrity-verified fork-mode Skills with valid empty tool and supporting-file declarations are eligible; malformed or unsupported Skills fail before model invocation with stable sanitized errors.
- [ ] #3 The runner loads one immutable Skill snapshot and closes the request-scoped Skills database before model/provider work begins.
- [ ] #4 Normal MCP authorization applies to the `skills.run` tool and the existing `Skill(skill_name)` subject; `skills.run` is classified as effectful for write-scope checks, rate limiting, idempotency, hooks, audit, metrics, and tool-use reporting.
- [ ] #5 Model invocation uses a narrow injected port with server-managed provider credentials, provider usage quotas, and existing outbound-egress enforcement; request arguments cannot supply credentials, endpoints, provider overrides, or arbitrary model overrides.
- [ ] #6 The runner performs exactly one logical tool-disabled completion and one model turn with no module-level retry. Character, UTF-8 byte, provider-envelope, wall-time, and cancellation bounds fail atomically; cancellation propagates and retained work is canceled and drained without partial success.
- [ ] #7 Successful results expose bounded final output and sanitized execution metadata without rendered Skill contents, raw provider responses, credentials, endpoints, paths, or raw exception text.
- [ ] #8 Focused unit, integration, authorization, lifecycle, cancellation, configuration, risk-surface, regression, lint, compile, Bandit, and documentation checks cover the changed scope; nested tools and broader orchestration remain in TASK-2294.4 and TASK-2294.5.
<!-- AC:END -->
