## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
When collection setup fails after creating some source rows, Quick Ingest records their failure and stops before ingesting. A later user retry may create a second collection. Preserve the collection and stable source identities across partial writes, lost acknowledgements, and concurrent retries.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Reopening or retrying the interrupted setup uses the same owner-scoped collection and creates each source row once, including a request whose acknowledgement was lost.
- [x] #2 Concurrent resumes and user changes to item order or editable metadata preserve the identity of each original source.
- [x] #3 A source that already has an accepted job retains its original job and stored content. Newly admitted sources run once with their edited metadata.
- [x] #4 Exercise browser recovery and the supported persistence backends with durable-state and failure-injection tests.
<!-- AC:END -->
