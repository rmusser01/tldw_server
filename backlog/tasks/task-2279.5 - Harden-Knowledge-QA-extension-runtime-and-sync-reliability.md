## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Stage 3 hardens Knowledge QA extension recovery states and persistence failure handling. The UI now distinguishes setup, auth, reachability, allowlist, search failure, and search-succeeded-but-sync-failed states, keeps successful answers visible when backend message persistence fails, labels them as unsynced local results, and exposes retry sync without rerunning the RAG query. The retry path now handles persistence failure as a recoverable false return and clears the unsynced trust badge once message/context sync succeeds.

Packaged extension route validation remains release-blocked before `/knowledge` renders: unsandboxed headless Chromium launches but exposes no extension targets to `resolveExtensionId`; headed launch times out locally; sandboxed launch aborts before route code. The expected-failure launch-health probe records this blocker, and the actual Knowledge QA extension specs still fail 6/6 at launch rather than page assertions.
