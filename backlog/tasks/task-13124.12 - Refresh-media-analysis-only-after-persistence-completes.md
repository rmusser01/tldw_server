## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Live real-backend UAT shows a successfully generated analysis as 'Pending save'. AnalysisModal invokes onAnalysisGenerated before its PUT and persistence verification, so ContentViewer refreshes stale media detail and never refreshes again after the save succeeds.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 A successful analysis save refreshes media detail after persistence, not before it.
- [x] #2 The generated analysis is displayed without a stale Pending save badge after the success flow completes.
- [x] #3 Failed persistence does not falsely report the analysis as saved.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Add a failing callback-order regression; move the generated callback to confirmed PUT/version-save success paths; keep failure behavior unchanged; verify focused and live workflows.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Red/green regression: AnalysisModal.stage3.regression.test.tsx proves onAnalysisGenerated remains silent until the PUT persistence promise resolves and is called only on confirmed PUT or version-save success. Focused AnalysisModal suites: 6 passed. Live real-backend workflow passed end-to-end in 1.6 minutes with the Pending save badge cleared before navigation.
<!-- SECTION:NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Moved analysis consumer refresh notification behind confirmed persistence. Failed save paths no longer imply success; successful normal and fallback version saves refresh consumers only after durability is established. Verified by focused tests and the retained live ingestion -> analysis -> review -> re-analysis workflow. No Python touched, so Bandit is not applicable.
