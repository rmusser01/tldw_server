## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H2a + H9a, severity High (security), roadmap phase 0. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

The startup guard core/testing.py:101-120 (called from services/startup_pre_core.py:86) checks only TEST_MODE, TESTING and TLDW_TEST_MODE, returns early whenever PYTEST_CURRENT_TEST is set, and never consults the production detector. PYTEST_CURRENT_TEST alone unlocks seams with no production check: the SSRF private-IP bypass for hostnames (http_client.py:1789-1804), SINGLE_USER_TEST_API_KEY accepted as admin (User_DB_Handling.py:1034-1037; :325 treats an empty value as set), the middleware skip (main.py:2631-2649), audit flush off (unified_audit_service.py:1059-1062), and the AuthNZ JWT fallback: in multi-user mode with no JWT_SECRET_KEY, any non-empty PYTEST_CURRENT_TEST installs the public default "test-secret-jwt-key-please-change-1234567890" (settings.py:73-74, 943-953), making JWTs forgeable. Unguarded knobs: TLDW_ALLOW_TEST_FALLBACK_KEYS (crypto_utils.py:161), SINGLE_USER_TEST_API_KEY, E2E_TEST_BASE_URL (settings.py:973), RG_TEST_FORCE_STUB_RATE / RG_TEST_DISABLE_ACCEPT_WINDOW (governor_redis.py:323,332,474), MINIMAL_TEST_APP. Production detection is copied about 20 times with 8 key sets (testing.py:75 is the broadest; config.py:3455 lacks DEPLOYMENT_ENV and is lru_cached; auth_deps.py:228-230, crypto_utils.py:211-213 and character_rate_limiter.py:418-421 read only ENVIRONMENT/ENV; settings.py:931,1007 and main.py:1732 read only tldw_production), so APP_ENV=production or DEPLOYMENT_ENV=production skips the weak single-user key hard-fail and the JWT template hard-fail. Precedent: TASK-13296 "TEST_MODE fallback leaks every user's webhook URLs and secrets" and TASK-13369 "TEST_MODE env disables webhook SSRF validation on delivery" fixed the same bug class at other sites (both ids are shared with unrelated tasks).

Review and dry run (2026-10-25): Review: main.py:2719 installs security headers in either branch, so the security-headers clause was dropped from the acceptance criteria.
