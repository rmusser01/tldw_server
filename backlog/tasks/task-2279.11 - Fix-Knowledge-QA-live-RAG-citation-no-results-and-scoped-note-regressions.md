## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Post-rebase live testing exposed two remaining regressions after the first remediation commit: selected note evidence was dropped by the WebUI default chunk-type filter because note documents lacked `chunk_type`, and the evidence Details tab hid runtime search details behind a closed nested disclosure. Notes are now materialized as text chunks, and the details panel opens by default with a visible "Web fallback disabled" status. Verification included focused backend/frontend regressions, the six-test live WebUI backend gate, UI package typecheck, `git diff --check`, a Knowledge QA terminology guard, and Bandit output at `/tmp/bandit_knowledge_qa_follow_on_retry_skip_b101.json`.
<!-- SECTION:IMPLEMENTATION_NOTES:END -->

## Final Summary

<!-- SECTION:FINAL_SUMMARY:BEGIN -->
Implemented backend and frontend follow-on remediation for the Knowledge QA live RAG regressions. Backend changes enforce explicit source include scope before fallback retrieval, prevent Media DB fallbacks from broadening notes-only searches, retrieve explicitly selected notes by ID, keep selected notes through the WebUI chunk-type filter, exclude Knowledge QA self-history from chat evidence, skip answer generation when no documents are returned, and classify chunk/source-document citations as structural evidence. Frontend changes render citation markers visibly, auto-open evidence for cited answers even with fewer than three results, fall back to standard RAG search when the streaming endpoint completes with no usable evidence, and keep evidence Details search runtime status visible. The deterministic live WebUI gate now passes all six Knowledge QA checks against the launched backend. The unrelated post-rebase Research Workspace type fixture failure is tracked and fixed separately in TASK-2315.
<!-- SECTION:FINAL_SUMMARY:END -->
