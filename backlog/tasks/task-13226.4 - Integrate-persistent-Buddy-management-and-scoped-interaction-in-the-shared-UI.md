## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Provide a console-centered Buddy and Persona entry point and one persistent Buddy tied to an explicit conversation or workspace, with accessible interaction controls.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Buddy and Persona management is discoverable from the composer and workspace; staged identity is committed only on Apply.
- [x] #2 A selected independent Buddy remains visible across routes, identifies its target, and can be detached without cancelling accepted work.
- [x] #3 Users can read and reply to the explicitly selected authorized conversation in place; workspace mode does not offer microphone input and names queued speech by conversation.
- [x] #4 Static and Dynamic modes honor reduced motion, keyboard repositioning and reset work, and controls fit compact screens.
- [x] #5 Failures, stale targets and access changes retain drafts safely without sending to another target; focused tests and rendered checks verify the paths.
- [x] #6 Attached profiles remain visible outside the first collection page; additional profile, conversation, activity and recent-turn pages are reachable without dropping loaded selections.
- [x] #7 Pointer and keyboard positioning use separate web and sidepanel buckets; initial collection failures expose a retry action.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Follow ADR-005; integrate the independent Buddy API in a shared shell provider and management modal, reuse conversation and workspace services and existing approval authorities, commit transactional drawer identity, then verify route continuity, scope labels, keyboard and motion controls.
<!-- SECTION:PLAN:END -->
