## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Remove the production extension-package condition that causes Chromium persistent-context launch to stall before app execution. Add a deterministic package-health probe and immutable artifact fingerprint for TASK-12098.3, enforce explicit startup-entry budgets, remove duplicate auto-import exports and circular barrel imports, and repair font packaging without substituting a stripped or mocked extension for release evidence.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 A deterministic extension package-health test launches the exact production unpacked artifact and reports actionable sanitized diagnostics when startup fails.
- [ ] #2 The production artifact loads in Chromium without post-build deletion of generated asset classes or replacement of production entrypoints with test doubles.
- [ ] #3 Binary isolation identifies and removes or corrects at the production build source the generated asset condition responsible for the current unpacked-extension launch stall.
- [ ] #4 Duplicate auto-import exports and circular tldw service barrel imports in affected extension bundles are removed.
- [ ] #5 Existing bundled fonts resolve from production assets and invalid JetBrains font declarations are removed while preserving a system monospace fallback.
- [ ] #6 Explicit budgets guard startup-critical background, options, sidepanel, and content-script entrypoints; lazy chunk warnings are only tuned after those budgets are enforced.
- [ ] #7 Package health emits a deterministic full-directory fingerprint that TASK-12098.3 verifies before and after the final browser UAT; TASK-12098.3 owns the round-trip result.
- [ ] #8 Extension compile, production build, focused tests, startup budgets, and package-health probe pass outside the sandbox.
<!-- AC:END -->
