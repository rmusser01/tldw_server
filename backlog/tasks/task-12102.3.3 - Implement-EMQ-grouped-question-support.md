## Acceptance Criteria
<!-- AC:BEGIN -->

- [ ] #4 The WebUI presents a shared option bank once per EMQ group and keeps each stem independently answerable in practice, graded, and review/result states.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Use additive nullable question group fields rather than a new question type or a separate groups endpoint. Each EMQ stem remains a normal independently graded multiple-choice question; the group fields drive shared-bank presentation.

Stage 1 complete: schema v52 adds nullable group_id/group_prompt for SQLite and PostgreSQL; question create/get/list/update plus API/import contracts round-trip the fields. Fresh local verification: 42 unit tests passed. A real PostgreSQL migration integration test was added and skipped locally with Docker disabled; CI is configured to run it against PostgreSQL. Independent spec and code-quality reviews approved the stage.

Stage 2 complete: EMQ is an available multiple-choice profile with shared-bank prompt contracts, strict unambiguous answer normalization, bounded group metadata, whole-group limiting, final fail-closed validation, deterministic minimum-two-stem generation, per-stem provenance, and group persistence forwarding. Fresh local verification: 51 focused generator tests and 24 neighboring endpoint/schema tests passed; independent spec and code-quality reviews approved the stage.
