## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Eliminate caller-supplied credential internals from Prompt Studio optimization persistence and Jobs payloads; create one owner-scoped ProviderCredentialRuntime per durable job and per /test-cases/run request; normalize provider/model selection; require validated provider success and fail closed on credential/capacity failures.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Optimization request, DB, and Jobs payload boundaries reject or scrub api_key, credential fields, app_config, credentials_resolved, and runtime handles recursively.
- [x] #2 Durable optimization workers create one owner-scoped credential runtime, resolve credentials server-side, mark only validated success, and close after owned provider work exits.
- [x] #3 /test-cases/run uses the same request-scoped runtime lifecycle and no longer converts provider/config/capacity failures into an empty successful result.
- [x] #4 Provider/model/parameters are normalized once and used consistently across evaluation, generation, scoring, and refinement.
- [x] #5 Jobs cannot complete successfully without at least one validated provider response; adapter-boundary and concurrent isolation regressions pass.
