## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Eliminate caller-supplied credential internals from Prompt Studio optimization persistence and Jobs payloads; create one owner-scoped ProviderCredentialRuntime per durable job and per /test-cases/run request; normalize provider/model selection; require validated provider success and fail closed on credential/capacity failures.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 Optimization request, DB, and Jobs payload boundaries reject or scrub api_key, credential fields, app_config, credentials_resolved, and runtime handles recursively.
- [ ] #2 Durable optimization workers create one owner-scoped credential runtime, resolve credentials server-side, mark only validated success, and close after owned provider work exits.
- [ ] #3 /test-cases/run uses the same request-scoped runtime lifecycle and no longer converts provider/config/capacity failures into an empty successful result.
- [ ] #4 Provider/model/parameters are normalized once and used consistently across evaluation, generation, scoring, and refinement.
- [ ] #5 Jobs cannot complete successfully without at least one validated provider response; adapter-boundary and concurrent isolation regressions pass.
<!-- AC:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
2026-07-16: Independent production call-graph audit confirmed a Critical durable-boundary issue: free-form optimization model configuration can persist caller-supplied api_key/app_config/credentials_resolved and later bypass ProviderCredentialRuntime. Four adjacent Important gaps cover missing per-job and /test-cases/run runtime lifecycle, inconsistent provider/model propagation, and false-success completion after provider failure. A five-stage TDD plan is linked; production edits have not started.

2026-07-17: Implementation remains in progress and prior completion claims are withdrawn. Fresh authoritative Prompt Studio verification passed 1001 tests with 17 expected skips and two separately documented WebSocket deselections. Independent review nevertheless found unresolved production blockers: broaden recursive secret detection; eliminate silent OpenAI/provider defaults and ignored/conflicting model-config aliases; enforce bounded/rate-limited simple requests; reject unsupported strategies instead of silently billing iterative execution; fix admin cross-owner monitoring; make idempotency atomic before enqueue; bound and make compare semantics retry-safe; complete the server-side WebUI route/response contract; revalidate test-set ownership at worker dispatch; and reconcile Jobs terminal/lease/cancellation state safely across SQLite/PostgreSQL without starving heartbeats. These blockers require TDD regressions and a fresh full validation gate before any merge-ready claim.
