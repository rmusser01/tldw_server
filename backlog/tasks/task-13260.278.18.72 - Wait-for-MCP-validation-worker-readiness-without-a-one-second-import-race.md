## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Old-head hosted POSIX MCP shards and a 3,433-case local suite intermittently fail the SIGTERM-ignoring worker test before cleanup: the spawned child has a PID but takes longer than 500x2ms to import and signal readiness. Use a bounded readiness wait consistent with sibling worker tests, retain kill/reap/semaphore assertions, and ensure teardown on readiness failure.

## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
Old hosted POSIX shards and full local MCP run fail the SIGTERM-ignore close/cancel readiness check: process PID exists, but its spawn imports exceed the 500x2ms poll. Replace only that poll with a five-second Event wait; on timeout cancel/await the task and close the manager before failing with child exit code. Gateway module passes 103/103 with correct subprocess import path, and both close/cancel cases pass when the worker delays readiness 2.25 seconds, zero skips. Two other local exec-worker failures disappear by adding apps/mcp-unified/src to child PYTHONPATH; no product change for those. Ruff clean; Bandit B101 LOW:116 baseline/current. Full MCP and hosted acceptance remain.
