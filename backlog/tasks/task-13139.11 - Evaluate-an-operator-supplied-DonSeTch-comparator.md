## Acceptance Criteria
<!-- AC:BEGIN -->
- [ ] #1 The operator supplies and pins the executable by commit, release artifact, or digest at execution time; the task does not hardcode a stale release or download a binary automatically.
- [ ] #2 A suitability gate checks upstream availability, supported platform, callable MCP contract, fixture compatibility, and documented AGPL operational implications before any run.
- [ ] #3 The comparator runs only in an opt-in local or controlled evaluation environment with bounded time/resources, no production credentials, and no public-network requirement.
- [ ] #4 Results compare quality, output size, latency, and failure classification against the same versioned fixtures without treating the external tool as an oracle.
- [ ] #5 Any tldw_server implementation remains independently designed and copies no DonSeTch source; the project makes no claim that this lightweight evaluation is a formal clean-room process.
- [ ] #6 If no suitable operator-supplied artifact exists, the task closes with a documented no-run decision rather than introducing a download or build pipeline.
<!-- AC:END -->
