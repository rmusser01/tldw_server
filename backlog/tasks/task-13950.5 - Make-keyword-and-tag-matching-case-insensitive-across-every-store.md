## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Parent: TASK-13950 (architecture review 2026-10-25). Finding H5 (keyword identity), severity Medium (bug), roadmap phase 0. Verified on dev dca11342de; roadmap: Docs/superpowers/plans/2026-10-25-architecture-remediation-roadmap.md.

Owner decision 2026-10-25, restated the same day: keywords are case-insensitive, product-wide. Today the stores disagree. SQLite uses COLLATE NOCASE for ChaCha keywords and keyword_collections (ChaChaNotes_DB.py:1806; shared by notes, conversations, collections and flashcards), Media DB Keywords (media_db/media_database_impl.py:629-631) and Prompts keywords (Prompts_DB.py PromptKeywordsTable). On Postgres, COLLATE NOCASE is stripped (media_db/schema/postgres_sqlite_conversion.py:75, backends/query_utils.py:219-220), so those columns become case-sensitive: ChaCha adds a LOWER(keyword) unique index (:12561), but get_keyword_by_text (chacha/keyword_store.py:138 -> _get_generic_item_by_unique_text, "WHERE keyword = ?") still compares case-sensitively. Collections tags (Collections_DB.py collection_tags, plus the Media DB copies in media_db/schema/features/core_media.py and postgres_claims_collection_structures.py) and Watchlists tags (Watchlists_DB.py:774-779, UNIQUE (user_id, name)) are case-sensitive on every backend. Call sites drift too: endpoints/notes.py:1603, :1877, :1973 and notes_schemas.py match case-insensitively; WebClipper/service.py:838-851, endpoints/chat.py:7134 and notes.py:7908 match exact text; MCP notes_module.py:2213 and media_db/runtime/keyword_access_ops.py:17 lowercase on write, losing display casing; chacha/organization_sync_store.py:163 normalize_keyword_identity (a @staticmethod) uses NFC plus casefold. Out of scope: Kanban labels, which have no uniqueness at all today, so deduplicating them is a separate product change. Suggested PR slices: (1) helper plus ChaCha; (2) Media and Prompts keywords; (3) Collections and Watchlists tags with the duplicate-merge migration.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria

- [ ] #1 normalize_keyword_identity (NFC plus casefold) is extracted to a module-level helper and used by every keyword and tag store and call site listed above; a guard fails on new ad hoc keyword or tag normalization
- [ ] #2 ChaCha keywords, Media keywords, Prompts keywords, Collections tags and Watchlists tags each match case-insensitively on SQLite and on Postgres (Postgres uniqueness and lookups use LOWER(...) or citext instead of the stripped NOCASE); parametrized per-store tests prove adding "Foo" then "foo" yields one entry and a lookup in either case finds it

- [ ] #6 Non-ASCII cases where casefold+NFC disagrees with SQLite NOCASE (ASCII-only) or Postgres LOWER (e.g. German sharp s, accented capitals) are tested and either aligned or documented as a known limit
