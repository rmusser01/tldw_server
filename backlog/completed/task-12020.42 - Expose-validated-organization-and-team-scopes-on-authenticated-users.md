## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
Live TASK-12020.39 UAT proved that JWT scope claims and request.state contain validated org/team memberships, but the production User model returned by get_request_user drops those fields. Sharing endpoints read user.org_ids/user.team_ids, so valid organization and team shares are rejected with 403 and shared-with-me lists remain empty. Preserve the already validated scopes on the returned User for JWT and API-key authentication.
<!-- SECTION:DESCRIPTION:END -->

## Acceptance Criteria
<!-- AC:BEGIN -->
- [x] #1 Authenticated JWT users expose the validated org_ids, team_ids, active_org_id, and active_team_id on the returned User model.
- [x] #2 Authenticated API-key users expose the same validated scope fields without expanding their permitted scope.
- [x] #3 Workspace sharing accepts a scope the authenticated user belongs to and continues rejecting scopes outside validated membership.
- [x] #4 Focused AuthNZ and sharing tests cover the returned-user scope contract.
- [x] #5 Live PostgreSQL sharing and recipient shared-with-me UAT pass through the real backend.
<!-- AC:END -->

## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
Add the four validated scope fields to the established User model, populate them after scoped-permission resolution in both JWT and API-key authentication, add red/green assertions to focused membership tests and real AuthNZ happy-path tests, then rerun the live PostgreSQL organization-share and recipient shared-with-me flow.
<!-- SECTION:PLAN:END -->

## Implementation Notes

<!-- SECTION:IMPLEMENTATION_NOTES:BEGIN -->
Added defaulted organization/team scope fields to the compatibility User model and populated them only after apply_scoped_permissions in both JWT and API-key authentication. Added claim-bounded JWT and organization/team-restricted API-key assertions that align request_user, request.state, and AuthPrincipal without widening scope. TDD red reproduced AttributeError for missing User.org_ids. Fresh final verification: 60 selected AuthNZ/sharing tests passed in 418.96s; scoped Ruff, compileall, and git diff --check passed. Bandit reported only three pre-existing LOW/MEDIUM-confidence B106 false positives for literal token_type values (access/api_key), confirmed present at HEAD before this task; no new findings. Independent code review returned no actionable findings. Live PostgreSQL UAT changed the valid organization share from the reproduced 403 to 200, and the recipient shared-with-me and metadata endpoints returned the expected workspace/access envelope.
<!-- SECTION:IMPLEMENTATION_NOTES:END -->

## Final Summary
