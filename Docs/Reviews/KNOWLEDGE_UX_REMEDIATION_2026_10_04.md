## Walkthrough

| User task | Current workflow | What to inspect |
|---|---|---|
| First connection | Knowledge → Setup required / Server settings → configure the server and credentials → finish reachability/browser-access checks. | Available service categories do not prove that your personal library contains searchable items. |
| First source | Knowledge → **Add your first source** → Quick Ingest file/URL → Configure → Review → Start processing → Results → **Ask added items**. | Actual Stored/Searchable/Analysis available/Needs attention state. Unknown search/index totals remain unknown. The continuation’s visible exact source set contains successful canonical IDs. |
| Several new items | Add multiple files or URLs to the same queue; review settings, then process. Inspect each result. Retry eligible unfinished items or reattach a missing file when prompted. | Successful items stay retained. Retry uses only the unfinished subset, preserving settings and durable collection/item identity. Ask added items uses the accumulated successful set. |
| One ingested item | Media → inspect Content and processing/indexing status → **Ask this item** or **Research with this source**. | Extracted text and source identity. Analysis and search preparation are independent of storage. |
| Several ingested items | `/media-multi` → select items → Compare, Focus, or Stack → **Ask selected items** / **Research with selected sources**. | The selected IDs follow the handoff. Other workspace sources remain in the library; the transferred set becomes active for this research question. |
| Power-user corpus | Knowledge → Sources/saved profiles → Specific → **Find documents or notes** → server search/page controls → select → Done. Change Fast/Balanced/Deep when needed. | Recognizable selected titles/IDs persist across pages, filters and presets. Provider/model, category selection and corpus filters remain part of the user’s question. Select visible affects the current visible page. |
| Ask and evaluate | Ask an editable question or choose Compare these papers / Extract claims with evidence / Summarize this interview / Save a sourced brief, edit it, then Ask. Open Evidence and source previews. | Recipes never auto-run. Check excerpts, actual source identity, answer trust and whether evidence is local, web or mixed before treating a generated claim as supported. |
| Save and revise a brief | Knowledge → Export → acknowledge unsupported-draft qualification when required → **Save to Notes** → **Open saved note** → inspect, edit title/body, save and reopen. | The exact canonical note opens. Original Knowledge provenance stays separate from later manual editing; trust qualifications and references remain in the saved content. |
| Continue research | Knowledge → **Continue in Research Workspace** → inspect attached/pending/failed counts and imported Quick Note → retry unfinished imports if needed. | Media attaches directly. Notes/web attach as clearly labeled retrieved-excerpt snapshots, with original references and limitations. Draft, trust, scope and source evidence survive the real server-backed workspace restore. |
| Generate and review analysis | Media → Analyze → Summary / Key claims / Custom analysis → choose a configured model → Generate → inspect the saved-version preview. Advanced exposes raw prompts. | Save prompt defaults changes defaults. Generate persists an analysis version and keeps it inspectable. Edit analysis → Save as New Version preserves earlier versions. Empty multi-review analysis links to generation in Media. |
| Recover a search | No results → **Change included sources** to edit the corpus, or **Search more results** for retrieval depth. Follow item-owner links for indexing problems. | Each action changes the dimension it names. After a transport error, the existing Ask action reruns the retained question against the same corpus. |
| Capture in extension | Configure the same server → capture a page in Clipper → inspect/save the named clip → **Ask captured source**. | Clipper saves a canonical note UUID. Ask opens the full options Knowledge page with that exact note scope. Shared dialogs, vocabulary and evidence workflow apply there too. |

For a first-time user, follow the first-source path and verify readiness before asking. For a power user, establish the intended source set first, then change retrieval depth or choose a recipe; inspect evidence before exporting or continuing research. Source selection, retrieval settings and a saved output are distinct checkpoints.
