**Personas and cognitive walkthrough**

- **First-time self-hosted researcher:** Setup diagnostics help, but a connected empty library appears ready. They must discover ingestion, understand storage versus indexing, and scroll through generic examples before a useful question. Make “add → check ready → ask this item” a visible path. The anticipated frustration is a successful add followed by a search that still excludes the item; this is an evaluator prediction, not a recorded participant emotion.
- **Experienced researcher with a large library:** Presets, profiles, and multi-review help. Silent scope replacement, a first-200 selector, and repeated selection across routes are unacceptable research overhead. Display named active source sets and keep the same set through tuning, review, and synthesis.
- **Keyboard / small-screen reader:** Global controls have names and skip links exist. The two modal focus failures, clipped picker, hidden exact-scope label, and mobile bottom-control overlap make evidence selection and inspection unreliable. Reuse the working Settings focus pattern and verify complete task flows rather than only isolated control semantics.

The essential mental work is choosing evidence, checking claims, and deciding what to save. Avoidable mental work is remembering item identities across pages, translating prompt/route terminology, and recovering a scope that was silently replaced. Keep guidance beside the decision it explains. Reveal uncommon tuning after the primary task rather than adding another first-screen layer; this applies [NN/g progressive disclosure guidance](https://www.nngroup.com/articles/progressive-disclosure/).

**Potential improvements after the repairs**

1. **One source-set handoff reused everywhere.** Ingest results, Multi-Item Review, Knowledge, and Research Workspace should carry the existing canonical IDs and a visible scope summary. Start with the current stores/route payloads; a new workspace abstraction is unnecessary.
2. **A readiness summary for each item.** Show Stored / Searchable / Analysis available / Needs attention and link the remedy. Existing ingestion and Media status surfaces already provide much of the foundation.
3. **Outcome recipes on top of existing functions.** Compare these papers, Extract claims with evidence, Summarize this interview, and Save a sourced brief can set up a question/output template without creating another destination.
4. **A visible output review loop.** Generate → inspect excerpts/trust → save → open the exact saved artifact → revise/version. Preserve origin and the corpus used at every stage.
5. **Consistent extension/full-page vocabulary and handoff.** Use the same names for source selection, capture readiness, and continuation. A captured page should land as a named source, not require the user to rebuild context.

Keep specialized Media, Document Workspace, and Research Studio routes where they serve distinct tasks. ADR-007 already defines the canonical Research Workspace shell; this audit does not recommend merging all tools or adopting a new architecture.

Minor follow-ups: make Evidence drawer semantics/focus explicit; assess suggestion-list active-selection announcements; remove duplicated guide surfaces; make source titles recognizable rather than counts alone; separate original authorship from subsequent editing. Do not describe existing cancel, presets, trust export, or comparison features as missing.
