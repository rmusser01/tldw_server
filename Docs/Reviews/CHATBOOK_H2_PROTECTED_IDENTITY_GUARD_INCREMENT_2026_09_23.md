# H2 protected assistant identity guard increment — 2026-09-23

The generic conversation update path previously allowed a protected native chat's assistant binding to change. This Task 1.2 increment rejects changes to `assistant_kind`, `assistant_id`, `character_id`, and `persona_memory_mode` whenever the conversation carries a native projection, bundle, or creation-operation marker. A second predicate on the final SQL update closes the gap if a concurrent transaction installs protection after the initial read. Ordinary conversation identity updates and protected-chat title edits remain available.

The representative SQLite cases failed before implementation: a protected persona could be rebound through `update_conversation`. After the guard, all four identity fields pass against projection and bundle markers on both SQLite and PostgreSQL (16 cases). The native migration/transaction/lifecycle and ordinary conversation store run passed **98 tests** with four inherited warnings. Ruff (`F` rules on the legacy store and full rules on the changed tests), diff check and Bandit passed; Bandit reported zero findings over 2,000 scanned production lines. Independent scoped review found no P1/P2 issue; it identified the other identity fields as a nonblocking coverage gap, now covered by the expanded test.

This closes one generic mutation path, not native child creation or the full assistant snapshot contract. Workspace admission, physical asset and quota lifecycles, privacy erasure semantics, and native Sync remain separate gates. The draft stacked H2 PR remains unqualified for merge or full Chatbook parity.
