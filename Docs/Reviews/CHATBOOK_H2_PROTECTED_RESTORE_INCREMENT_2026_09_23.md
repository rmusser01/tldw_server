# H2 protected restore increment — 2026-09-23

This follow-on to the workspace deletion barrier protects individual native chat restore. A protected conversation is identified by its required projection, native bundle, or creation-operation binding. Before restoring it, the store checks the current owner and locks the original workspace if workspace-scoped; the workspace must be owned, ordinary, active and admission-open. It then locks and rechecks the conversation, rejecting changed owner, scope, workspace or protected descriptors. A successful restore leaves an already-gone creation operation key gone. Protected global chats need no workspace lock; unprotected ordinary restore retains its existing behavior.

The public restore endpoint had an already-active shortcut that returned before this store check. A first fix called ordinary restore in that branch, but independent review reproduced a P2: deletion between the endpoint read and the call could make it reactivate a Sync-backed local tombstone without checking Sync enrollment. The final endpoint uses `require_already_active=True`, which validates lifecycle under the same locks but rejects a now-deleted row before any update. The reviewer reran the identical real SQLite schedule: HTTP 409, row still deleted at version 2, no local resurrection. The real endpoint race is now a regression test on both SQLite and PostgreSQL.

Test-first evidence: closed-workspace and wrong-owner restore tests failed on SQLite before the guard; the active endpoint shortcut test failed before routing through the guard; the active-only store test failed before the new mode. After the fixes, 40 workspace lifecycle cases passed across SQLite and PostgreSQL, including typed native bundle markers and the endpoint race. The focused native transaction/restore and route run passed 69 cases; the broader route file passed 128 cases with two unrelated tests deselected. Those two `persist_streamed_assistant_message` tests fail identically on unchanged H1 because their call omits a required `request` argument. Ruff, compilation and diff check passed on the touched scope; Bandit found zero issues over 9,842 scanned production lines. The final independent review found no remaining scoped P1/P2.

This increment does not complete Task 1.2 or full Chatbook parity. Final native fork/retention admission still needs the workspace lock through commit. Sync/import/generic updates must not reparent, revive or strip protected rows; bulk/admin deletion and native context writes need the corresponding lifecycle guards. Physical candidate, quota and asset cleanup remain open.
