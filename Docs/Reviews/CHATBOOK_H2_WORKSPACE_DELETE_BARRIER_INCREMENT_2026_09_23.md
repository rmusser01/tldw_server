# H2 workspace deletion barrier increment — 2026-09-23

This increment implements the deletion half of the W1 workspace lifecycle contract in Task 1.2. Soft and hard deletion now commit an owned, ordinary workspace's `native_chat_admission_closed` flag before enumerating conversations. They reject an enclosing repository transaction before mutation, so the closure cannot be accidentally rolled back with caller work. The flag does not advance the public workspace version. A failed cascade leaves the workspace discoverable and closed; a later retry enumerates again using the current public version.

The final short transaction locks the workspace again, validates ownership, closure and (for soft delete) the expected version, then refuses the transition while a protected scoped conversation remains. Soft deletion checks live protected chats; hard deletion includes trash. A failed final check rolls back quiz/deck detachment or membership/root removal and returns the retryable `workspace_delete_incomplete` conflict. It does not acquire an operation lock under the workspace lock. Existing saved-view delete-first race tests now hold their barrier after the final workspace update and before commit, preserving their original serialization assertions.

Test-first evidence: the initial four SQLite tests failed on missing closure/nested rejection, then passed after implementation. Four follow-on SQLite tests failed when they required the retryable conflict type, then passed after the error mapping change. A deterministic second-connection barrier now observes the committed closure before enumeration on both engines. Focused native migration/transaction and saved-view regression: 63 passed, 55 deselected, 4 inherited warnings. Expanded lifecycle suite: 24 passed across SQLite and PostgreSQL, 4 inherited warnings. Ruff on the changed tests and `F` rules on the legacy DB module, compilation, diff check and Bandit passed; Bandit reported zero findings over 42,789 production lines. Independent scoped review found no new P1/P2. The broader saved-view suites previously showed six failures reproduced on unchanged H1 (v53 fixtures and PostgreSQL unique/RLS diagnostics), separate from this increment.

This is not the complete W1/native fork runtime. Final fork and retention admission must still hold the workspace lock through commit in operation → workspace → conversation order and reject closure. Protected restore, generic import/Sync and context writes must also respect closure and immutable scope; bulk/admin deletion and physical asset/charge reclamation remain open Task 1.2/2.3/4.1 work. No WebUI or extension parity is claimed by this storage increment.
