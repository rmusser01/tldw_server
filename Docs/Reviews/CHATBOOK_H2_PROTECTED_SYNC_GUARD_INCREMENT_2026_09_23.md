# H2 protected Sync guard increment — 2026-09-23

This Task 1.2 increment prevents generic Sync v2 projection writes from changing a native-protected conversation. The existing upsert previously replaced owner, version, deleted state, scope and workspace on ID conflict. Its `ON CONFLICT DO UPDATE` now has an atomic predicate on the conflicting row's native projection, bundle and creation-operation columns. A protected conflict affects zero rows and returns `native_conversation_sync_unsupported`; it cannot be revived, reparented or stripped while the actual native Sync protocol is unfinished. The generic Sync tombstone similarly refuses protected rows before changing deleted state or owner, so it cannot bypass receipt-aware deletion. Ordinary Sync projections retain their existing update and tombstone behavior.

The five new SQLite cases failed before implementation: fork-marker and typed-bundle chats, both live and trashed, were overwritten by upsert; a protected tombstone bypassed the native delete adapter. The same five cases pass on SQLite and live PostgreSQL after the guard. The ordinary Sync insert/update/tombstone test passes. The complete native lifecycle/operation/conversation-store run passed **88 tests** across SQLite and PostgreSQL, with four inherited warnings. Ruff (`F` rules on the legacy store and full rules on changed tests), compilation, diff check and Bandit passed; Bandit reported zero findings over 1,979 scanned production lines. Independent scoped review found no P1/P2.

This is a fail-closed boundary until a reviewed native Sync representation and conflict protocol exist. It does not implement native chat synchronization or full Chatbook parity. Final native admission, other import/admin write paths, bulk deletion, and physical asset/quota lifecycle remain open.
