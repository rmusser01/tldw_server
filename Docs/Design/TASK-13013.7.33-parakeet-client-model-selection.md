# Parakeet RNNT client model selection — TASK-13013.7.33

The unified WebSocket config handler currently copies an arbitrary client
`parakeet_rnnt_model_name` into its configuration. A harmless characterization
of the actual handler body confirms that `example.invalid/unapproved-model`
reaches a stubbed model entrypoint after protocol framing validation. The
optional RNNT backend ultimately passes that value to NeMo `from_pretrained`.
This establishes an application trust-boundary defect, not deployed CVE impact:
the retained base images do not contain optional NeMo/Hydra.

Add one inline check immediately after audio protocol validation, before any
client configuration is copied or model initialization begins. An explicit
override must be a string equal to the current server-selected value or one of
the two existing documented repository choices:

- `nvidia/parakeet-tdt-0.6b-v3` (current default)
- `nvidia/parakeet_realtime_eou_120m-v1` (documented streaming option)

Reject other values with the existing `AudioProtocolError` bad_request response
and close code 4400. Omission preserves the server value. Do not normalize paths,
accept namespace prefixes, or extend the approved choices to arbitrary models.
Keep validation even when the client disables RNNT or chooses another provider.

The authenticated endpoint creates the initial config from explicit server
defaults; the legacy wrapper copies an explicit list of legacy fields. Neither
copies a request RNNT model name into that initial value. The post-config
callback handles persistence/metrics and does not overwrite it. Trusted custom
server selections remain supported without granting clients arbitrary overrides.

Tests execute the unchanged first-party handler/config/protocol definitions
with stub lifecycle/model entrypoints, selected using the standard-library AST.
They do not import the heavyweight audio module or any ML package. Regressions
must show zero model entry calls on rejection, clear client error/close behavior,
unchanged config on rejection, and preserved approved/omitted/server choices.
No dependency, policy, model-loading backend, or runtime-gate changes are needed.
