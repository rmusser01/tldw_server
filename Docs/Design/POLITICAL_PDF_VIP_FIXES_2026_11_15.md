# Political PDF research: approved remediation design

Task: TASK-15505 and children .1–.4. Baseline: a1ec6cc5d1. Approval: user requested implementation of the prioritized [UAT findings](../Reviews/LARGE_POLITICAL_PDF_UAT_2026_11_15.md) and an end-to-end rerun with the same PDF and DeepSeek on 2026-11-15.

## Outcome and scope

A nontechnical researcher uploads a large political document, understands its chapters, asks questions with inspectable evidence, compares opposing positions, and exports research that preserves provenance and annotations. Fix the existing Media → Knowledge/Research → Document viewer → Notes/export flow. Preserve WebUI/extension parity, owner isolation and explicit expert settings. No new dashboard, provider abstraction, vector service or political-document-specific parser.

Use the existing components and storage owners. Merely increasing prompt limits would still omit content or exceed context; a separate document-analysis engine would duplicate existing navigation, Jobs and artifacts. The selected approach extends the established mechanisms with exact provenance, bounded generation and visible coverage.

## A. Retained originals and exact locations (TASK-15505.1)

Extract existing original retention into one shared orchestration helper. Call it before Jobs staging cleanup and from the synchronous ingest path. Preserve quota/path validation, checksums, registration rollback and replacement cleanup. Successful persisted results with warnings remain eligible. Propagate `original_file_stored`; failed retention is a visible partial success, never a false guarantee.

Native PDF extraction uses per-page Markdown, normalizes each page, joins deterministically and computes offsets against the final stored string. Optional safe metadata:

```json
{"page_count":2,"page_map_content_hash":"<SHA-256 of exact stored UTF-8 text>","page_map":[{"page_number":1,"start_char":0,"end_char":120,"printed_page_label":"i"},{"page_number":2,"start_char":122,"end_char":450}]}
```

Physical pages are one-based; character ranges are inclusive/exclusive Python string positions. Preserve blank pages. Printed labels require evidence from the PDF, never a guessed constant offset. OCR/alternative parser replacement must rebuild provenance or explicitly omit it. Existing imports without a map require re-extraction for reliable locations.

Intersect persisted chunk ranges with the map. Keep compatibility `page_number` plus complete `page_spans`; retrieval must not prepend titles or strip mapped source text before using offsets. Reuse arbitrary chunk metadata storage; avoid schema migrations where existing metadata suffices.

Move exact navigation resolution to core for use by both the API and output worker. Section content returns `navigation_version`, `resolved_start_char`, `resolved_end_char`, `page_spans`, `coverage_status` (`exact` or `unavailable`). A heading includes child sections until the next same/higher-level heading. Physical bookmark pages and printed TOC pages are distinct; unresolved ranges must not silently become the full source. Validate stale navigation versions before generation. For an unnumbered TOC child contribution under a numbered chapter, resolve its start to a unique exact heading within the mapped page after removing Markdown wrappers and collapsing whitespace; use the same start as the preceding sibling end. Missing or ambiguous child headings are unavailable, never guessed. Parent chapter page ranges and navigation identity stay unchanged; only the response-cache format version advances. Retain shared chapter endnotes in coverage, but instruct extraction and synthesis that reference-list names, titles and URL fragments do not establish the current author’s stance or an opposing author. Reference-only material cannot justify a claim that an argument is absent elsewhere in the selected scope.

## B. Scoped, focused and bounded questions (TASK-15505.2)

Validated selected Media/note IDs disambiguate the default clarification decision. Explicit true/false settings still win. Preserve clarification as a distinct streaming/nonstream/persisted outcome; announce that search did not run.

Natural-language FTS questions use a bounded persisted-chunk term fallback rather than exact-phrase-only matching. Exclude answer-format directives from search terms, and use consistent conservative English inflection roots for candidate prefixes and relevance coverage so ordinary wording changes do not suppress a short relevant passage. Preserve deliberate quoted/Boolean/prefix syntax and existing term, candidate and score bounds. Do not implicitly regenerate all chunks for Media that already has stored chunks. Preserve supported fallback for unprepared Media and explicit late-chunk requests, with bounded work and cooperative cancellation.

For quote-first requests, separate the anchored quotation instruction from its topic and omit trailing citation/source-selection instructions from retrieval terms. Keep ordinary topic words such as “quote” or “printed page” when they are part of the substantive question. Natural fallback considers at most 128 persisted candidates before selecting the requested answer count, so asking for few results does not prematurely discard a substantive passage behind repeated short matches. The original generation question remains intact.

Honor requested parent/neighbor context using the current visible Media version. Verify the retrieved excerpt against its exact canonical offsets before expansion, preserve the matched chunk identity/rank, and extend the same excerpt by at most `parent_context_size` characters on each side within valid section bounds. Include only verified neighboring chunk ranges; do not append separately ranked neighbors that `top_k` can discard. Recompute exact offsets and physical page spans from the content-hash-validated page map, retaining original matched offsets separately. Hidden parents are excluded; stale excerpts stay unexpanded without stale page claims. Run expansion before injection, policy and security filtering under the request deadline, with cooperative cancellation between database reads. A parent-read failure must not return evidence that skipped those filters.

Propagate only the matching, validated server AuthNZ scope's admin claim into the existing security access controller. Preserve the requested sensitivity ceiling, explicit document ACLs and repository visibility; missing, malformed or mismatched authority retains guest behavior. Client role metadata cannot grant authority. This corrects lost trusted authority: public policy prose containing “account” is classified INTERNAL by the existing heuristic and otherwise wrongly excluded for an authenticated admin. This authority bridge leaves classification rules unchanged.

Sensitivity category keywords match bounded words and common inflections, so unrelated derivatives such as “accountable” and “accountability” do not trigger financial “account”. Preserve explicit confidential/restricted markers, multi-category thresholds, authority and the requested sensitivity ceiling. Verify retained evidence through the public endpoint pipeline and reclassify cached retrieval seeds before returning them.

Before expanding a cached excerpt, recheck the parent's current personal/team/org visibility through the DB read contract. Reuse the existing SQLite search predicate and PostgreSQL RLS; deny absent authority on this scoped read, and require custom readers to implement the scoped contract explicitly. Revoked access excludes the seed before reading any version or neighbors. Existing unscoped lookup callers retain their behavior.

Use one request deadline across retrieval/expansion, pass remaining budgets to stages and stop optional work after expiry. Forward server timeout settings instead of relying only on streaming idle timeout. Blocking work must yield/offload safely; thread offloading alone is not proof of cancellable computation.

Carry the original retrieval question separately from full-source prompt context. Keep context bounded and visibly explain when focused evidence replaces an oversized full-text request. Do not discard the actual question or silently present an opening prefix as a complete document.

## C. Complete section summaries and comparisons (TASK-15505.3)

Extend existing Research Workspace output Jobs for `summary` and `compare_sources`; do not create a browser-owned queue. Typed section selection references `{source_id,node_id,navigation_version}`. Resolve ownership and exact ranges server-side. The existing outline proposes sections; the user can review/select chapter starts. Do not assume 95 derived nodes equal 30 chapters or hardcode this book.

Read complete selected ranges and partition into bounded batches without gaps. Each batch is partitioned into contiguous source passages of at most 1,000 characters, preferring sentence/paragraph boundaries. Send deterministic passage IDs to the model; evidence selects existing IDs rather than retyping quotations. The server copies each selected original passage and its exact character/page range into the evidence artifact. Reject unknown IDs and retain completed compatible checkpoints. Summarize batches, synthesize each section, then synthesize completed sections. Intermediate hierarchy reductions use a separate compression prompt containing only the current group, excluding final report instructions, global coverage counts, and final length preferences. They have a strict 250-word system instruction and a 2,048-token ceiling (or the lower explicit user limit), while extraction and final synthesis retain the user output budget. Every input enters the hierarchy; nothing is clipped. Reject truncated or non-shrinking reductions and bound reduction depth to eight rounds. Validate every evidence ID token, including grouped citations. The final overview receives authoritative completed/failed/unread section and portion counts; intermediate excerpt limitations cannot override them. Reductions prioritize concrete policy positions and disagreements, and the final overview explains each opposing stance, using a 600–1,200-word large-scope default unless the user requests another length. Explicit completed-card replacement reuses canonical source settings and checkpoints to regenerate the overview; reconnecting to any terminal job adopts its saved completed or failed checkpoint without submitting another job. Only explicit Retry or completed-card replacement can request more provider work. Creating a new version revalidates the canonical target under the current account and workspace while retaining the current generation selection and settings. Changed checkpoint boundaries produce a typed terminal failure with preserved evidence and an actionable request to create a new version; they never reset saved evidence silently. Research output failures use WorkerSDK’s generic typed-exception path; optional retry backoff is omitted when unset. Cancellation finalizes through the existing JobManager UUID/worker/lease check after persisting the cancelled checkpoint, avoiding the Slides-specific terminal-outcome contract. Display synthesis stage/group and incomplete section counts separately from extraction coverage; long-document UI avoids per-file timing estimates. Preserve opposing authors/positions and supporting page evidence. Missing or failed material stays visible and cannot count as covered. Persist per-section/batch checkpoints in canonical artifact `version_metadata.workspaceClient.data.sectionAnalysis`. Job retry/resume skips completed compatible work; stale source/navigation invalidates reuse. Cancellation and reopening retain the job/artifact identity.

Reuse Media navigation controls in Studio, with named section selection, page ranges, completed/failed/unread counts, retry/cancel and source links. Both comparison gates accept two sections from one source. Use a 4,096-token ordinary unset output default and an 8,192-token DeepSeek unset default, preserving explicit settings. For supported DeepSeek Flash/V4 section extraction and synthesis only, disable thinking through the existing adapter so the bounded allowance is available for the final artifact; preserve normal-chat defaults and explicit controls outside this path. Extraction requests JSON mode. Detect provider truncation at every stage and stop after two consecutive identical failures with actionable partial/unread coverage. Remove separate low implicit caps that prevent a final answer. Source text, model output and evidence remain separate untrusted inputs. Passage selection proves exact source provenance; it does not independently establish semantic claim correctness, which remains reviewable against the quoted passage.

Render coverage, citations and limitations into the artifact's Markdown as well as structured metadata so individual text exports remain honest. Existing output jobs, workspace ownership, canonical artifacts and codecs remain authoritative.

## D. Evidence review, export and UX (TASK-15505.4)

Route citation clicks to the existing authenticated Document Workspace at a validated physical page, preserving selected source and same-document navigation. Clearly label PDF versus printed pages. Keep unsupported/unavailable evidence qualified rather than showing a positive citation claim. Preserve page/citation fields through Research → Notes projection and restoration.

Keep source annotations browser-local as today, but include a validated optional `sourceAnnotations` payload in workspace bundles and restore it under the imported workspace identity. Reject malformed or unrelated source references. Old bundles remain importable. Explain the local/live versus exported snapshot contract in the UI. Verify individual summary/brief export as well as workspace ZIP roundtrip.

Track UX issues using NN/g's ten usability heuristics and 0–4 severity, considering frequency, impact and persistence. The ledger records scenario, heuristic, severity rationale, observed evidence, fix owner, tests and live retest disposition. This is a heuristic evaluation and agent walkthrough, not a participant study or NN/g certification. Consult [NN/g heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/) and [severity guidance](https://www.nngroup.com/articles/how-to-rate-the-severity-of-usability-problems/). Preserve the incumbent visual system; focus on state, familiar language, recovery, recognition and evidence.

### Completed section-output reader (UX-PDF-34)

For schema-version-1 `sectionAnalysis` outputs, the existing Studio View modal opens a readable overview and a chapter/section selector. Render only the selected overview or section summary with the existing safe Markdown preview. Show completion coverage and incomplete/error states explicitly. Evidence for the selected section is mounted only when its disclosure is opened, retaining exact quotes, claims, qualifications and validated physical/printed page links through the existing authenticated Document Workspace route. Technical artifact lineage stays behind a separate disclosure. Ordinary artifacts keep their existing viewer. This is a presentation-only projection: full content, structured metadata, persistence and exports remain unchanged. Tests cover all section titles, bounded initial rendering, section switching, evidence/provenance preservation, malformed metadata and legacy fallthrough. Existing artifact/storage ownership remains under ADR-007; no new ADR or dependency is needed.

Failed section outputs with retained content also expose View, so a final-overview failure cannot hide completed chapters behind a paid retry. In-flight outputs retain their existing controls. A retained synthesis accompanied by a synthesis error is explicitly labeled as an overview from an earlier attempt. Page links use the validated Document Workspace route through the incumbent WebUI or extension router.

## Verification contract

Regression tests cover real retention after cleanup; page-map normalization/Unicode/blanks/cross-page chunks; exact parent section bounds; scoped/unscoped and explicit clarification controls; persisted natural-language retrieval and explicit search syntax; deadline/cancellation; original question preservation; complete range partitioning; resume without duplicated successful calls; owner/stale-version rejection; page links and Notes; export/import annotations and coverage. Run scoped linters, type checks and Bandit before completion.

Rerun the actual 922-page source in fresh disposable state with DeepSeek Flash. Verify original retrieval, all 30 reviewed chapter ranges, chapter summaries and a whole-document synthesis, scoped Education/FBI/Fed/late-FTC questions, opposing Ex-Im/trade positions, enactment uncertainty, page-opening actions, artifact save/reopen, text export and workspace export/import. Verify gold evidence directly from the PDF. Measure retrieval and generation separately with no overlapping heavy probes. Failures remain open until corrected or reported concretely; no mock-provider result substitutes for this acceptance run.

## Final disposition

The final retest report separates passing processing and provenance from remaining model attribution errors; those raw outputs and the targeted reviewed overview are preserved. UX-PDF-01 through UX-PDF-43 carry NN/g heuristic, severity, evidence and disposition.

Actual worker and StrictMode import failures found during acceptance were repaired using existing owners: generic Jobs failure/cancellation and the existing chat history projection. ADR assessment remains no new ADR required; ADR-003/007/065 and existing AuthNZ authority decisions govern these corrections. No new subsystem or security policy was introduced.
