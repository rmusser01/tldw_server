# Quick Ingest after the first screen

The WebUI can successfully extract a transcript without giving the person a way to read it. It can also announce that work was cancelled while the server still has the job. These are the first two changes to make. Keep the one-screen draft, its counted action and the retry behavior that protects earlier successes.

[Five-page visual review with observed screens and proposed desktop and phone layouts](assets/quick-ingest/modal-states-review.pdf) · [One-screen implementation and screenshots, PR #3631](https://github.com/rmusser01/tldw_server/pull/3631)

## What was reviewed

Two independent assessments examined the WebUI reached through **Media → Add media** on the one-screen implementation (bcec6d2f40). One evaluated the interactions against Nielsen’s ten heuristics. The other ran the Impeccable detector and exercised the real interface with controlled API responses. Additional paired walkthroughs measured batch editing, overwrite settings and Back navigation. Browser sizes included 1280 × 800 and 1340 × 900 on desktop, 390 × 844 on phone and a 320 × 700 check of the three-action confirmation. The severity and scores below are design judgments. The sessions did not measure task success with participants, physical devices, screen readers or live workers. [Nielsen Norman Group heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/)

**Browser** below means someone exercised the rendered WebUI. **Source** means the named branch or test was inspected. For combined rows the evidence column identifies what was exercised. The modal's entry, exits and minimized state count as part of the experience. The browser extension’s separate wizard and the contents of downstream workspaces have their own flows.

## Findings in order of impact

| Priority | Reproduced behavior | Proposed interaction |
|---|---|---|
| P0 · Reading an extraction | A successful extract-only response included transcript text. The receipt reported “1 extracted”. More actions contained Add more sources, and the footer offered Done. | Give a single readable extraction **View extracted text**, and give each readable member of a batch **View text**. Provide Copy text and a return path to the receipt. Describe empty or unavailable output explicitly. Scope the proposal to text available in the active run. |
| P1 · Repairing a source | A well-formed URL rejected with HTTP 422 prompted “Check the file format” and **Correct settings**. Adding a replacement put it outside the retry run. Removing the original left zero runnable sources. After draft reload, both a local file and a pasted passage requested reattachment. Neither draft row offered a picker. | Give the failed entry **Edit link**, **Choose file**, or **Paste again** according to the input. Keep the entry’s batch identity, selection, metadata and retry scope. A changed configuration gets **Edit settings** only when it can resolve that error. |
| P1 · Knowing whether work stopped | After a fixture rejected bulk cancellation with HTTP 503, the receipt said “1 cancelled”. With one failed source and one running at 40%, the minimized widget said “Failed”, then disappeared after ten seconds. An inaccessible tracked job ended with a warning to check Media, no affected name, and Done. | Keep active and failed counts visible together. Mark a submitted stop request as pending. Report cancellation only after acknowledgement or a terminal job status. For an unresolved job keep its source name, last status, **Check status** and **Check Media**. Keep already saved items reachable. |
| P1 · Making a consequential choice on a phone | In the 320-pixel close confirmation, the focused Stay button occupied x = −116 to −56. At 390 pixels only its rightmost 14 pixels were in the viewport. The sampled dark-mode title contrast was approximately 1.38:1. In playlist replacement review, one at-risk URL was listed while the action confirmed two sources without explaining the difference. | Reflow the close choices vertically. **Continue in background**, **Stay here**, and **Stop remaining source…** describe three distinct outcomes. Confirm stopping the remaining work. In overwrite review show the item title and URL, how many matches may change, how many other sources will run and the counted final action. |
| P1 · Retaining work while editing | Clear all immediately emptied a queue containing pasted material. On both desktop and phone, returning from replacement review erased an unqueued passage. | Offer **Undo** after Clear all and retain the in-memory inputs during its window. Preserve the selected input, unsent text, queue, scroll and focus across confirmation and Back. |

Severity applies to each affected task. P0 blocks its stated outcome. P1 represents substantial loss, confusion or difficulty. Most straightforward saves still completed.

## State inventory

| Surface and states | Evidence | Finding and disposition |
|---|---|---|
| Entry from Media, empty draft, Files, Links, Text, populated and mixed queues | Browser for each input and unsupported extension. Source for first-source focused entry, size limit and FFmpeg warning. | Keep the three named inputs, file limits, per-row eligibility and counted footer. Present the remedy beside its source when every row is excluded. |
| Duplicate or invalid link, re-include, edit, clear, excluded from current retry | Browser for mixed queue, inline edit, Clear all and retry exclusion. Source for duplicate policy mapping. | Keep ready-only submission and distinguish a repeated input in this run from a match already in Media. Return focus to the edited row and support batch undo. |
| Offline, connection check/retry, missing server capability | Source for offline/checking banner, disabled submit, FFmpeg warning and capability-gated controls. | Keep editing available offline. Put the controlling blocker and **Retry connection** within reach of the disabled primary action. Explain a media-specific dependency on affected sources. |
| Settings collapsed/expanded, presets, destination, missing provider, custom provider, skip analysis | Browser for chooser, keyboard jump, skip, presets and all three destinations. Source for provider list and arbitrary values. | At first use, show **Choose provider** and **Skip analysis for this import** together. The provider placeholder on dark UI computed to black at 25% opacity. Restore focus after skipping. Tell people when a preset also changes where their content goes. |
| Advanced settings and media-specific fields | Browser for advanced disclosure, audio/video fields and changing destination. Source for chunking modes, document OCR, transcription, custom language and field visibility. | Keep type-specific options behind disclosure. On both viewport sizes an enabled, checked **Overwrite existing** switch remained visible in extract-only mode. Hide inapplicable storage controls for that run. |
| Playlist detection, preview loading/error/retry/success, selection, duplicate policies | Browser for preview error, recovery, selection, overwrite and add. Source for loading and all four policy branches. | Use a single add action for a previewed playlist and describe how duplicates will be treated. Keep a retryable preview error next to Preview. Correct singular “1 duplicates”. |
| Conference batch and per-source metadata | Browser on both sizes with title, speaker and two video links. | At 390 pixels the 356-pixel metadata region had 601 pixels of content. Track began at x = 390 and Tags at x = 498. Keep the desktop grid where it fits. On phones show editable source cards with vertical labels, inclusion and return focus. |
| Overwrite review by batch setting or per-item playlist policy, confirm, Back | Browser for global and playlist overwrite, heading focus, count mismatch and unsent text loss on Back. | Identify known matches separately from potential matches. Show title and URL together. Keep all entered values and restore focus to the trigger when returning. |
| Start, queued, running, reported progress, partial failure in flight, stalled or unavailable status | Browser for upload/job tracking, sourced 40% progress, mixed running and failed states. Source for the five-minute wait message and latest-known status. | Lead with counts and the active source. Show elapsed time and last known status once. Keep technical job details available on demand. Never infer completion from elapsed time. |
| Minimize, floating widget, resume, close/Escape and stop | Browser for mixed active state, disappearing widget, resume via Media, close confirmation, failed per-item cancellation, bulk rejection and cancelled receipt. Source for pre-acknowledgement races. | Keep a running widget visible while any item is active. Preserve Stay and a visible keyboard focus at 320 pixels. A failed single-item cancellation already leaves its action available. Bring that feedback to the bulk path. A deliberate cancel should offer a new attempt when safe. |
| Receipt for one/many saves, skipped inputs, partial success, transient retry | Browser for mixed success/failure/skips, scoped retry, individual and grouped actions. Source for saved-ID and already-in-Media paths. | Keep access to saved items and retry only the failures. Put actionable failures ahead of passive exclusions. Identify the reason when the same URL has both a saved and skipped entry. Keep long names inspectable and make the phone row actions as easy to hit as the footer. |
| Permanent failure, rejected source, reattach at results, all failed, no confirmed results | Browser for correction dead end, empty interrupted receipt and single failing item. Source for original-file matching, handoff after all failures and unreported input fallback. | Distinguish a rejected input, a request that failed to submit, and a job with unknown outcome. Retain source and last known job status. Validate a reattached file in place and preserve prior successes. |
| Extract-only results, draft creation pending/confirmed/failed/empty | Browser for extract with text, confirmed drafts and browser quota failure. Source for pending write and zero confirmed drafts. | Expose returned text. While creating drafts, show the pending state. On quota failure explain the local write once, offer **Retry creating drafts**, and keep the available extraction readable. Offer **Open drafts** only after a confirmed draft exists. |
| More actions and handoffs | Browser for disclosure, Add more sources, Open drafts availability and retry-success review actions. Source for batch review selection, Media, Knowledge, document workspace, collection scope, export fallback and handoff errors. | Keep one primary action matched to the outcome. Past imports, existing collection items and newly saved items have distinct scopes. Name the target, retain the receipt if a handoff fails, and offer an alternative when a requested action cannot run. |

Default disclosure already keeps advanced choices out of the initial task. Apply the same pattern to tracking details and passive exclusions. Keep choices needed to recover or prevent loss visible at the point of action. [NN/g on progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)

## Heuristic scorecard

| Nielsen heuristic | Score / 4 | Deciding observation |
|---|---:|---|
| Visibility of system status | 2 | Counts are useful, but bulk cancellation and background status can assert the wrong final state. |
| Match with the real world | 2 | Files, Links and Text are familiar. After refresh a paste becomes a file the person never had. |
| User control and freedom | 2 | Resume and scoped retry work. Clear all and Back can discard work. |
| Consistency and standards | 2 | A result row can offer file reattachment while a draft row merely instructs the user to do it. |
| Error prevention | 2 | Replacements require review. The review omits the unaffected count, and the phone confirmation clips the safest choice. |
| Recognition rather than recall | 2 | Source identity is visible initially. Bare URLs in replacement review discard useful titles. |
| Flexibility and efficiency | 3 | Batch input and failure-only retry save effort. Source replacement breaks that fast path. |
| Aesthetic and minimalist design | 3 | The draft and receipt have a clear action. Processing repeats related status above and below the source list. |
| Help users recognize, diagnose and recover from errors | 1 | A URL correction, a restored file and an interrupted job can each lead to an unavailable remedy. |
| Help and documentation | 2 | File limits and draft hints help. A format error advises checking a file even for a URL. |
| **Total** | **21 / 40** | First full-modal baseline. |

A first-time researcher can choose a source immediately, then run into a provider prerequisite before saving it. A returning batch importer can retry failures efficiently but can lose sight of remaining work after minimizing. A keyboard user reaches the provider and replacement heading, then lands on the document body after skipping analysis, repairing a link or returning from review. The next Tab reached Save, Clear all or Review replacements respectively. Two different source URLs rendered the same visible prefix on phone. An Open in Media row action measured 109 × 20 pixels beside 44-pixel-high footer actions.

The CLI design detector returned zero findings in both source scans. The browser overlay identified two local findings in the empty draft, three during processing, two on the mixed phone receipt and three on the mixed desktop receipt. Confirmations and the recovered receipt had none. Several nested-card flags identified legitimate source grouping. The 10-pixel error badge, long line and cramped spacing warrant attention, but the detector missed the clipped Stay button and the false cancellation receipt. The illustrations use clean screenshots. ## Acceptance walkthrough for the next change

1. Extract one link, then a batch with one empty result. Read and copy each returned text exactly. Closing the preview returns focus to its source. The extract-only path creates no Media item.
2. Reject a syntactically valid URL while another source succeeds. Edit the failing URL and retry just that entry. Verify the request uses the corrected URL and the other Media item appears once.
3. Refresh a draft containing a file and pasted text. Choose the original file and paste replacement text in their own rows. Verify both become ready, and a mismatched file leaves a usable correction beside its row.
4. Minimize a run with one failed source and one running. Wait longer than ten seconds, resume, then reject bulk cancellation. Verify the active source remains traceable, and the UI counts a cancellation only when the server confirms it. Simulate an inaccessible job and verify the UI names it and offers a status or Media check.
5. At 320, 390 and 1280 pixels exercise Escape, Stay, Continue in background and Stop remaining. Verify every control fits, is reachable by keyboard, and receives and restores visible focus. Verify per-row result and disclosure controls are comfortable to tap.
6. Choose two playlist sources with one existing match. Edit title, speaker, track and tags on a phone. Confirm the review identifies one potential replacement and two submissions. Go Back with unsent text, then clear and undo. Check source order, editor values and selected mode.
7. Run draft creation through pending, success, quota failure and no-draft results. Report counts only for confirmed writes. Recover from storage failure without reprocessing the source. Check single, mixed and all-failed receipts with long titles.

**ADR assessment.** This review proposes changes within existing WebUI source, session, job and results contracts. It introduces no new storage or API policy. Any later proposal to persist extract-only text across sessions warrants a separate retention decision. [ADR guide](../ADR/README.md)
