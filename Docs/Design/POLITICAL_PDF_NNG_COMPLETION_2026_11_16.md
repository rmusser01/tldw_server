# Political PDF: remaining NN/g interface work

User-authorized scope: UX-PDF-69–72 from the [Luna retest](../Reviews/POLITICAL_PDF_LUNA_GROUNDING_RETEST_2026_11_15.md), PR #3480. Tracking: TASK-15505.13, TASK-15505.14 and TASK-15505.15. This completes four bounded improvements to existing screens. It does not resolve the semantic-accuracy finding UX-PDF-66 or replace human/VIP acceptance.

## Design and ownership

The audience is a nontechnical researcher reading a large political document. Preserve the existing Research Workspace, document reader, styles, tokens and responsive controls; add no dependency, new service or parallel store. Existing saved artifacts, reviews and original source files remain unchanged.

1. **Recognize outputs (69; TASK-15505.13).** Cards and the section reader show the saved model/provider, creation time and selected-section scope. Read Jobs settings from their recorded producer metadata, and imported history only from known import wrappers. Label imports. Missing metadata stays explicitly unknown; never substitute the currently selected model or the current clock. Show a bounded preview of saved section titles with the exact known count. Keep technical provenance available separately.
2. **Understand the wait (70; TASK-15505.13).** Creation and running views disclose the observed 52–62 minute example for this 922-page, 30-chapter document, qualified by model/settings/source variation. Explain saved progress and reading completed chapters. Do not manufacture an ETA, token usage or cost; existing truthful unavailable states remain.
3. **Read while generation continues (71; TASK-15505.14).** A generating section output with a completed chapter exposes a read-only reader. Resolve the current artifact from the existing workspace store/canonical polling, preserving chapter selection as saved checkpoints arrive. Distinguish pending, processing, retained and completed sections/overview. Generation disables review writes both in the viewer and at the save boundary; preserve account/workspace/editor/version guards. A terminal update re-enables the normal review path. No extra polling or generation request is introduced. Deletion and workspace/account changes invalidate the view.
4. **Navigate PDFs without bookmarks (72; TASK-15505.15).** Embedded PDF bookmarks win. If absent, request the document's existing Media navigation with generation disabled and label it “Generated navigation.” Reuse the tree controls and reject malformed, duplicate, cyclic or orphaned hierarchy. Generated TOC targets can be printed page numbers: on selection, resolve that exact node through the existing navigation-content endpoint and accept only matching media/node/navigation-version, exact coverage and a valid physical page span within the owned PDF page count. Do not use a generated target directly as a physical page. Show resolving/unavailable feedback without jumping when ambiguous. Use the existing verified document-operation lease and query scope; permit only exact owned GET routes for outline, navigation and selected-node content, preserving transport isolation/abort handling. Never infer a printed-page offset or eagerly fetch the whole book.

Callers and connected surfaces: Studio cards/create flow/section modal, section reader and review-save boundary; PDF outline hook, Contents tree and document transport route tests; English shared locale keys; existing Stage1, reader, review, navigation, hook and scope tests. Shared UI changes apply to web and extension consumers; no API/schema/export format change is required. Imported metadata is display-only and does not regain active Job authority.

## Verification and limits

Use red/green focused regressions for new logic, connected suites, type checks, scoped lint and independent review. Inspect the same saved Luna output and original PDF at desktop/mobile widths with keyboard navigation. Exercise running checkpoints through a controlled isolated browser fixture, not by mutating the accepted Job 46 evidence or buying another hour-long generation run. Record fixture proof separately from prior live provider evidence. Run the Impeccable detector once after integration and retain findings/evidence in the NN/g ledger.

The preserved raw Luna analysis still contains one Financial chapter endnote-attribution error and incomplete citation support. A valid evidence ID or exact excerpt does not establish that the nearby claim follows from it. Review overlays remain separate, and human labels remain unset. No full accessibility certification, physical-device study or VIP signoff is implied.
