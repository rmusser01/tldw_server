# Email sensitive logging guardrails (TASK-13376.2)

EMAIL-M0-006 requires information-and-higher upload, parsing, persistence and search logs to exclude email bodies, sensitive headers, credentials and serialized metadata. Uploaded filenames, archive member names, titles, keyword sets, URLs, and exception strings can contain those values. A traceback can expose them through exception text and diagnostic locals even when the event message is static.

Use static operation/outcome messages, numeric counts, internal numeric identifiers, and a bounded exception class name. Do not log user-controlled filenames, paths, titles, metadata, query text, validation issue text or exception messages in these paths. Use the existing Loguru logger without per-request global filters or changes to error response contracts. Shared upload validation uses the same safe summaries for all formats because email ZIPs and nested attachments traverse generic helpers.

Regression tests add a real INFO Loguru sink with diagnostic tracebacks and structured extras included. Synthetic sentinels cover body, header, credential and metadata values, including exceptions that echo every sentinel. The harness exercises real upload validation/parser/SQLite persistence/search with model and outbound work forbidden; specific failure injection occurs at the dependency that raises. Success and failure outcomes and exception classes must still be observable. Actual Uvicorn standard-library records are passed through the application's interceptor to verify query redaction for email routes and media search, including URI-encoded values; routing and status remain visible, and unrelated access logs retain their queries. DEBUG logs and external provider/client network logging are outside this gate.

Ownership: logging worker owns upload helpers, safety helper, email endpoint, access-log redaction, native database failure boundaries and logging tests. Attachment worker owns parser/process-emails and descendant persistence loops. Parent integrates repository and document-like persistence logging; logging worker also owns outer multipart orchestration and reached metadata-contract/collections/embedding helpers using localized patches. No Gmail or model calls, no commits from workers.
