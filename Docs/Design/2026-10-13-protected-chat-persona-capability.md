# Protected chat persona choices — TASK-13667

The requester chose to make unsupported tracked-persona chat unavailable with guidance. Protected H1 dispatch and complete-v2 already reject this mode; a picker must explain this before selection or setup application. A fresh or local view with an H1 controller has the same restriction as a native saved view.

Use a shared predicate for protected history plus persona identity plus tracked selection. Offer an explicit public persona-overlay action in the live ordinary-chat picker; hide it for staged identity and already tracked conversations. Never select an overlay automatically. Keep persona prompt overlays, tracked characters and existing non-H1 behavior available. Never change a stored persona bundle into an overlay implicitly, discard its content, or bypass the server refusal.

Enforce before both live and staged AssistantSelect callbacks. Render disabled persona choices with visible, localized guidance. External events must publish the requested mode reactively so overlay requests work even while the same picker is open; the click guard must read the latest intent. New external intents retire old pending selections synchronously; preference changes retire them during layout commit. An old character acknowledgement must not close or publish into the newer overlay picker.

Apply the same guidance to the compact tracked-persona launch, saved setups and startup previews. Central setup application rejects unsupported identity before changing model, prompt, RAG, identity, draft or conversation ownership. Stored setups remain readable and removable. Loaded tracked-persona histories remain readable, with visible guidance and unavailable Send/Enter/queued dispatch before preparation. Use the sender’s actual effective state so restored preferences and loaded metadata agree with readiness; keep the runtime protocol refusal. Refuse compact regeneration before Scene, model, activity or native dispatch; disable its visible action and keyboard shortcut while keeping Copy, Edit and supported-character regeneration. Preserve legacy non-H1 and explicit persona overlay controls.

ADR assessment: no new ADR. This aligns existing controlled choices with the current protected history capability; it adds no persona protocol, storage authority, or persistence rule. [ADR-049](../ADR/049-chat-history-selection-ownership.md) governs H1 ownership. No new native persona authority is introduced.
