## Scope And Decision

PR #2963 delivered effective-default hardening, explicit Workspace None and local server-owned startup provenance. It did not deliver strict versioned startup, durable retry receipts or current Persona send admission. Implement those together as Stage 2C. Stage 2D remains the separate verification/parity gate; tool policy, provisioning and Research UI adoption stay outside this slice.

Reuse the existing resolver and `add_conversation(..., conn=...)`. Add one operation-specific DB store and a closed request model, not another creation SQL path, generic idempotency framework or native-fork operation kind. The native fork store retains canonical requests, leases and projection requirements that are inappropriate for the smaller privacy-bounded startup receipt.

## Closed Transport

`POST /api/v1/chats/workspace-startup` requires authenticated Workspace scope, `workspace_id`, `workspace_assistant_selection` (`inherit` or `none`) and `Idempotency-Key`. Only `title`, `state`, `topic_label`, `cluster_id`, `source`, `external_ref` metadata are accepted.

`inherit` requires a positive strict integer `workspace_assistant_default_version` representing the whole Workspace version. `none` rejects the version even when null, records explicit None and never queries Persona availability. Supplied identity, memory-mode, parent/fork, Character, provider/model/sampling fields are invalid even if null or default-valued. Reject all query options, including greeting flags. Reject duplicate idempotency headers; the one accepted key is 1-128 ASCII characters matching `[A-Za-z0-9][A-Za-z0-9._:-]*`.

The strict route alone adds these text limits; do not retroactively constrain legacy create/update requests. Validate raw decoded strings before trimming/normalizing: reject U+0000, unpaired UTF-16 surrogates and invalid UTF-8 with 422, without echoing rejected text. Keep valid non-ASCII text unchanged, apart from the existing Workspace-id trim and state normalization. UTF-8 byte ceilings are:

| Field | Maximum Bytes |
| --- | --- |
| `workspace_id` | 256 |
| `title`, `external_ref` | 4096 each |
| `topic_label` | 1024 |
| `cluster_id`, `source` | 256 each |
| `state` | 16 |

The combined supplied strings, before normalization, are limited to 8192 UTF-8 bytes, with null/omitted values contributing zero. Reject over-limit strings before UTF-8 encoding when their character count already exceeds the field's byte ceiling. A route-local streaming body guard enforces 65536 raw bytes before JSON/model parsing, including escaped JSON, unknown fields and chunked bodies; oversize is 413, not a database failure. Content-Length alone is insufficient. This is not a new global request-size policy. Field/aggregate failures are 422 with zero DB/provider effects, and the validated request hash cannot allocate an unbounded metadata serialization. The strict route sanitizes RequestValidationError to at most 32 details with fixed message/type and only allowlisted static field/location names; unknown names are omitted with body as the fallback location. Do not copy Pydantic msg or arbitrary loc segments: existing state errors embed input and unknown keys can contain invalid Unicode. Omit input/context/body, never log raw request/errors, and leave legacy validation responses unchanged.

First acceptance is 201; matching accepted replay is 200 with `Idempotency-Replayed: true`. Missing/inaccessible Workspace is 404. New strict startup on an archived Workspace is 409 `workspace_archived`; closing/system-operation Workspaces are 409 `workspace_chat_admission_closed`. Legacy archive/create semantics are unchanged. Clients must never downgrade a rejected, timed-out or missing strict route to legacy creation.

Existing bounded error codes remain: `workspace_assistant_version_conflict`, `workspace_assistant_unavailable`, `persona_feature_disabled`, `idempotency_key_conflict`, `workspace_chat_startup_changed`, `workspace_chat_receipt_capacity_exceeded`, `workspace_chat_deleted`. An invalid caller transaction boundary raises 409 `workspace_chat_startup_transaction_required` before reads/writes, preserving caller work. Unavailable defaults expose only the resolver's bounded reason, not a hidden Persona id/name. Database errors remain service errors, not fallback success.

The current resolver raises string-detail HTTPException for unavailable defaults. Replace only that branch with a typed HTTPException subclass `WorkspaceDefaultUnavailable` carrying the existing bounded degraded reason and unchanged legacy status/detail. Legacy HTTP clients see the same response. The strict adapter catches this exact type and maps `persona_feature_disabled` to 503 with that code, and other unavailable reasons to 409 `workspace_assistant_unavailable`; both include the bounded reason. Do not infer reasons from status/message text or catch generic HTTPException/database failures as unavailability. Effective selection still uses the existing resolver, not a parallel implementation.

## Receipt Storage And Binding

`workspace_chat_startup_receipts` contains authenticated `owner_user_id`, SHA-256 key digest, SHA-256 canonical request fingerprint, SHA-256 accepted binding digest, origin Workspace id, nullable conversation reference, creation timestamp and nullable invalidation timestamp. Unique `(owner_user_id, key_digest)`. Do not retain raw keys, request JSON, responses, prompts, names or title snapshots. Origin Workspace is a scalar without deletion cascade; conversation FK uses `ON DELETE SET NULL` and a null reference is permanently deleted, never eligible for rebinding to a reused id.

PostgreSQL uses a shared ChaCha database: ENABLE and FORCE row-level security with both USING and WITH CHECK comparing `owner_user_id` to `current_setting('app.current_user_id', true)`. No live-parent EXISTS predicate: tombstones must remain countable after Workspace/chat deletion. Add guarded policy construction to the current RLS builder and apply it in the receipt migration; preserve upgrades through earlier versions where this new table does not yet exist. Missing/other tenant scope fails closed. Verify SELECT/INSERT/UPDATE/DELETE/count/replay under a NOSUPERUSER NOBYPASSRLS role in the official isolated fixture, not only under its admin role or by matching SQL text. Do not exempt the table from the RLS coverage ratchet.

The request fingerprint uses validated original metadata plus supplied-field presence before generated titles, UUIDs, timestamps or Persona selection. Key namespace is this operation across all owner Workspaces. The binding digest covers normalized assistant kind/id/character id/memory mode, server-owned startup provenance and scope. Title/state/labels, counters and client attribution changes are not binding changes; authenticated ownership is checked separately against the scoped DB owner/current access. A real identity/memory/scope change sets invalidation once in the same transaction, including change-away-and-back. No-op normalized changes do not invalidate.

`WORKSPACE_CHAT_STARTUP_RECEIPT_LIMIT_PER_USER` defaults to **10000**, must be a positive integer and counts every accepted receipt including invalidated/deleted tombstones. Invalid configuration fails closed. No expiry, eviction or key reuse. Deleting chats does not recover lifetime capacity. Exact replay works at capacity and after live-chat quota exhaustion. This is one indexed table count, not a second quota ledger.

## Transaction And Lock Protocol

1. Validate/authenticate/rate-limit before writes. The strict orchestrator must own an idle outermost transaction for creation and replay. Before any database read or write, reject SQLite `in_transaction`, PostgreSQL managed/backend transaction depth, or driver status other than IDLE; follow the existing native deletion guard's ownership checks without weakening it. Do not commit, roll back or nest inside caller-owned managed or driver-open transactions. Then begin the existing DB write transaction and serialize startup admission per authenticated owner before Workspace/Persona locks. SQLite uses write serialization; PostgreSQL uses a transaction-scoped advisory lock with a stable startup-specific namespace.
2. Read receipt without taking a receipt row lock. Recheck after each blocking admission/Workspace/Persona acquisition before fresh version/default/quota/capacity decisions. A committed duplicate wins even if defaults changed or capacity became exhausted while waiting. The strict DB-owned Workspace lookup applies current authenticated owner/access predicates but includes deleted/system-operation state for bounded classification; do not use an unowned id-only query. Existing `get_workspace` hides system-operation rows, so it alone cannot implement the new closure error. The legacy getter remains unchanged.
3. For replay, lock origin Workspace with PostgreSQL **FOR NO KEY UPDATE**, selected original Persona when applicable, then conversation; reread/lock receipt last. The weaker Workspace lock still serializes closure/default edits/deletion but is compatible with implicit KEY SHARE from a conversation Workspace-FK update, consistent with [PostgreSQL's row-lock conflict matrix](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS). Do not call the existing FOR UPDATE Workspace getter for replay: Sync currently takes a conversation lock before updating that FK, so FOR UPDATE would permit a Workspace/conversation deadlock on transfer back to the origin. SQLite remains write-serialized. Mutation writers lock conversation before receipt and acquire no new startup owner/Workspace/Persona locks afterward. Receipt-bound restore/Sync resurrection acquires its destination Workspace admission lock before conversation, then revalidates scope; if a race discovers a new required Workspace, roll back for bounded retry instead of inverting locks. Treat missing/inaccessible Workspace as 404; an archived but accessible Workspace permits replay, not new creation. A closing Workspace rejects replay while its lifecycle is in progress. Once the Workspace is gone, current access failure is 404 without revealing tombstone contents.
4. Check current access and deleted state before invalidation/binding mismatch. Null hard-delete reference or soft-deleted target returns 410 when the origin remains accessible. An unchanged restored target can replay; invalidation survives restore. Current inactive/deleted/revoked/disabled Persona rejects reuse without creating or rebinding anything. Metadata edits return current metadata from the locked row.
5. For unseen keys, lock/read current Workspace/default, validate version and current Persona, check receipt capacity and live-chat quota on the same connection, then write conversation, provenance and receipt in that one transaction. Generate title only after selection. No LLM, credential discovery or network calls inside the transaction.
6. Hold the result until the owned transaction context exits successfully; only then return to the endpoint for 201/200 projection. A commit failure must not produce an accepted/replayed response. Roll back conversation and receipt together on failure. A unique receipt conflict exits/rolls back the attempted outer transaction before rereading the winner in a fresh owned transaction through the same replay checks, never in an aborted PostgreSQL transaction. Bounded handling is not an infinite retry loop. Test caller-work preservation, nested rejection, commit failure and commit-then-response-loss separately on both backends.

Owner serialization guarantees receipt capacity across strict-startup requests in different Workspaces. Existing legacy chat quotas use an outside-transaction preflight and are not converted into a cross-route hard-quota framework here. Stage 2C must not claim to eliminate unrelated legacy quota races; strict quota rejection itself leaves no partial receipt/chat.

## Lifecycle And Native Integration

All relevant conversation writers use the DB-owned hook, not endpoint-only invalidation. Hard deletion preserves the hashed tombstone, including Workspace cascades. Private receipts never enter Sync entities, JSON export, Chatbooks, clone/import authority or public OpenAPI models. Existing provenance import stripping remains intact.

The H2 Workspace cascade closes admission in a separate committed phase. Strict creation locks the Workspace and checks `native_chat_admission_closed` and `system_operation_state`; it must not race past that closure or reset it. Current restore applies this gate only to native-protected rows, not ordinary startup chats. Extend it to receipt-bound restore and Sync resurrection/re-entry, even when the receipt was previously invalidated: their destination must remain accessible/open. Lock destination Workspace before conversation, including before Sync's initial INSERT ON CONFLICT attempt (which can itself block on an existing conversation); compare preflight and locked scope/receipt association, and abort/retry on a changed target. Extend the final Workspace-delete residual check to receipt-bound chats without weakening the native predicate. A create/restore/resurrection that commits first must be included in the deletion cascade; a closure that commits first blocks it. Keep existing outermost transaction requirements and native projection checks. Archive is a separate new-create rejection, not admission closure.

Do not weaken `native_assistant_identity_locked` or `native_conversation_sync_unsupported`, alter fork operation kinds, reinterpret native receipts, or change native restore behavior. Run native lifecycle regressions alongside receipt races.

## Current Persona Admission

Use a small shared helper for ordinary chat and session generation/preview, not a new prompt renderer. An actual Persona-backed row requires current owner-accessible, non-deleted, active Persona and enabled Persona support. Missing/wrong-owner profile remains 404; inactive is 409 with a bounded unavailable reason; feature disabled is 503 `persona_feature_disabled`. Missing Persona binding is 409. Do not disclose inaccessible ids/names.

Admission uses the construction-time `db.owner_user_id`, never mutable writer/device `client_id`. Require the supplied authenticated owner to match that immutable owner before profile lookup; retain normal conversation scope/access checks. Replace the existing service's client-id-derived Persona lookup with the helper's returned profile rather than performing a second lookup with different authority. Test matching owner with different writer attribution, wrong supplied owner, another owner's Persona and changed writer attribution without binding invalidation. None/Character bypass Persona lookup, not authentication/ownership.

Explicit None and Character/non-Persona rows bypass Persona lookup. In ordinary `chat.py`, authenticate and validate conversation scope/access, then run admission before `_resolve_auto_chat_routing_decision`, construction/use of credential runtime and message effects. Guarding only `_resolve_assistant_context_for_chat` is too late: routing and credential resolution precede it. Retain a service-level recheck for direct service callers and revocation between endpoint admission and assembly; do not cache approval across requests. Session guards run before provider/credential resolution, prompt/exemplar use and message persistence. Read-only chat listing is not generation admission. Admission is a point-in-time check, not a database lock held across a network generation; existing revocation/cancellation policies remain unchanged. Existing boundaries, custom-prompt precedence, exemplar and read-only/read-write memory behavior must pass unchanged tests. Unsupported session Persona behavior must fail closed rather than silently use a plain Assistant.

Session scope decision: `prepare_chat_completion`, `prompt_assembly_preview` and complete-v2 remain global-only in this slice. Keep their global ownership/scope verification and guard admitted global Persona rows. Omitted scope and the existing client's single `scope_type=global` query are supported. Workspace, malformed or duplicate scope options and any `workspace_id` on those routes return 422 rather than being silently ignored; an owned Workspace chat id retains the existing 404 and causes no prompt/provider/credential/message effects. Preserve unrelated query compatibility and global Character/native behavior. Stage 2C must not advertise Workspace session preview/completion support: supported Workspace Persona generation goes through ordinary `/api/v1/chat/completions`, which validates current stored scope when the client supplies only a conversation id and enforces a match whenever explicit scope is supplied. Both forms require current owner/Workspace/Persona access before effects. Adding Workspace session support requires a separate reviewed scope/access and prompt-assembly change; Stage 2D cannot claim it delivered here.

Ordinary generation treats a supplied conversation id as an existing target: missing or deleted targets return 404 before routing, credentials, creation or message effects. Do not silently replace a stale target or downgrade its former Persona. Legacy new-chat requests without a conversation id retain their creation path; this is not the strict retry/startup endpoint.
