## Approved change

Root `passlib>=1.7.0` is replaced by `libpass>=1.9.3`, with the tested 1.9.3
release locked and the MCP README installation command corrected. The existing
`passlib.context.CryptContext` import, PBKDF2-SHA256 format, 200,000 creation
rounds, 16-byte generated salt and MCP password methods remain unchanged.
Lasting synthetic interoperability regressions are added in the MCP test area.

`libpass` is a third-party fork with a different maintainer; its wheel metadata
uses an Alpha classifier. This proposal qualifies the exact 1.9.3 artifact and
the observed MCP contracts, not future versions or comprehensive dependency
trust. The fork reports removing the crypt dependency in 1.9.0.
[PyPI package and artifact](https://pypi.org/project/libpass/1.9.3/),
[maintainer changelog](https://github.com/notypecheck/passlib/blob/main/CHANGELOG.md).

The published wheel SHA256 is
`3cbeb14d22086660e92c30d787ea981973d67394e81c8c870e1a83cfe1c84353`.
The downloaded bytes match that hash. Inspection found no stdlib `crypt` or
`legacycrypt` import; PBKDF2 tests likewise do not load `crypt`.

Alternatives considered: retaining Passlib retains the warning; switching to
the separate Argon2 service changes existing hash and password-policy contracts;
a custom standard-library PBKDF2 adapter would introduce a new encoding/parser
implementation. The compatible fork preserves the existing tested API without
application code changes.

## Inventory and compatibility boundary

The only production Passlib import found is
`app/core/MCP_unified/auth/jwt_manager.py:17` under `tldw_Server_API`. Its
`pwd_context` uses only `pbkdf2_sha256`; `hash_password` returns a string and
`verify_password` returns a bool, logging a generic error on exceptions.
`JWTManager` is exported by both MCP package and auth package. The runtime auth
provider supplies it to the MCP server proxy for legacy token handling.
Scoped caller searches found password calls in the basic-functionality and
sanitization tests, but no MCP password-storage writer. External consumers
remain possible; no production password database or credential was read.

AuthNZ's `PasswordService` uses Argon2 and password-strength checks. Its API
returns `(is_valid, needs_rehash)`, so it is not a direct replacement. The
AuthNZ API-key KDF also uses a different encoded format. Neither is changed.

MCP hashes use `$pbkdf2-sha256$rounds$salt$checksum`, adapted Base64 and UTF-8
for text passwords. Verification honors the stored rounds. These match the
[Passlib format documentation](https://passlib.readthedocs.io/en/stable/lib/passlib.hash.pbkdf2_digest.html).
The old library imports `crypt` in `passlib.utils` even for this PBKDF2-only
context. It catches ImportError; the warning is not evidence that old PBKDF2
necessarily crashes on Python 3.13.

manifest/lock swap into a fresh or correctly reconciled environment and verify
that distribution metadata contains libpass alone. The README must say this
and install libpass instead of Passlib. Existing external requirements naming
the original distribution must also be reconciled by their owners; the current
repository lock has no other Passlib-dependent package.

restores the old manifest and lock into a clean environment, then verifies a
synthetic candidate-generated hash. Do not overlay or partially uninstall the
