# UAT Knowledge QA cookie bootstrap across tabs

Related task: TASK-13260.278.18.83.45 (parent-owned note established before edits).

Actual failure: a Knowledge QA request on `/knowledge?media_ids=1` lost its active results after a same-profile blank peer tab opened Notes. Source tracing identifies each new WebUI tab removing the shared cookie-session config before bootstrap; the resulting native storage event invalidates the first tab's connection and remounts its owned QA provider. The saved user-only thread restores only its question. This unit repairs the bootstrap boundary; it makes no claim about the interrupted provider or source result.

Existing canonical cookie/session, verified authority, and fail-closed request contracts remain; ADR-044 (Docs/ADR/044-cookie-session-governance-owner-preflight.md) supplies related canonical owner/explicit-credential governance. This is a client lifecycle repair, not a new durable auth or persistence rule.
