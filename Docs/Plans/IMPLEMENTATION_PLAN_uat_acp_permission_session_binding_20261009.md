## Design and ADR assessment

Bounded source repair in the existing runner. The downstream child is already captured as an actual Session by its Conn callbacks. handlePermissionRequest currently forwards raw claimed sessionId without checking that source, so child A can request policy/UI approval for registered child B. Existing validateSessionID allows absent/nonstring/empty values and is insufficient. After the existing upstream-unavailable cancelled fallback, decode only the exact canonical sessionId map key as a string, require nonempty claimed ID and the existing locked getSession lookup to return the actual source pointer. Preserve raw params, current prompt context, canonical permission decisions and nil-upstream fallback. The map is populated only after validated nonempty session/new ID, establishing exact actual identity without an initialization read.

The connected notification guard replaces only its raw session.id comparison with the same nonempty registered-pointer predicate. This refuses unregistered/empty updates and avoids that newly added initialization read; all native payload fields remain untouched. Do not change generic Conn, all direct FS/terminal readers or session initialization semantics. Other unsynchronized direct Session.id readers are baseline scope; no full race-free assertion is made. The isolated directPermissionSession helper will register its real valid Session in Runner map, matching the actual lifecycle invariant, while every original assertion stays unchanged.

ADR required: no. Existing originating session/owner and ACP permission rules are enforced, not changed; no new wire, persistence, policy, dependencies or lifecycle architecture. ADR inventory and governing ACP persistence ADR-016 were read; its shared durable ownership model remains unchanged.
