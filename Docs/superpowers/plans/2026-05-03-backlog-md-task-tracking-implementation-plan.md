# Backlog.md Task Tracking Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Initialize Backlog.md for this repo and update root `AGENTS.md` so future repo file changes are tracked through Backlog.md tasks.

**Architecture:** Backlog.md remains a repo-local markdown task board under `backlog/`, with MCP as the preferred AI-agent integration and CLI commands as the fallback. Root `AGENTS.md` receives a narrow process section that makes Backlog.md the historical task record while preserving the existing superpowers design, planning, testing, security, and commit gates.

**Tech Stack:** Backlog.md CLI `1.44.0`, markdown task files, YAML config, root `AGENTS.md`, existing `Docs/superpowers` spec/plan workflow.

## Source Spec

- `Docs/superpowers/specs/2026-05-03-backlog-md-task-tracking-design.md`

## File Structure

- Create: `backlog/config.yml`
  - Backlog.md project config, generated by `backlog init`, then adjusted for this repo's Definition of Done defaults.
- Create: `backlog/tasks/task-<id> - Adopt-Backlog.md-task-tracking.md`
  - Bootstrap adoption task created after Backlog.md initialization. The exact ID is generated by Backlog.md; use the ID printed by the command.
- Modify: `AGENTS.md`
  - Add `### 0. Backlog.md Task Tracking` under `## Process`, before `### 1. Planning & Staging`.
- Modify: Backlog.md adoption task file through CLI only
  - Record implementation plan, notes, acceptance criteria checks, DoD checks, verification, and final summary.

Do not run `backlog agents --update-instructions` for this task. The command updates all supported agent instruction files (`CLAUDE.md`, `AGENTS.md`, `GEMINI.md`, `.github/copilot-instructions.md`), while this task is scoped to root `AGENTS.md`.

## Bootstrap Rule

The approved spec and the first Backlog.md setup commit are the bootstrap exception. After Backlog.md is initialized, create the adoption task before making non-Backlog follow-up edits.

## Task 2: Create Adoption Task And Update AGENTS.md

**Files:**
- Create: `backlog/tasks/task-<id> - Adopt-Backlog.md-task-tracking.md`
- Modify: `AGENTS.md`

- [ ] **Step 1: Create the bootstrap adoption task**

Run:

```bash
backlog task create "Adopt Backlog.md task tracking" \
  --status "In Progress" \
  --desc $'Initialize Backlog.md in this repository and add root AGENTS.md instructions requiring Backlog.md tasks for future repo file changes.\n\nThis task begins after the approved spec and first setup commit, which are the agreed bootstrap exception.' \
  --doc Docs/superpowers/specs/2026-05-03-backlog-md-task-tracking-design.md \
  --doc Docs/superpowers/plans/2026-05-03-backlog-md-task-tracking-implementation-plan.md \
  --ac "Backlog.md is initialized with repo-local storage" \
  --ac "Backlog.md config keeps auto_commit=false and bypass_git_hooks=false" \
  --ac "Root AGENTS.md requires a Backlog.md task for repo file changes" \
  --ac "Root AGENTS.md preserves superpowers/spec/plan/test/security requirements" \
  --ac "CLI fallback and MCP-first guidance are documented" \
  --plain
```

Expected: output prints the created task path and ID, such as `TASK-1`. Save the actual ID for later steps.

- [ ] **Step 2: Add the implementation plan to the adoption task**

Run, replacing `TASK-1` with the actual ID:

```bash
backlog task edit TASK-1 --plan $'1. Initialize Backlog.md with project-local storage and MCP-first setup.\n2. Configure Definition of Done defaults without enabling auto-commit or hook bypass.\n3. Add root AGENTS.md Backlog.md task-tracking instructions.\n4. Verify Backlog.md config, AGENTS.md wording, and diff sanity.\n5. Record final summary and mark the adoption task done.' --plain
```

Expected: task shows the plan text.

- [ ] **Step 3: Insert Backlog.md policy into AGENTS.md**

In `AGENTS.md`, under `## Process` and before `### 1. Planning & Staging`, add:

```markdown
### 0. Backlog.md Task Tracking

This repository uses Backlog.md for task tracking and historical work records. Any work that changes repository files must have an associated Backlog.md task before file edits begin. This includes code, tests, docs, config, scripts, tracked generated artifacts, cleanup edits, and agent-instruction changes.

Read-only investigation can proceed without a Backlog.md task. If investigation turns into edits, stop, find or create a Backlog.md task, and then continue. Creating or updating Backlog.md task records is the tracking mechanism itself and does not require a separate recursive task.

Use Backlog.md through the official MCP workflow when available. First read the workflow overview exposed by the installed MCP server, such as `backlog://workflow/overview` or `backlog://docs/task-workflow`; if MCP resources are unavailable, call `backlog.get_backlog_instructions()` if that tool exists. Use the `instruction` selector for `task-creation`, `task-execution`, or `task-finalization` when needed.

Search before creating tasks to avoid duplicates. Prefer one Backlog.md task per reviewable unit of work, and split work that grows too broad. Keep the task current with status, notes, plan links, touched files when useful, verification results, blockers, PR links, and final summary.

Backlog.md does not replace this repo's superpowers workflow. Use the existing brainstorming, spec, implementation-plan, test-driven development, review, verification, Bandit, and commit requirements whenever they apply; link those artifacts from the Backlog.md task instead of duplicating them.

If MCP is unavailable but the CLI works, use CLI fallback commands such as `backlog search "query" --plain`, `backlog task list --plain`, `backlog task <id> --plain`, `backlog task create`, `backlog task edit`, and `backlog board`. Do not manually edit Backlog.md task files unless MCP/CLI/Web paths are unavailable and the user explicitly approves the exception.

If neither MCP nor CLI is available, pause before making repo file changes unless the user explicitly approves a temporary exception. Commit Backlog.md task changes with the related work unless the user asks for different staging.
```

- [ ] **Step 4: Record progress in the adoption task**

Run, replacing `TASK-1` with the actual ID:

```bash

```

Expected: note is appended.


Expected: commit contains only the root `AGENTS.md` change and Backlog.md task/config changes from this adoption flow.
