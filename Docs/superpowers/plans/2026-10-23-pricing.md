## Review Focus

Input classes the tests do not exercise; the reviewer should think about them:
1. **Float drift and ordering of multipliers.** Fast and US multipliers are applied to the finished prompt and completion cost, after cache splitting and tiering. Check that no category is multiplied twice (cache write already includes its 2x/1.25x; the 1.1x and fast 2x are applied once on top).
2. **Haiku 5.5 threshold is strict `>`.** Exactly 100,000 prompt tokens is the low tier ("up to 100,000"); 100,001 is the high tier. `prompt_total` is `prompt_tokens`, which already includes cache reads and writes (ADR-075 shape), matching the page ("counts all of its input tokens, including cache reads and cache writes"). If a caller passes `prompt_tokens` that excludes cached tokens, the tier is wrong; the only callers are `log_llm_usage` (adds them) and tests.
3. **Streaming.** `message_start` carries `cache_creation`, `speed` and `inference_geo`; `message_delta` carries only output tokens and totals (`_MESSAGES_NATIVE_DELTA_USAGE_FIELDS`). `_StreamUsage.feed` merges delta over start, so the sub-fields survive. One stream test covers it. The OpenAI-shaped adapter stream path is a confirmed pre-existing gap (review M3): `AnthropicAdapter.stream` (`anthropic_adapter.py:450-575`) never handles `message_start`, yields `message_delta` only as a `finish_reason` chunk with the usage nested under `provider_response`, and `_StreamUsage.feed` (`usage_accounting.py:140`) reads only the top-level `usage`. A streamed reply through the adapter is therefore still costed from an estimate (as `Usage_Quotas.md:108` says; Task 5 keeps that sentence). Filed as follow-up 4, unconditionally.
4. **Multi-iteration usage** (`usage.iterations`, advisor and fallback messages that can bill another model): top-level usage is priced at the request model's rate. Not changed here; follow-up.
5. **1h share larger than total writes.** Clamped to `cache_creation_input_tokens`; a provider that reports `ephemeral_1h` without `cache_creation_input_tokens` yields zero write tokens, so the 1h share is zero too (the existing normalizer takes writes from `cache_creation_input_tokens`). Test pins this.
6. **Fast or US reported on a model with no entry** (unknown-rate fallback): the multiplier still applies on top of the estimated rate. This is deliberate: the unknown rate is already a conservative estimate and the multiplier is a billing fact.
7. **Substring matching in `get_rate_details`.** Removing keys can change which key a model ID falls into: `claude-opus-4` and `claude-sonnet-4` must stay (they price the dated 4.x IDs by substring); the new `claude-mythos-5` key is a substring of `claude-mythos-5-1`, but exact match wins first, and a dated Mythos ID falls to the longest key.
8. **`get_rates` and `compute_token_cost`** (no prompt length) price tiered models (Haiku 5.5, gpt-5.5, gpt-5.4 and the -pro rows) at the base tier. They are estimators for RAG and quick wins and the ACP admin cost estimates, not billing. Acceptable; the `get_rates` docstring and the JSON `_catalog_note` say so (Task 5 edits the note).
9. **OpenAI's 272K threshold** is strictly above 272,000 input (prompt) tokens: the GPT-5 model page's "Maximum input tokens: 272,000" fixes the meaning of "272K". Cached tokens count toward it (they are part of `prompt_tokens`); output tokens do not. The two-sided test pins 272,000 versus 272,001.
10. **Hidden models under strict selection.** A hidden entry (Mythos) is priced but not listed, so `is_model_known_for_provider` answers False for it unless config.txt lists it; under `CHAT_ENFORCE_STRICT_MODEL_SELECTION` an explicit request for it is then refused with `model_not_available`. An account with Mythos access must list the model in config.txt. The cost path is unaffected.
11. **The `estimated` flag.** With the alias keys `claude-sonnet-4-5` and `claude-opus-4-1` added (Task 3), the dotted names `claude-sonnet-4.5`/`claude-opus-4.1` still price as exact matches (`estimated=False`), as on origin/dev. Without those two keys they would flip to substring matches (`estimated=True`), which `log_llm_usage` stores.
12. **US-only multiplier trusts the usage report.** The page scopes 1.1x to "Claude 4.6 and later models" and older models reject the parameter. The data-residency page says a workspace `default_inference_geo` applies when the parameter is omitted; what `usage.inference_geo` reports for a pre-4.6 model in such a workspace is undocumented. The code comment says it trusts the report; follow-up confirms the case.
13. **Retired models** (Haiku 3.5, Sonnet 3.7, Opus 4.1/4, Sonnet 4) stay priced, because historical rows and Google Cloud / Bedrock customers can still send those IDs.
14. **Generic names reprice through the reverse substring match** (review M-D). `get_rate_details` also matches `mdl in mk`, and the longest key wins, so deleting `claude-sonnet-4-6-20260105` and `claude-opus-4-7-20260103` moves bare `claude-sonnet` from $3/$15 to $2/$10 (via `claude-sonnet-5-5`) and `claude-opus` from $5/$25 to $4/$20, and bare `sonnet` loses its cache rates. These are not API IDs (`claude-sonnet` appears only in tests and the pytest-only alias map). Noted; no change.
15. **The adapter rewrites a dotted name on any Anthropic base URL** (review M-C), including a BYOK proxy (`byok_allowed_base_url_providers` includes `anthropic`). A proxy that defines its own dotted alias (a LiteLLM model name `claude-sonnet-4.5`) would receive `claude-sonnet-4-5`. Unlikely and consistent with the ruling; Task 5 documents it.
16. **"The outgoing request always carries the dashed ID"** holds for the Anthropic adapter, the Messages proxy and `count_tokens`, the tokenizer count-only adapter and the Slides standalone-HTML provider (the Anthropic request builders found by reading the callers of the Anthropic endpoint). A new direct caller must use `canonical_anthropic_model_id`.
