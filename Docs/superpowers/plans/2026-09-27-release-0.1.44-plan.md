## Upgrade and scope limits

Back up and drain existing API, workers and direct database writers before the registered per-user schema migrations. Restart only compatible binaries; mixed-version rolling upgrades and data-preserving old-binary rollback are unsupported. PostgreSQL requires a dedicated NOSUPERUSER/NOBYPASSRLS application role that does not own content tables; run migrations as the owner. Existing pgvector tables require owner-prefixed migration to appear, and previously issued ownerless Chatbook signed URLs stop verifying. See the release notes and merged PR2963/2985/3002 contracts.
