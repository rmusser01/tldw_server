63,144-test suite in the publication job; it does not claim that suite passed.

`25608249ed5f0fe3700f6e87feeedce77c503425`. Application/package inputs, version and
legal records are unchanged. PyPI publication has not completed. PR #2974 must
finish final CI and its applicable review/merge gate before main changes.
The explicit human-summary waiver for PR #2973 covered that PR only.

## Stage 3: Publish and verify immutable artifacts
**Goal:** Complete the existing 0.1.42 PyPI release with traceable build evidence.
**Success Criteria:** The approved bounded gate, build/package validation and
trusted PyPI publish succeed; registry files/digests and recovery build commit
are recorded and package inputs still match the immutable tag.
**Tests:** Actual workflow outcome, registry metadata and distribution verification.
**Status:** Not Started (awaiting Stage 2)

Observe the automatic main push workflow after the reviewed merge. It requires:

1. Version detection with fail-closed lookup behavior.
2. A 30-minute release gate containing five-minute contract and startup steps.
3. `make pypi-check`, artifact upload, and a successful build dependency.
4. The existing environment-scoped trusted PyPI publisher.

Manual TestPyPI/PyPI choices remain available for deliberate recovery. If an
attempt fails, diagnose that failure before retrying. Never move/recreate the
published tag or republish successful container artifacts. Record the actual
recovery merge as the build commit; do not call it the original tag commit.
Approval of this gate change does not authorize a 0.1.43 release.
