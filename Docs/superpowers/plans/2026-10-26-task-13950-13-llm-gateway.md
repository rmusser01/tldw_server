# Extract the LLM gateway from chat_service as the single policy hook Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every LLM provider call goes through one module, `core/LLM_Calls/gateway.py`, that LLM_Calls can import without loading the Chat package, and that gives moderation (TASK-13950.27) one pre-call and one post-call hook.

**Architecture:** Six ordered PRs. First freeze direct adapter calls and move templating to `core/Utils` (A). Then cut every `core.LLM_Calls -> core.Chat` import but one by moving the shared helpers down and the Anthropic wire-format module up (B). Then move key resolution into the new gateway, delete its test-only reach into `api.v1`, and give every test the healthy, empty override store that production startup gives the server (C1). Then move the call path and provider/model resolution (C2). Then add the hooks and a typed pre-call refusal (`LLMPolicyRefusal`) that chat passes through to its client (D). Last, amend ADR-025 (D2). `chat_service` keeps re-export shims for the moved names that production callers import. Moved internals are not re-exported, so a stale patch or call on `chat_service` fails with an AttributeError instead of silently doing nothing.

**Tech Stack:** Python 3.12/3.13, FastAPI, pytest, the AST lint ratchets under `tldw_Server_API/tests/lint/` (`_ast_cache.py`, `_ceilings.py` from TASK-13950.8; `test_layering_contract.py` from TASK-13950.9), ruff, mypy, GitHub Actions `backend-required`.

**Spec:**

## Review Focus

1. **A patch that silently stops intercepting after the move.** For example, a test that patches `chat_service._get_llm_registry` would make a real provider call. AttributeError covers only names that are not re-exported. It misses a shim name (`STREAM_DAEMON_POOL` set on `core.Chat.bounded_daemon`), a DUPLICATE name patched on one module only, and the `perform_chat_api_call*` patches once `.27` moves a caller. Pinned by Task 4 `test_moved_internals_are_not_re_exported`, the scanned RETARGET/DUPLICATE lists, B's module-import grep, and the no-network run that ends B, C1 and C2 (Task 0 Step 2): a test that newly attempts a live connection means a patch stopped intercepting.
2. **A policy refusal rewritten as a provider error.** The gateway's `except Exception` turns errors into `privacy_safe_chat_error`. Chat then rewrites any untyped error into a 502 `provider_unavailable`, in `_sanitize_provider_stream_call` (stream) and `_bound_provider_invocation_exception` (non-stream). Pinned at the gateway by `test_a_pre_call_refusal_reaches_the_caller_unchanged_and_skips_the_provider` (sync and async, `privacy_safe_errors=True`), and at the client by `tests/Chat/integration/test_gateway_policy_hooks_chat_endpoint.py::test_a_policy_refusal_reaches_the_chat_client[stream/non-stream]` (400, not 502).
3. **Streams bypass the post-call hook, or lose the user.** Output moderation would then miss every streamed reply. A per-user or Guardian policy also needs the user when the wrapper runs, which is later, in a stream daemon thread that does not carry the content scope. Pinned by Task 5 `test_a_post_call_hook_can_wrap_a_sync_stream`, `test_a_post_call_hook_can_wrap_an_async_stream` and `test_a_stream_wrapper_consumed_in_another_thread_sees_the_user`.
4. **The surface tag reaches a provider.** `llm_surface` forwarded as an unknown parameter gives a 400 from strict providers. Pinned by Task 5 `test_the_surface_id_reaches_hooks_but_not_the_provider`.
5. **Fresh-process import cycle or laundered Chat load.** `adapter_utils -> gateway -> adapter_registry -> providers -> adapter_utils` must import cleanly at server start, and no `core.Chat` module may load through a third package, which the static layering count cannot see. Pinned by `tests/lint/test_llm_calls_import_isolation.py` (fresh interpreter: `openai_adapter` and `gateway` load no `core.Chat`; `core.Chat` loads no `api`).

    """One provider call as the policy hooks see it."""

    surface: str | None  # the caller's llm_surface kwarg; "chat.completions" for /chat/completions, else None until .27
    provider: str
    request: dict[str, Any]  # the adapter request (messages, system_message, model, stream, ...); a pre-call hook may replace values
    stream: bool
    user_id: int | None  # current_llm_user_id() when the gateway was entered; never the client's OpenAI "user" field


PreCallHook = Callable[[GatewayCall], Any]
PostCallHook = Callable[[GatewayCall, Any], Any]


def add_policy_hooks(
    *, pre_call: PreCallHook | None = None, post_call: PostCallHook | None = None
) -> Callable[[], None]:
    """Run pre_call before and post_call after every provider call; return a function that removes them."""

class LLMPolicyRefusal(HTTPException):
    """A gateway pre-call policy hook refused an LLM call: always HTTP 400 (TASK-13950.13).

    An ``HTTPException``, like ``LLMQuotaExceededError`` and for the same reason: endpoints report
    a ``ChatAPIError`` as a provider failure, and most let an ``HTTPException`` through unchanged.
    ``detail`` is client-safe text the hook author writes. It never echoes the request, the system
    prompt or retrieved context.
    """

    retryable = False  # job workers read these, as for LLMQuotaExceededError
    failure_code = "llm_policy_refused"

    def __init__(self, detail: str) -> None:
        super().__init__(status_code=400, detail=detail)
```

  - Chat's own moderation block today is `HTTPException(400, "Input violates moderation policy")` (`chat_service.py:3858`), so `.27` can move it into a hook as `LLMPolicyRefusal("Input violates moderation policy")` with the same response.
  - The status is fixed. A hook-chosen 401 would re-enter chat's OpenAI OAuth retry (`_is_auth_401_error` reads `status_code`, `chat.py:5421-5431` on `06a2ceb3cb`), and the refusal would come back as `ProviderCredentialTerminalError("provider_authentication_failed")`. A 402 would read as a quota refusal, and a 429 or 5xx as retryable to job and workflow callers.

- Contract (the gateway docstring states it, and the ADR amendment repeats it):
  - **Order.** Hooks run in registration order. The registry is the module list `_POLICY_HOOKS: list[tuple[PreCallHook | None, PostCallHook | None]]`, iterated over a tuple copy.
  - **Refusal (pre-call only).** A pre-call hook refuses by raising `LLMPolicyRefusal(detail)`. Pre-call hooks run after the adapter lookup and before the `try` that maps provider errors, so their exception reaches the caller unchanged and the provider is not called. Any other exception from a pre-call hook refuses the call too (fail-closed); a hook that wants fail-open catches its own errors. Nothing has been spent: the quota gate only checks, and chat refunds its reservation.
  - **Refusal text.** `detail` is client-safe text the hook author writes. It never echoes the request, the system prompt, a character card, world-book entries or retrieved context, and never names the provider, model or endpoint. Chat returns it to the client as is, even for `privacy_safe_errors` callers.
  - **Re-entrancy.** No guard. A hook must not call the gateway, because it would run every hook again, itself included.
  - **Secrets.** `call.request` carries `api_key`, `app_config` and the credential handle. Hooks must not log or persist it.
  - **Editing.** A pre-call hook replaces values (`call.request["messages"] = [...]`) rather than mutating nested items. `call.request["messages"]` aliases the caller's `templated_llm_payload`, which chat reuses for fallback and tool continuation. The adapter receives `call.request`.
  - **Post-call (never raises).** Post-call hooks run after that `try`, each receiving the previous hook's return value, and the last value is returned. By then the provider has answered and billed. So a post-call hook does not raise, and never raises `LLMPolicyRefusal`. To block or redact output it returns a replacement: a response that keeps the provider's `usage` (as `moderation_pipeline.apply_output_safety_to_choices` does today), or a stream wrapper that replaces content chunks, passes the provider's usage chunk through, and ends the stream itself. Self-recording callers such as chat (`llm_call_context(records_itself=True)`) then still record the real tokens. An exception from a post-call hook is a bug: the gateway lets it propagate, and that call's usage goes unrecorded. Post-call hooks catch their own errors.
  - **Streams.** For a stream, the value is the stream iterator: sync in `perform_chat_api_call`, async in `_async`. A wrapper runs when the caller iterates, which for chat is later and in a stream thread. It reads the user from `call.user_id`, not from context. A chunk the wrapper has already yielded cannot be recalled, so a match that can span chunks needs a bounded holdback buffer, as chat's `MODERATION_STREAM_BUFFER_CHARS` does today.
  - **User.** `GatewayCall.user_id` is `core.Usage.llm_call_context.current_llm_user_id()`, read when the gateway is entered. For a streamed chat call that is already inside the stream-factory daemon thread, and `BoundedDaemonPool.start` carries the resolved user there (`capture_llm_call_state`, `bounded_daemon.py:139-145`). It does not carry the content scope to later threads, which is why the value is captured on the call. Guardian's `chat_type` is `.27`'s to add, for example as another reserved kwarg like `llm_surface`.
  - **Async hooks.** In `perform_chat_api_call_async`, a hook's awaitable return is awaited. In `perform_chat_api_call`, an awaitable return is closed and raises `TypeError(f"policy hook {hook.__qualname__} is async; perform_chat_api_call is sync")`.
  - **No hook.** The result is the same object the adapter path returned.
  - `llm_surface` is read from `kwargs` and is never part of the adapter request.

TASK-13950.13 moved `perform_chat_api_call`, `perform_chat_api_call_async`, provider and model resolution
(`resolve_provider_and_model`) and provider key resolution (`resolve_provider_api_key`) from
`core/Chat/chat_service.py` into `core/LLM_Calls/gateway.py`, and moved `get_api_keys` from the chat request

longer imports the Chat package, and key resolution no longer reads `API_KEYS` from the API layer under pytest.

The gateway runs registered policy hooks around every provider call: `add_policy_hooks(pre_call=..., post_call=...)`.
None is registered by default. A pre-call hook sees a `GatewayCall` (surface, provider, adapter request, stream,
and the user the call is for) and may replace request values or refuse the call. A post-call hook receives the
result, or the stream iterator, and returns what the caller gets. Callers name their surface with the reserved
`llm_surface` keyword, which never reaches a provider; `/chat/completions` sends `chat.completions`.

The hook contract:
- Only a pre-call hook refuses, by raising `LLMPolicyRefusal(detail)` (`core/exceptions.py`, always HTTP 400). The
  refusal reaches the caller unchanged, and `/chat/completions` returns it to its client, streamed or not. Any
  other exception from a pre-call hook refuses the call too (fail-closed); a hook that wants fail-open catches
  its own errors.
- `detail` is client-safe text the hook author writes. It never echoes the request, the system prompt or retrieved
  context, and never names the provider, model or endpoint.
- A post-call hook never raises: the provider has already answered and billed. To block or redact output it
  returns a replacement that keeps the provider's `usage`, or a stream wrapper that passes the provider's usage
  chunk through and ends the stream itself, so the call's real tokens are still recorded. A chunk the wrapper
  has already yielded cannot be recalled, so a match that can span chunks needs a bounded holdback buffer, as
  chat's `MODERATION_STREAM_BUFFER_CHARS` does today.
- Hooks run in registration order, with no re-entrancy guard. A hook must not call the gateway.
- `GatewayCall.request` carries the API key, the app config and the credential handle. Hooks must not log or
  persist it. A hook replaces values rather than mutating nested items, because the messages list aliases the
  caller's payload.
- `GatewayCall.user_id` is the user the call is for, read when the gateway is entered. A stream wrapper reads the user
  from the call, because it runs later and in another thread. Guardian's chat type is TASK-13950.27's to add.

Moderation (TASK-13950.27) registers here, from its own package, so LLM_Calls imports neither Chat nor Moderation.
Direct adapter calls outside the gateway are frozen by `tldw_Server_API/tests/lint/test_direct_llm_adapter_calls_ratchet.py`.
```
