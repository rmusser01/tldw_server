# Notes structured source

The main Notes editor keeps the note body as exact source. Language is separate nullable metadata: Default means Markdown, explicit Plain text/Markdown/YAML/JSON/JSONL modes are available, and an unknown future value remains unchanged. Choosing a mode changes no source. YAML, JSON and JSONL use the installed native Monaco editor; other modes retain their existing source controls. Structured/future notes never invoke Markdown/WYSIWYG conversion, including while loading or restoring a device preference.

**Check document** checks the current whole source. Checks also run on initial open, mode changes and after 400 ms inactivity. Any edit immediately retires old diagnostics/success. Problems show logical line/column coordinates; selecting a Problem moves to the source. Background checks do not move focus or announce every keystroke. Check and explicit Format share 1 MiB UTF-8, depth 100, 100 diagnostic and 2 second processing bounds. Diagnostic status is separate from save/recovery status; syntax errors do not veto saving.

**Format document** is explicit and checks its own captured source. A changed proposal enters native history as one transaction; a no-op adds no history. Source edits, mode/authority changes, navigation, conflict, loss of editability and composition can retire a pending operation. Selection/caret and viewport are preserved. No source undo stack is stored by diagnostics, and manual/native changes retire the prior AI undo action. Pending Markdown attachment and Studio actions also check the current canonical document, authority, source and effective display language before writing; a later structured or temporary mode retires the old write.

LF and CRLF are supported without converting their representation. Monaco supports both an initial model-owned BOM and a leading FEFF pasted into its buffer; its adapter preserves the factual native prefix. YAML BOM formatting is qualified. The strict JSON/JSONL engines retain their BOM syntax refusal: those sources remain exact/editable/saveable, but format is blocked. Mixed LF/CRLF and lone CR are source-only native profiles; exact body, title and Save remain available. Ordinary textarea owners retain CR-bearing canonical source rather than passing it through a normalizing widget.

On a server proven unable to persist language metadata, a note whose canonical language field is proven absent may use a clearly labeled temporary display mode. Fresh implicit-default drafts can use the same session-only choice. It survives ordinary title/body save and benign same-note reload, but expires on note/authority/auth/connection changes or new canonical metadata. It is never claimed as portable metadata or automatically promoted. Missing capability fields alone are unknown. Known/null/future values and recovered explicit intent remain protected by normal save/ACK rules.

The Notes Dock opens structured/future server notes in main Notes before handing them to a mode-less local editor. Source-only profiles retain canonical text for title/save or offer that existing main open action. Secondary capture uses **Save source**: only exact text and the existing captured tag are saved; the displayed page URL is not persisted. The modal explains this before saving and keeps the URL visible. Existing older note bodies with inline source attribution are unchanged.

Monaco loads only local installed assets, prepared through existing postinstall/build/development entries. Next production/standalone serving consumes those prepared assets and does not require installed build dependencies. The shared loader restores the fixed native worker factory after the installed AMD initialization and before Notes, Presentation Studio HTML or Watchlists template editors use it. CSP, bundlers and the canonical Notes transport/storage rules are unchanged. Physical OS IME and system clipboard behavior remain unqualified by the synthetic composition and public native paste controls.

## Download source or export a note

**Download source** writes only the current canonical body as UTF-8. It adds no title, frontmatter or attribution and never parses or formats document values. Unsaved edits are included. BOM, line endings, boundary whitespace, invalid syntax and large numeric spellings stay exact, including source retained behind a native representation fence. Known canonical modes use `.txt`, `.md`, `.yaml`, `.json` or `.jsonl`; Default/null, absent and unknown future modes use `.txt` without guessing a language.

**Export note** writes a distinct `.note.json` file with the existing `tldw.note.v1` portable envelope: title, exact source string, canonical language and keywords. The envelope JSON escaping is a container representation, not a conversion of the source. Import as a note container to recover its metadata; importing it explicitly as source instead treats the whole envelope as source. Null and unknown future modes are preserved. An absent/unknown language field from an old server cannot become portable metadata automatically: download source remains available, while portable export refuses until canonical metadata is known. A temporary view selection does not change the source filename extension or fill portable metadata.

Markdown, print and bulk Markdown exports are separate existing conversions; they are not exact-source or complete portable-note backups. The desktop Chatbook exporter uses archive version 4.0 for Notes and retains Canvas records; its Canvas-only archives continue to use 3.0. Unsupported portable-note/archive versions are refused before import writes. Use the desktop archive export for combined Notes and Canvas; the single-note envelope does not contain Canvas.

## Checking, formatting and recovery

Choose Plain text, Markdown, YAML, JSON or JSONL independently of the body. Unknown future modes remain unchanged and have no structured parser. Check document runs on initial open, language change and after 400 ms of typing inactivity. Manual Check checks the whole current source. Editing or changing language retires previous diagnostics. **No syntax errors** means a complete check of that source found no grammar errors; it does not establish application-schema validity, correct values or intended structure. Markdown code blocks are not linted.

YAML indentation may be syntactically valid while expressing an unintended structure. For example, moving `name` under a different mapping can still pass Check; inspect the intended nesting yourself. JSON is strict: trailing commas, comments and non-finite numbers are refused. JSONL requires one JSON value per physical record, rejects blank records, allows a final newline, and treats an empty file as zero records; an empty JSON document is not valid JSON. Duplicate keys, including escaped JSON names, are reported and block formatting. YAML custom tags are never executed; ambiguous merge/key semantics or constructs the engine cannot prove it preserves may be unsupported for formatting even if grammar is valid.

**Format document** is an explicit action and checks its own captured source. Syntax errors, duplicates, unsupported constructs, excerpts, resource limits or unavailable editors/workers refuse formatting without changing the body. A changed result is one native undo transaction; an already formatted result adds no edit. Normal Undo restores the prior source. A pending result cannot apply after source, language, document or authority changes, conflict, loss of editability or supported composition begins. Formatting is deterministic and idempotent within each engine; whitespace need not match across the two apps.

Common limits are 1 MiB of UTF-8 source, nesting depth 100, 100 displayed diagnostics and a 2-second processing deadline per request. A limited, unsupported or failed check is not a successful syntax check. File Notes additionally keeps its existing 200,000-character interactive limit; an excerpt cannot become editable because the engine permits more bytes. Native mixed/lone-CR representation fences preserve canonical source for download/export and title/save while body editing is unavailable.

Syntax errors never add a save veto, and formatting never saves automatically. Existing optimistic versions, conflict/overwrite controls, authority and path checks still apply. Empty drafts remain local when a server's nonempty-body contract rejects saving; recovery keeps the empty source without inserting placeholder text. Restore the draft, add content if needed and retry the existing Save action. Diagnostics are separate from save and recovery status.

The browser uses its existing download flow. Canonical source and language are captured together when the action runs; a later edit does not mutate the downloaded artifact. On proven incapable old servers, a clearly labeled temporary language remains session-only through ordinary body/title saves and benign same-note reload, then expires on note/authority/auth/connection changes or new canonical metadata. Missing capability fields alone do not prove incapability. Existing known/null/future metadata and recovered explicit intent keep their save/ACK protections.
