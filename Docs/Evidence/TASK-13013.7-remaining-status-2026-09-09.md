## Schema warning compatibility assessment

Independent scratch probes extracted only the two response-format class
definitions and used Pydantic 2.11.7 with a synthetic request envelope. No
application module was imported or edited. An alias plus wrap serializer
preserved default nested output but broke `include={"schema"}`,
`exclude={"schema"}`, nested schema exclusions and `model_copy` updates.
Dataclass alternatives preserved nested wire output but removed BaseModel APIs
and changed `exclude_unset` behavior; an ordinary dataclass also lost direct
construction validation. No tested minimal alternative preserved all of these
contracts, so this warning remains open.

The Pydantic 2.11-only `serialize_by_alias` setting cannot cover the declared
minimum of 2.0. Model serializers existed in 2.0, but API availability alone
does not make the proposed rename compatible. Neither minimum-version 2.0 nor
locked-version 2.13.5 behavior was executed in this assessment.
