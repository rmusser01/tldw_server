## Twelve scoped mount exclusions

[CVE-2026-76642](https://github.com/util-linux/util-linux/security/advisories/GHSA-m25x-3hj9-m26f)
requires an executed external helper that fails, followed by privileged mount
post-hooks. The complete fresh helper inventory closes the earlier missing
filesystem prerequisite. [CVE-2026-78410](https://github.com/util-linux/util-linux/security/advisories/GHSA-rh77-686x-2f2m)
requires restricted authorized bind/rbind use with replaceable source ancestors
and ownership/mode post-hooks. The fresh root-controlled fstab supplies no such
authorization. Earlier first-party caller/source evidence remains applicable:
all 16 retained caller and recipe hashes are unchanged. Current repository
Compose inputs add no such in-image mount invocation or authorization.

The inference is limited to these reviewed defaults. Each CVE has one exact
High-severity record for `mount` and `libmount1` 2.41.5-0+deb13u1 in each backend
component, including exact amd64 Debian-13.6 PURLs. Setuid presence is expressly
acknowledged. An unprivileged process or permission to execute local code is
not used as a reason to dismiss a privilege boundary.
