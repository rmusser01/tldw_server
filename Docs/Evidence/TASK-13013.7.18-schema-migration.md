## Contracts and limits

Normal JSON input, default nested dictionary/JSON output, and generated schema
metadata retain `schema`. Python attribute access, field selections, copy
updates, `by_alias=False` and legacy `.dict()` have the approved differences
listed in the design. Use `schema_definition` for Python updates.

Review found one additional edge: on Pydantic 2.13.5, direct
`JSONValidateConfig.model_validate_json()` with both `schema` and an extra
`schema_definition` key drops the latter extra. Pydantic 2.11.7 and dictionary
validation retain it. The actual schema is unchanged, unrelated extras remain
supported, and no affected application caller was found. This evidence does
not claim complete parity for every possible JSON input.
