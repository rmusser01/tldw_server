## Why the raw scanners still match

The retained Trivy and Grype reports each contain four Expat rows for
`libexpat1` version `2.8.4-1~deb13u1+tldw1`. Trivy attributes all four to Debian
and supplies no fixed version. Grype uses `dpkg-matcher`, the source package
`expat`, and namespace `debian:distro:debian:13`; every row has version constraint
`none (unknown)` and an empty fix-version list. Its `wont-fix` field describes
that database record, not a determination about this custom candidate's source.

Debian's fixed-version entries above apply to unstable's `2.8.4-1`; Trixie's
published security package remains `2.8.3-1~deb13u1`. The match metadata supports
a distribution-record recognition gap for the three source-fixed cases. It does
not justify automatically removing a row or treating a custom version string as
proof of a fix. Trivy marks all four Medium; Grype marks 66046 High and the others
Medium. These original severities and all eight rows are preserved.

Syft catalogs one system Expat package. It does not separately catalog the
bundled CPython copy in this image scan. Therefore this four-row reconciliation
cannot establish that the entire image or both copies have complete scanner
coverage. A separate source SBOM is supporting evidence, not image-wide clearance.
