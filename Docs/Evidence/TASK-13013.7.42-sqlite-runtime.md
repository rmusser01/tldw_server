# TASK-13013.7.42: fixed SQLite runtime — qualification incomplete

The three canonical backend Dockerfiles now install official Debian
`libsqlite3-0 3.53.4-2`. The source correction is committed in `6da7787415`
and `4c64af2c46`. Compatibility checks pass with the fixed library and the
previously verified installed application code. Full canonical image builds
remain blocked by host storage, so this task and release qualification remain
open. No new exception is active.

## Package and source correction

The administrator bundle restore can preserve externally supplied database
pages for later application FTS queries. Existing logical-import protections
remain in place. This work updates the native library without changing the
restore API; it does not claim a reproduced native exploit or authentication
defect.

[Debian's CVE-2026-11822 record](https://security-tracker.debian.org/tracker/CVE-2026-11822)
and [CVE-2026-11824 record](https://security-tracker.debian.org/tracker/CVE-2026-11824)
identify `3.53.4-2` as fixed while Trixie's `3.46.1-7+deb13u1` remains affected.
[SQLite's advisory record](https://sqlite.org/cves.html) identifies the two IDs
as the same FTS5 defect, fixed upstream in 3.53.2. The retained primary-source
snapshots document the vendor basis for this update.

Both packages are fetched from Debian with Docker's mandatory SHA256 check:

| Architecture | Package SHA256 |
| --- | --- |
| amd64 | `bbf13c9326764d05e37e6590debdaa6f33af6bd822e3ca1204789d9d1dc23b11` |
| arm64 | `e417fb0642502c090d84a6f5fce1a2e5961dfe18644415ddce77a1a67cd2fc89` |

The runtime installs only its matching package through a temporary builder
mount. The archive is not copied into a runtime layer. Installation follows
the large dependency/source copies and precedes the production image's user
switch. An isolated standard-library check rejects SQLite older than 3.53.2.
Python locks and runtime APIs remain unchanged, and no unstable APT source is
added. Both packages require libc6 >=2.38; the qualified base has 2.41.

## Completed compatibility checks

Four small images cover Python 3.11/3.12 on amd64/arm64. All sixteen SQLite
checks and four restores of a benign database created with 3.46.1 pass. The
old app image passes the three compatibility checks and fails the version
check, as expected. The compile-option delta is retained; the scoped source
search found no first-party use of the `fts3_tokenizer` interface or
SQLite subtype C APIs.

Three additional compatibility images use the exact saved TASK41 OCI
subjects as immutable build contexts. They add one SQLite installation layer
and preserve the original environment, entrypoint, command, healthcheck,
working directory, user and source labels. Their separate qualification label
explicitly identifies this limited purpose. These derivatives are not builds
of the revised canonical recipes.

| --- | ---: | ---: | ---: |

All fifty-five checks pass. The import probe hashes the installed files and
checks ordinary, STRICT and WITHOUT ROWID data, configuration views and
hydration without loading models or starting the application. The independent
SQLite checks cover backup/restore with FTS5 search, JSON and WAL. Every copied
virtual environment maps SQLite 3.53.4 to the expected native library with
SHA256 `666b2574049ed1db068b4a70837171d327c1696bf0498e6538913711c1a28370`.
The JSON companion records exact baseline and derived subjects, source hashes,
package provenance and test results.

An initial verifier incorrectly required completely empty `dpkg --verify`
output. The pinned Debian slim configuration deliberately excludes four
package documentation files. The corrected verifier requires that configuration,
the exact package version and precisely those four missing-document lines;
any additional discrepancy fails. The separate native SHA256 check remains
mandatory. No library mismatch was observed.

## Pending canonical qualification and policy

The first canonical app/worker attempts exhausted host storage during the
large virtual-environment copy and stopped Docker. Docker was recovered. A
serial retry with a disk reserve was deliberately canceled when dependency
cache reuse failed, before another large download could fill the disk.

Cleanup was restricted to recorded task-owned failed intermediates and
superseded TASK39 Docker copies. All 61 files in the complete saved TASK39 OCI
layouts were rehashed before removing their loaded duplicates. The three
TASK39 build records were exported before removing their Docker history
copies. Saved OCI layouts, raw reports and prior committed evidence remain.
Docker reported substantial intermediate-cache reclamation, but macOS still
had approximately 14 GiB free after its documented space-reclamation helper.
No additional full rebuild was attempted with that headroom.

The retained offline scan of the small fixed-library image still reports the
two High SQLite IDs for `3.53.4-2` under Trixie's suite status. Six exact,
expiring vendor-fixed dispositions and thirty boundary tests are retained as
inactive proposals. Their activation requires successful canonical candidate
builds, exact installed-library qualification and fresh bound scan evidence.
The active 336-record policy, including all Chroma dispositions, is unchanged.
Old affected package versions have no new allowance.

The final explicit five-file source/policy selection passes 261 tests without
warnings. Scoped Ruff and Bandit checks and independent source/helper reviews
are retained. Temporary subprocess and pytest diagnostics are classified in
the review records; they are not presented as application vulnerabilities.
No push, publication, deployment, workflow dispatch or merge occurred.
