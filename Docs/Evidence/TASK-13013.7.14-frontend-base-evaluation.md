# Frontend OS base evaluation — TASK-13013.7.14

Date: 2026-09-08. This is candidate evidence, **not release certification**.
Production Dockerfiles, locks, vulnerability admission and exceptions are unchanged.

## Result and next step

The same-version Trixie base does not solve the frontend OS gate. Distroless
substantially reduces installed packages but still has four High/Critical Grype
matches. A throwaway Ubuntu 24.04 + Node 24.20.0 runtime successfully starts and
has zero High/Critical matches with both pinned scanners. Ubuntu's installed
`libc6 2.39-0ubuntu8.8` contains vendor fixes for the three glibc findings below.

That is **not** evidence that every earlier OS finding was fixed: Grype still
reports 40 of the baseline's 58 High/Critical package/CVE keys in Ubuntu at lower
severity. In particular, zlib CVE-2026-85091 remains reported as Medium and
unfixed. No exception, custom ignore rule, VEX document or severity override was
added. Grype retained its stock kernel-header ignore rules; these runs report
zero ignored match rows. Those defaults are visible in the raw configuration.

Next: qualify a candidate-only Ubuntu runtime with the existing frozen frontend
build outputs on native amd64. Preserve GNU native dependencies, UID/GID/home,
Next.js tracing paths, health behavior and shutdown. Do not adopt the throwaway
recipe below as a production recipe. zlib applicability remains unresolved;
the changed distribution severity is not a remediation claim.

## Compatibility and validation boundaries

Both existing builders use the frozen Bun 1.3.2 install and Node 24.20.0; keep
those inputs unchanged. The standalone outputs contain GNU sharp/libvips native
dependencies. Native checks must load sharp and perform a real transform, not
only detect a package. Preserve WebUI UID 10002, Admin UID 10003, group/home
semantics, standalone/static/public paths, ports 3000/3001, the WebUI root health
check and Admin `/api/health/ready` backend-aware behavior, and 30s/5s/5 retries.
The Admin real-backend test mode disables standalone output, so that test alone
cannot qualify the production standalone image.

Alpine was not selected: [Node 24.20.0 platform policy](https://raw.githubusercontent.com/nodejs/node/v24.20.0/BUILDING.md)
classifies x64 musl as Experimental and GNU/Linux x64 as Tier 1. Ubuntu preserves
the supported libc family, but that does not replace native dependency tests.
