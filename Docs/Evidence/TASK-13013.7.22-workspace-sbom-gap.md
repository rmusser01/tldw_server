## Reproduction and root cause

The root `apps/package.json` declares `extension`, `tldw-frontend`, and
`packages/*`. Resolving those patterns finds four child manifests:

| Workspace | Manifest directory | Present in retained source SBOM metadata |
| --- | --- | --- |
| `tldw-assistant` | `apps/extension` | Yes |
| `tldw-frontend` | `apps/tldw-frontend` | Yes |
| `@tldw/ui` | `apps/packages/ui` | Yes |
| `@tldw/voice-assistant-sdk` | `apps/packages/voice-assistant-sdk` | **No** |

The SDK also has its own importer and workspace package entry in
`apps/bun.lock`. The inspected workflow `.github/workflows/sbom.yml` constructed
three child identities from a fixed manifest-directory list, assigned them to
`metadata.component.components`, and asserted the same three identities.
It did not include the SDK directory. The existing contract test
`test_bun_sboms_use_pinned_required_only_cdxgen_profiles` checked that same
partial list, rather than comparing with the declared workspace set.

The SDK name is absent throughout both retained JSON documents, not merely
from the metadata list. Its direct `eventemitter3` dependency is represented
at version 5.0.4; version 4.0.7 is also present for other consumers. No claim
is made that the SDK's third-party dependency was omitted or that the SDK is
shipped by a particular runtime image.

## Approved correction

The requester approved the following scope, which has now been implemented:

1. In `.github/workflows/sbom.yml`, add
   `apps/packages/voice-assistant-sdk` to the existing child-manifest list,
   and `("@tldw", "voice-assistant-sdk")` to its structured identity assertion.
   Check the scoped identity as separate group/name fields: its PURL encodes
   `@` as `%40`, so a literal full-name substring check is inappropriate.
   Preserve the canonical cdxgen component and dependency arrays,
   required-only profile, pins and vulnerability policy.
2. In `tldw_Server_API/tests/CI/test_sbom_workflow_contracts.py`, exercise the
   workflow's actual metadata-processing block against a synthetic SBOM and
   compare the resulting identities with manifests selected by the root's
   declared workspace patterns. The existing workflow must fail for the
   missing SDK before the correction. The test should also reject removal of
   any expected identity so the same omission cannot silently recur.
3. Validate the corrected producer and merged aggregate with the pinned
   CycloneDX tools; confirm all four child identities survive the merge and
   the third-party component/dependency arrays are unchanged. Run focused
   tests, actionlint, applicable Python lint and scoped Bandit, followed by
   independent review. Exact current-head remote CI remains a separate gate.

This keeps the existing explicit metadata construction and makes omissions
detectable when a workspace is added. It introduces no new generator or
dependency-resolution policy. Rollback is confined to the workflow and its
tests. Application packages, locks, image definitions and scanner decisions
are outside this correction.

The explicit approval supersedes the inherited workflow exclusion for this
bounded correction. Parent AC2 remains unchecked pending broader final
certification; this task does not admit a release.
