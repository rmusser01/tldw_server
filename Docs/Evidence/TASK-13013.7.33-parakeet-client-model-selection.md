# TASK-13013.7.33 — Parakeet RNNT client selection

The actual unified WebSocket configuration handler accepted an arbitrary client
model identifier before this change. A harmless JSON frame containing
`example.invalid/unapproved-model` became the resolved RNNT model name and
reached one stubbed transcriber entrypoint without an error response. No model
was loaded. This confirms the application configuration defect. It does not
establish deployed CVE impact: the hash-bound retained base-image inventories
in TASK-13013.7.29 do not contain optional NeMo/Hydra.

The fix adds 13 lines immediately after framing validation in
`Audio_Streaming_Unified.py:2719`. An explicit client value must be a string
equal to one of the two existing documented model choices or the current
server-selected value. Rejection uses the existing `bad_request` error and
WebSocket close code 4400, before client config mutation or transcriber
construction. Omission leaves the server selection intact.
