Two exact MbedCrypto CVE-2026-25835 records are non-applicable to the reviewed
app/audio consumer path. The library remains installed and affected code is
present. The [upstream advisory](https://mbed-tls.readthedocs.io/en/latest/security-advisories/mbedtls-security-advisory-2026-03-rng-cloning/)
concerns cloned random-generator state, including precautions for legacy
generators. Absence of PSA calls alone would not justify this decision.

Exact librist 0.2.11+dfsg-1 source initializes its legacy CTR_DRBG only when
SRP cryptography or authenticated EAP password rollover requests randomness.
The current exact libavformat consumer imports ordinary RIST APIs, with no
SRP/EAP enabling or verifier API. Newly allocated peers are zeroed; EAP context
cloning returns for a NULL source, incoming EAPOL rejects a missing context,
periodic EAP returns for NULL, and both password-rollover calls require
authenticated state 2. The generator therefore is not initialized or used by
the reviewed current path. This reasoning does not depend on a generic
assertion that the process never forks.
