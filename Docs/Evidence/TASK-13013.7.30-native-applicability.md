For util-linux, original tarballs and Debian patch tarballs match their official
`.dsc` checksums for [2.41.5-0+deb13u1](https://packages.debian.org/trixie/source/util-linux)
and [2.38.1-5+deb12u3](https://packages.debian.org/source/bookworm/util-linux).
Trixie `libmount/src/hook_subdir.c:291–295` returns `-ENOTSUP` whenever
`mnt_context_target_fd_required()` holds; `context.c:406–409` makes that predicate
exactly restricted mode. The only downstream context.c patch changes source
canonicalization around line 1998. Bookworm has no post-hook framework or
open_tree source/subdirectory path: `context_mount.c:807–817` handles helpers,
`:1128–1143` performs the legacy mount flow, and its library source list excludes
the later hook files. Its Debian patchset changes no libmount source. Existing
X-mount.mkdir and legacy X-mount.subdir features are not confused with the absent
advisory features.

Both distributions' build/install manifests assign libmount implementation to
libmount1 and mount/umount to mount. Across non-test C sources outside libmount,
only mount.c/umount.c reference mount-context APIs. Linked clients such as
findmnt, lsblk and fstrim use separate table/cache/lookup APIs. `su`/`runuser`
link their own sources, libcommon and PAM; `setpriv` links libcommon and cap-ng.
No affected source is folded into those binaries or the separate blkid, uuid,
smartcols and lastlog2 libraries. Dynamic dependency findings remain attributed
to libmount1. Complete installed-file lists corroborate this package split.
