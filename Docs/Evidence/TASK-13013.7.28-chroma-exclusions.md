## Dependency review uses the same policy

The existing pinned dependency-review action still enforces High/Critical
findings. Its temporary `allow-ghsas` input is derived from the complete,
paginated dependency comparison and unexpired canonical source records. An
advisory is allowed only when every added occurrence matches the reviewed root
manifest, package, installed version, component and severity. The four GHSA/CVE
aliases identify the same advisories; they grant no exception by themselves.

A pinned `actions/github-script` step fetches every comparison page using its
read-only token. The repository policy adapter receives the saved JSON file
without receiving that token. This preserves the existing credential boundary
for admitted `workflow_run` jobs.

After the action, the adapter validates its complete, unfiltered
`dependency-changes` output against the exact allowances passed in. A newly
observed unapproved version or manifest cannot inherit an advisory-wide
allowance. Missing, malformed or expired evidence fails the check. The raw
comparison and action output are retained as workflow artifacts. The action's
failure behavior and severity threshold are preserved; no `warn-only` or static
advisory list is used.

The pinned action's
[advisory filter](https://github.com/actions/dependency-review-action/blob/2031cfc080254a8a887f58cffee85186f0e49e48/src/filter.ts)
copies each changed dependency and builds a new vulnerability array; its
original `dependency-changes` output retains the unfiltered advisories.
The output is encoded as a JSON string in a quoted heredoc, then decoded to a
file. This preserves complete output larger than a shell environment variable
can hold and prevents embedded text from executing as shell commands.

A read-only GitHub comparison of base
`6cd2745f696af04668a61c20b84ab8a9e69ca5e4` and remote PR head
`78c3f92228c6411ee4637b9d2df9aa3b50aacdc8` returned 695 dependency changes.
The adapter derives exactly the four Chroma allowances for the added `uv.lock`
entry. Seven other High/Critical dependency-review rows remain outside the
allowance. Those are scanner matches, not new applicability determinations;
this task does not investigate or exclude them.

The integration uses GitHub's documented
[dependency comparison API](https://docs.github.com/en/rest/dependency-graph/dependency-review)
and the existing pinned action's
[inputs and raw output](https://github.com/actions/dependency-review-action/blob/2031cfc080254a8a887f58cffee85186f0e49e48/action.yml).
